# 从真实教师请求重建公开决策轮

来源为 11 月 11 日 FlockCue 正式首遍的 A 折 15 个连续场景。按内部划分，12 场训练、3 场验证。所有 HTTP 尝试、逻辑决策、工具调用和载荷均按题归档。5 个证据不完整的决策轮留在审计索引中。工具回执闭合只验证“模型发出了这个工具调用，执行器给了这条回执”，动作成功及整题可作为示范的判断另行审阅。

| 口径 | 训练侧 | 内部验证侧 | 合计 |
| --- | ---: | ---: | ---: |
| 题位 | 240 | 60 | 300 |
| 模型逻辑轮 | 3,421 | 1,010 | 4,431 |
| 可重建的公开决策轮 | 3,417 | 1,009 | 4,426 |
| 机械核验未通过的轮数 | 4 | 1 | 5 |

**公开数据。** [训练轮](../../../outputs/flockcue-teacher-trajectories-a-20261111/training-public-turns.jsonl.gz)和[内部验证轮](../../../outputs/flockcue-teacher-trajectories-a-20261111/validation-public-turns.jsonl.gz)为 UTF-8 gzip JSONL。每行的 `messages`、`tools` 取自当前请求实发的教师输入。 `target` 为该轮唯一实际返回的 assistant 消息，含服务原样提供的 `reasoning_content`、正文和工具调用。`post_action_receipts` 是该轮调用结束后的真实回执，按归档返回顺序保存，字段为调用 ID、工具名、框架回执状态和原始回执正文。渲染某轮提示时只传该行的 `messages` 与 `tools`。该轮的回执可参与下一轮决策。

**审计索引。** [题级索引](wire-episodes.jsonl)以场景 ID、任务 ID 为键，记录正式作业、命令、模型归档路径及 SHA-256。[逐轮索引](wire-turns.jsonl)追加逻辑轮序号、HTTP 尝试 ID、返回模型与指纹、用量、工具调用、核验问题。每次请求有实发正文摘要，每个完整响应有原始传输体摘要；未完整收到的响应缺项保留。对于各轮的同名或并行工具，先按原始调用 ID、模型逻辑 ID、实参比对绑定工具启动事件，再按单次执行的 span ID 和回执中的调用 ID 绑定结束事件。C 接口的无参感知按正式部署的规则，将教师的空对象映成可执行的参数包；公开数据保留教师原始写法。[正式 C 接口的执行映射](../../../scripts/flockcue_session_cpu/teacher_sense.py)

共记录 4,435 次 HTTP 尝试，4 个不完整传输尝试分别保留在所属逻辑轮的 `attempts` 中。6,717 个教师工具调用中有 6,711 个绑定到实际回执。5 个不完整决策轮均存在缺少回执的调用，其中 4 个缺少处理器成功返回的证据，1 个含非法原始 JSON 参数且与处理器动作不一致。292/300 个题位的模型归档自报完整。部分归档发生过重试或中断，其中独立闭合的公开轮仍可回看。进入监督训练时还需按整题和逐轮审阅结果筛选。[题级完整性及独立评分](../flockcue-deployment600-20261111/tasks.csv)

**摘要和定位。** [行映射](public-row-map.jsonl)用场景—任务—逻辑轮定位公开文件，以从 1 起算的 `line` 及包含末尾单个 LF 的未压缩行 SHA-256 校验。[文件摘要](public-files.json)记录压缩文件、解压后整份原文的 SHA-256、字节数和行数。`request`、`response`、工具的 `start` 和 `receipt` 均为题级归档 JSONL 的二元字节坐标 `[起始偏移, 长度]`，从 0 起算；请求位置指向一条 HTTP 请求归档事件，响应范围含开始事件、全部数据块和结束事件。请求摘要取 base64 还原的 HTTP 正文；响应摘要取各块依 `chunk_index` 拼接后、按传输头解压之前的正文。工具回执摘要取 `output.content` 的 UTF-8 字节。[现有响应解码方法](../../../scripts/report_flockcue_deployment600.py)

**可读样例。** 训练侧场景 `04cd6269` 第一题 `a05a871a` 共有 6 个逻辑轮。第 2 轮并行查天气与感知，第 3、4 轮调用 `run_harness`，第 5 轮查状态，第 6 轮返回最终回答。样例逐轮列出原始公开请求、目标消息和后续回执，可直接检查该轮能看到什么。[完整公开样例](public-example.json)

**核验范围。** 核对了各题归档和工具链的场景封存摘要、作业与命令绑定、请求正文和响应块字节摘要、处理器执行动作及实际工具参数、回执 ID，以及后继学生可见前缀中的消息、历史推理、回执和已记录的公开注释。扫描了既有试采规则列出的隐藏检查和私有评分标记。导出后对所有压缩文件重新解压、重新解析，逐行校验映射摘要、前缀中工具调用和回执的先后、当前工具调用与后置回执一一对应，以及两组场景互斥。原始任务获分、题前状态、私有评估及未来回执的监督用途须按各自作用域隔离。
