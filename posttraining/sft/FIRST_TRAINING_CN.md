# FlockCue 首轮 SFT 面试材料

## 90 秒口述

我做的是多无人机调度模型的监督微调。给学生的是任务、可用工具和到当前为止的执行反馈，希望它在 FlockCue 中学会决定下一步要查什么、调哪台无人机、传什么参数，以及何时宣布完成。教师用 DeepSeek，学生用 Qwen3.5-2B。

我从教师在仿真环境中的真实执行记录构建示范。先按完整场景划分训练和验证，再按工具调用 ID 把模型的具体动作和执行回执连起来。整题通过只是第一步，我还检查题初是否就已达标、实际动作是否支持题面要求，以及教师回复能否用学生的工具格式完整还原。训练侧 240 道题，最终有 110 道贡献了 386 个决策轮。每轮都保留当时请求中可见的完整上下文，只对当前教师回复和结束符计算损失。这样学生能看到前一步执行了什么，又需要自己预测下一步。

首轮冻结基座，用秩 16 的 LoRA 训练约 738 万个参数。单张 A100 40 GB 上，每步一个决策轮，恒定学习率 0.0002，跑一遍数据用了 3 小时 57 分 43 秒。固定每个训练场景各一条样本，基座和训练后模型在相同教师回复上的 loss 从 0.7144 降到 0.4703，12 条都下降。这个结果回答了学生是否更能复现这些示范。任务调度能力要让两个模型在同一 Harness 里实际执行，按 60 道内部验证题的整题通过数和逐题变化判断。[训练实测结果](../../datasets/results/sft-a100-first-pass/epoch-1/result.json)

随后在 A 折 3 个完整验证场景做了 60 题在线配对。基座与 SFT 的正式整题通过均为 0/60。仿真器整题检查从 0/60 到 6/60，覆盖起飞悬停、双机巡逻和到点拍照等任务。新达标的 6 题里，5 题最终触及累计 token 预算，1 题因回复格式被拒。这解释了为什么动作执行已有改善，而正式通过率仍为零。[在线验证与逐题记录](../../datasets/results/student-validation-60/REPORT_CN.md)

## 训练样本从哪里来

主基准含 30 个完整场景、600 题，每场 20 题。A 折 12 场、240 题是首版训练来源，另 3 场、60 题用于内部验证。B 折 15 场、300 题留作学生独立测试。按场景划分可以避免把同一连续场景中的相邻题分到训练和验证两侧。这批基准有历史开发暴露，学生本轮的数据边界可按场景清单核对。[场景划分](../../datasets/teacher/2026-11-11-fold-a/audit/scene-roles.json) · [全量题库角色](../../datasets/original-benchmark/scene-roles.csv)

教师示范取自 11 月 FlockCue + `deepseek-flash` 正式 600 题首遍的现成执行档案。训练侧 3,421 个逻辑决策轮中，3,417 个有可重建的公开数据。先用题级证据筛选，再选具体可学习的整轮回复。[教师运行设置与服务指纹](../../datasets/results/benchmark-600/summary.json) · [教师轨迹审阅记录](../../datasets/teacher/2026-11-11-fold-a/audit/REPORT_CN.md)

## 一条真实轨迹怎样变成一次梯度更新

1. **绑定请求、答案与动作。** 以场景、任务、模型逻辑轮定位一次决策，从实发 HTTP 请求取 `messages` 和 `tools`，从实际返回取本轮 `target`。通过工具调用 ID、参数和执行跨度 ID 关联工具启动、结束及回执。题目私有检查、终态分数和取舍依据存审计旁表。本轮动作之后产生的 `post_action_receipts` 用于核验，下一轮输入按当时实发历史取数。[轨迹重建](../trajectories/README.md) · [原始字段与证据索引](../../datasets/teacher/2026-11-11-fold-a/audit/WIRE_FORMAT_CN.md)
2. **渲染学生能实际使用的输入。** 用固定版本的 Qwen 原生分词器和对话模板，把系统说明、用户需求、可用工具及当时可见的历史消息渲染成提示。历史工具回执先按原调用 ID 匹配，再把规范化调用 ID、工具名、实参和执行结果写进回执内容，使并行调用的结果可归属。所有训练轮沿用同一种允许思考的提示格式，教师提供了本轮推理就保留，未提供就直接关闭该段，随后学习实际文本和工具调用。[学生输入适配](adapter.py) · [监督轮构造](supervision.py)
3. **校验并生成标签。** 用学生运行时的解析器回读教师目标，核对思考、文本、工具名、参数类型和调用顺序。每个通过的决策轮按场景、题 ID、轮 ID 去重。输出每行只有 `input_ids` 和 `labels`，前缀标签全部为 `-100`，当前助手回复及 EOS 对应原 token ID。单条总长上限 32,768，目标上限 2,048，合格样本使用原长。行号、原记录哈希与公开数据位置另存索引。[导出实现](export.py) · [训练行索引](../../datasets/sft/qwen35-2b-first-pass/index.jsonl)
4. **更新一次模型。** 模型读取完整序列，以 teacher forcing 预测当前教师回复中的下一个 token。训练实现只将各目标 token 前一位置的隐藏状态送入词表输出层，再用 FP32 logits 计算该回复的平均交叉熵。这样既保留所有历史的上下文作用，也省去为数万个已屏蔽的前缀位置构造词表 logits 的显存。每次反向传播和优化器更新对应一个决策轮。[训练循环](train.py) · [单步损失实现](benchmark.py)

**可在面试中举的例子。** 巡逻场景 `04cd6269` 的任务 `a05a871a` 要求 1 号机起飞至 9 米并悬停。训练文件第 1 行输入有 8,569 个 token，监督目标含 `list_drones` 调用，共 31 个 token。第 2 行中学生已能看到该调用及真实回执，9,233 个提示 token 全部屏蔽损失。要预测的 147 个 token 中有 36 个本轮推理 token，并含并行的 `get_weather` 和 `sense_nearby_entities` 调用。两次查询的真实结果要等执行后才能看到。[该题全部六轮执行](../../datasets/teacher/2026-11-11-fold-a/audit/public-example.json) · [对应训练行](../../datasets/sft/qwen35-2b-first-pass/index.jsonl)

## 首轮实际参数

| 项目 | 实际设置 |
| --- | --- |
| 教师与学生 | 教师为 `deepseek-flash`，学生为 `Qwen/Qwen3.5-2B` 的文本因果语言模型，固定 revision `15852e8c16360a2fea060d615a32b45270f8a8fc` |
| 训练方法与精度 | 冻结全部基座权重，BF16 前向，LoRA 可训练主参数 FP32，投影时转换到输入精度 |
| LoRA | rank 16，alpha 32，缩放系数 2，dropout 0。A 矩阵 Kaiming 均匀初始化，B 矩阵从零开始，因此初始增量为零 |
| 训练哪些层 | 6 个全注意力层的 `q_proj/k_proj/v_proj/o_proj`，18 个线性注意力层的 `in_proj_qkv/in_proj_z/in_proj_b/in_proj_a/out_proj`。共 114 个投影、228 个 LoRA 张量、7,382,016 个可训练参数 |
| 优化器 | fused AdamW，恒定学习率 `2e-4`，β₁ = 0.9，β₂ = 0.999，ε = `1e-8`，weight decay = 0.01。无学习率预热、衰减或显式梯度裁剪 |
| 数据迭代 | 随机种子 123，按决策轮打乱一次，每步 1 条，梯度累积 1，1 个 epoch 共 386 次更新。样本分别计算损失，无 padding、截断或多样本拼接 |
| 显存与环境 | 单卡 NVIDIA A100 PCIe 40 GB，PyTorch 2.8.0+cu128、Transformers 5.22.2，SDPA 与 PyTorch 线性注意力实现，非重入梯度检查点，训练时关闭 KV cache |
| 保存与恢复 | 第 1 步、每 10 步和末步原子写入检查点，含 LoRA、AdamW 状态、CPU/CUDA 随机数状态和已完成步。末步导出 safetensors，训练产物绑定基座 revision 和权重 SHA-256 |

参数来自实际启动的训练代码，版本为 Git `35b702e3`。冻结训练文件的 SHA-256 以 `1dfb4117` 开头，最终适配器的 SHA-256 以 `8735ff75` 开头。[训练参数](train.py) · [LoRA 实现](benchmark.py) · [基座清单](model.json) · [最终产物记录](../../datasets/results/sft-a100-first-pass/epoch-1/result.json)

## 超参数怎么定，训练效果怎样解释

**首轮固定了一个可复现的基线配置。** rank、学习率、batch size 和 epoch 数均按上表预先设定。本轮实验记录没有用多组 rank 或学习率比较验证分，也没有用中途检查点择优。上线前用同一 BF16 LoRA 配置在 8,517 至 32,608 token 的五个真实长度上跑完整前向、反向、AdamW 更新，确认最长样本能跑通，再按 386 条实际长度逐条估算一轮约 4 小时。换用其他训练超参数是否更好，需要另做受控实验。[五档实测](../../datasets/results/sft-a100-first-pass/measurement.json) · [训练参数与保存逻辑](train.py)

**区分每步损失和全轮报告。** 386 个样本共 6,962,880 个 token，6,833,870 个提示 token 只提供上下文，129,010 个回复 token 接受监督，其中 83,907 个是教师本轮推理。每一步优化的是一条样本中目标 token 的平均交叉熵。全轮报告则按每条样本的监督 token 数加权，得到 0.6984。每一步的样本不同，四段训练日志均值为 0.6648、0.7280、0.6943、0.7049。固定 12 个训练场景各一条样本，在完全相同的 2,948 个教师目标 token 上前后复算，基座为 0.7144，适配后为 0.4703，下降约 34.2%。[逐轮日志](../../datasets/results/sft-a100-first-pass/epoch-1/steps.jsonl) · [同样本测量与曲线](../../datasets/results/sft-a100-first-pass/epoch-1/loss.png)

**工程验证和任务验证各有观测量。** 训练实耗 3 小时 57 分 43 秒，纯训练步合计 3 小时 56 分 26 秒，平均每秒处理 490.8 个完整序列 token。正式训练的峰值已分配显存为 16.27 GiB，峰值预留为 28.46 GiB。最终权重通过独立进程重载，正式推理入口也在一个 8,569-token 提示上成功生成 8 个 token。数据中 381/386 轮含工具调用，110 道入选题里 5 道覆盖全部决策轮，21 道覆盖首轮。对整题通过率、失败恢复和完成判断的结论，需要在相同 Harness、仿真初态、任务顺序、执行预算和评分下比较基座与 SFT 的独立执行。B 折 300 题用于后续独立测试。[数据覆盖](../../datasets/teacher/2026-11-11-fold-a/audit/REPORT_CN.md) · [训练、重载与推理记录](../../datasets/results/sft-a100-first-pass/epoch-1/result.json)
