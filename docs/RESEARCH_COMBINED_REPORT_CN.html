Integrated Research Report · 2026.11.01

多无人机 Agent 系统与小模型后训练阶段一・二合并报告 · 架构、阶段成果与研究路线

本研究围绕多无人机协作中的计划执行与控制权交接，构建公开证据驱动的 Agent Harness，并进一步探索基于真实交互轨迹的小模型后训练。两阶段分别研究运行机制的有效性与决策能力的迁移，通过统一环境和评测协议建立联系。

阶段一　Harness：执行、证据与接管　→　阶段二　Teacher 轨迹 → SFT → 同 Harness 评测 → 条件式 RL

核心问题包括：公开执行证据能否支持对“继续、失效、交回模型”的正确判断；经过验证的 Teacher 轨迹能否改善约 2B 学生的技能选择、工具使用和接管决策；系统机制与模型训练分别贡献了哪些收益。

01 / AGENT HARNESS公开证据驱动的执行与接管机制

1.1　Agent4Drone 原架构与研究基础

本项目复用 MultiUAV-Plat 的仿真环境、多无人机工具、任务生成与评估基础，并以 Agent4Drone 为对比基线。原架构通过观察、任务理解、规划、工具链执行和验证形成反馈闭环；Memory 保存局部信息、动作历史与中间结果，执行反馈进一步支持重试和重规划。

原论文已经包含短程规划、有界工具链、记忆和验证。上述模块代表同一主 Agent 的概念职责，多个 UAV 由集中式策略调度。本研究在此基础上，进一步明确计划的适用条件、执行状态与交接内容，使程序内继续执行和模型重新决策之间的边界能够被检查和评价。

1.2　Harness 总体架构与模块职责

完整架构由任务与证据、模型决策、有界执行、回合与评估四层组成。模型负责语义判断、技能选择、无人机分配和重规划；Harness 管理已提交计划及其确定性执行规则；环境提供实际动作效果；独立评分给出最终任务判定。

任务与证据层。将任务要求与公开观测、状态查询、动作回执对应起来，保留执行主体、信息来源和作用范围，区分动作意图、已确认效果与未知项。目标表示还包括剩余义务和未支持条款，避免将局部进度或某个技能结束直接解释为整任务完成。

模型决策层。模型根据任务、公开上下文和工具定义，选择启动、恢复或取消技能，也可调用原工具处理未支持任务。技能工厂将选择编译为显式计划，记录计划身份、执行游标、依赖、预算和退出条件；模型无需自由生成任意计划图。

有界执行层。运行时在技能检查点验证计划适用性：条件满足时继续执行，问题处于既定修复范围内时实施局部修复，效果不明、依赖失效或预算耗尽时交回模型。原工具改变相关依赖后，旧计划应失效，以限制过期恢复与重复动作。

回合与评估层。采用独立回合、实际模型 I/O 和工具关联记录，保存交互顺序、执行效果与异常终止原因。回合结束后封存并隔离评分，公开信息用于策略决策，隐藏检查保留在评估侧；同一记录基础进一步支撑 Teacher 轨迹转换。

执行原则：动作失败不必然意味着计划失效，技能完成也不等于整任务完成。交接应包含状态与原因、当前游标、已确认和未知效果、剩余义务及可用预算。

例如，动作请求发出后响应丢失，应先核对公开状态；无法确认效果时保留未知状态并交回，避免将“请求已发出”当作完成，或未经核对直接重放。

1.3　与 Agent4Drone 的方法对比

方法扩展集中在证据、计划有效性与控制权交接的显式化。在原有“规划—执行—验证—重规划”闭环中，引入可追溯的计划状态和执行约束，分别处理可局部修复的异常与需要模型新判断的变化。

1.4　已有成果与验证边界

当前已实现有限技能的计划状态机、公开执行证据、局部修复和模型接管接口，以及回合隔离、模型 I/O 归档与独立评分的本地基础。现有完整技能主要覆盖简单动作链与特定公开搜索指令；通用任务义务、统一交接报告和自然端到端收益仍需补齐。

02 / SMALL MODEL POST-TRAINING从执行轨迹到小模型决策能力

阶段二利用同一 Harness 采集强 Teacher 的真实协作轨迹，经质量验证后构建版本化数据集，优先通过 SFT 将有效决策迁移到约 2B Student，再回接环境评价。学生承担高层规划、分配、工具使用与恢复决策，低层控制及确定性技能流程仍由程序执行。

待验证的工作假设是：执行感知的样本筛选和有效恢复示范能够改善小模型的闭环决策。蒸馏在此指 Teacher 到 Student 的能力迁移思路，首先通过轨迹 SFT 实施；RL 保留为奖励、采样信号与成本条件成熟后的扩展。

2.1　Teacher 轨迹构建与质量验证

轨迹记录。保留任务、场景与种子、模型身份、实际请求和响应、工具调用 ID、顺序与并行关系、公开回执及 Harness 事件。每个样本应追溯到原始回合和决策位置，重建当时可见的输入；后续回执与终态可用于验证，不能提前注入该决策的上下文。

四层验证。依次检查结构完整性、执行正确性、任务完成度和决策质量：消息及调用关联是否完整，参数与实际动作效果是否正确，独立 scorer 是否确认完成，以及是否存在冗余、重复或无效恢复。质量标签、规则版本和排除理由随数据一并保存。

样本分流。首版正向 SFT 优先采用完整成功轨迹和经过验证的恢复决策。错误输出可以作为恢复历史保留，但不默认成为正确标签；部分完成与失败轨迹用于诊断和任务设计。技能内部动作不伪装为模型生成，隐藏检查与私有状态不进入策略输入或示范。

独立划分与采样。正式采集前冻结场景、种子和任务族划分，同源改写与衍生轨迹按组管理。训练集用于优化，开发集用于选型与修订，测试集在模型和协议冻结后评价。小规模 pilot 先测量有效率、决策机会、长度、重复与截断比例，以及合格样本的采集成本，再决定扩量；历史开发题不重新命名为未见测试。

2.2　Student SFT 与同 Harness 回接

SFT 保持真实消息和工具协议，仅监督审核通过的 assistant 决策与工具调用，环境回执作为上下文。需要核对模型模板、角色边界与监督掩码；长轨迹按决策窗口切分或压缩时，必须保留目标决策依赖的公开证据。原始归档与训练视图分开管理，训练和部署使用一致的输入构造方式。

初期以 LoRA / QLoRA 等参数高效训练方式为候选，具体配置依据基座、上下文长度和实测资源确定。首个检查点应连同 tokenizer、模板、Adapter 或权重及推理配置导出，并接回同一 Harness，验证多轮工具调用、异常处理、接管与停止判断。

验收以可部署检查点及同 Harness 的基座／SFT 对照为依据，训练 loss 仅作为过程指标。若无增益，优先分析样本质量、上下文缺失、监督边界和分布偏移，再修订数据与配置。相关样本规范和训练选择见阶段二详细路线。

2.3　条件式 Agentic RL

—

奖励以端到端成功为核心，进度、无效动作和调用成本作为待验证的辅助项；需检查提前停止、重复获取进度等反例，并区分策略失败与基础设施异常。PPO / GRPO 保留为候选，具体算法尚未冻结。条件不足时继续完成 SFT 与统一评价，首轮可复用“新 worker → 完整归档 → 退出 → 独立评分”的整回合路径。

当前状态：本项目 Teacher 数据集、SFT、Agentic RL 与约 2B 训练后模型均未完成。已有记录和本地接口验证不等同于数据质量或学习效果验收。

03 / EVALUATION & NEXT STEPS贡献归因、阶段交付与实施安排

3.1　统一对照与评价指标

实验分别评价系统机制、监督学习和交互优化的作用。控制模型身份、公开权限、初态、技能语义、顺序、预算和评分协议；关键数据消融需同时报告样本量、有效监督 token 与训练计算量，避免将训练规模差异归因于数据形式。

关键对照回答的问题
固定模型，比较基线运行方式与 Harness系统机制是否有效？单独消融门控时保持技能和动作能力相同。
固定 Harness，比较基座与 SFT数据与监督训练是否改善决策？再消融关键质量规则或恢复样本。
同一 SFT 起点，比较 SFT 与 SFT+RL交互优化是否提供额外收益？仅在实际开展 RL 后报告。

主指标为端到端任务成功。同时记录工具正确性、接管／恢复机会、模型调用、token、时间、动作及 Teacher 和训练成本。恢复指标以实际机会为分母，机会为零时标记不可估计；失败、不可评分与重试按预先规定的口径保留。开发集用于改进，独立测试不参与样本筛选、奖励设计与反复调参。

3.2　近期安排与阶段门槛

未来约 1–2 个月以形成数据、SFT 和同 Harness 评价闭环为重点。Harness 的有界验证、模型接口集成与样本准备可交叠推进，具体规模依据小批采样和训练吞吐调整。

  1. 准备与小批采样。—
  2. 首轮 SFT 与回接。形成版本化数据、可部署检查点和基座／SFT 开发集对照；检查工具错误、接管表现和成本，根据错误来源修订数据或上下文。
  3. 归因与统一交付。完成关键消融、冻结模型后的独立测试和失败分析；通过奖励、采样及资源门槛后开展有界 RL，并评价其相对固定 SFT 起点的增量作用。

待冻结事项：—

最小完整交付：可追溯的合格数据集、可复现的 SFT 配置、可部署 Student，以及固定 Harness 下的基座／SFT 独立评价。最终研究主张对应明确的机制、消融、成本和失败边界；RL 为条件项。
