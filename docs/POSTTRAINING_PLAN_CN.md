### 首批学生从哪些轨迹开始

1. **先审阅 A 折。** 逐题绑定题初与终态、原指令明确要求的动作、指定无人机、真实工具调用 ID 和回执。正式归档的题前快照需验证能否还原初态条件；无法判定的标为未知。首版优先选取本题有可归因行动的成功轨迹，保留成功轨迹中收到失败回执后有效恢复的轮次。状态继承已满足、缺回执、无依据完成、重复无进展分别登记。按任务族、难度和场内题序记录从 300 个题位到最终题数与轮数的去向。旧试采 A 折已有 22 题、148 个审核合格轮，可回归转换和训练链路；与正式首遍同题的数据保留来源、去重。[试采审阅约定](results/deepseek-teacher-pilot40-live-20261111/REVIEW_PROTOCOL_CN.md) · [实际试采结果](results/deepseek-teacher-pilot40-live-20261111/REPORT_CN.md)
2. **用 2B 自己的模板测长度与覆盖。** 在上述两折合计 540 道候选题中，7,353 次有用量的响应里，3,326 次的教师输入加输出超过 32,768 token。这个数字使用 DeepSeek 的计量。先在训练侧用 Qwen 模板重建真实前缀，分别统计首轮、后半段、多机协作及失败恢复的可用轮数，检查工具调用与回执是否成组保留。压测可用的上下文长度、显存和 500 秒内能完成的轮数。若需压缩历史，只用当时可见的信息，训练、推理共用同一规则，并把新的输入配置与原教师成绩的可比范围写入报告。[逐请求计量](results/flockcue-deployment600-20261111/calls.csv) · [Qwen3.5 学生适配](../scripts/flockcue_qwen35/adapter.py) · [A100 推理测速](results/flockcue-a100-g1g2-20261110/T37_CN.md)
3. **先交付一份能自主执行的 SFT 权重。** 建议从 A 折预留 3 个完整场景作内部验证，每个任务族一个，其余 12 场用于迭代。从同一份 Qwen3.5-2B 初始权重做单卡 LoRA，用一种固定模板保留教师实际产生的本轮推理、工具调用或最终回答。只对该轮助手输出计算损失，用户指令、历史与工具回执全部遮罩。用小批数据先验证训练、保存、重载、接入正式 Harness 和 20 题连续执行，再训练全部审阅合格的训练侧样本。原始 2B 和 SFT 在相同内部验证场景各自执行，按独立整题通过数选择 checkpoint，同时检查合法工具调用、动作回执和错误完成声明。曾在另 29 道开发题上取得的 1/29 只作故障诊断。[监督 token 构造](../scripts/flockcue_qwen35/dev_sample_tokens.py) · [原始 2B 筛查](results/flockcue-a100-g1g2-20261110/REPORT_CN.md)
4. **RL 从 SFT 权重起步。** 建议先做带原仿真的多轮 GRPO 小试。从同一训练侧题初状态复制隔离环境，包括世界、黑板和公开历史，以每组 4 条独立学生轨迹试测。验证同一前缀的恢复与隔离；模型读回真实动作回执继续决策。先以独立原检查的整题通过给 1、失败给 0，只对学生生成的 token 计算策略损失，保留 SFT 快照作为对照。题初已满足或运行设施故障的轨迹单独登记，检查是否存在未执行要求动作却获奖的情况。记录组内有成功也有失败的组数及每个有效组的采样成本；若几乎全为同分，先从训练侧选择 SFT 偶尔能完成的题或补相应示范。正式评测继续保留所有题、原顺序及原部署失败口径。[原部署协议](specs/05-deepseek-harness-ab600/plan.md) · [GRPO 原论文](https://arxiv.org/abs/2402.03300)
5. **测量两段训练各带来多少整题收益。** 冻结学生输入、工具权限、场序、每题 500 秒、并发与推理设置。原始 2B、SFT、SFT+RL 分别在留出的 B 折完整运行，每个系统从同一场景初态开始，后续 19 题继承自己的执行状态。报告 300 道题的首次独立通过数、SFT 相对原始和 RL 相对 SFT 的配对增减、按场景估计的不确定性、三族分数、token 与 P50/P95 时延。B 折教师参照为 270/300。若要求 600 题折外成绩，在查看任一方向的学生折外成绩前锁定双向配方；从同一原始基座独立训练 B→A 的另一套权重，各取其留出侧的 300 题汇总。报告历史开发暴露与跨折指令复用。[分折与暴露记录](specs/02-benchmark600-sft/spec.md)

已用固定 Qwen3.5-2B 模板实测 A 折巡逻场景 `04cd6269` 第 3 题。核过两份请求体摘要后，保留可见历史推理，首轮提示为 8,487 个学生 token，第 13 轮增至 28,409 个。两者都不含当前监督目标。全训练侧还需统计不同题型的长度及超长时损失的动作。[该题原始模型归档索引](results/flockcue-deployment600-20261111/tasks.csv)

第一项可交付结果是 A 折的示范清单、可训练轮数与长度分布，外加原始 2B 在正式学生执行入口的完整会话成绩。以这些实测值估算 LoRA 与在线 RL 的卡时。达到哪一个整题通过率才满足部署需要，由项目在查看折外学生成绩前确定。

### 学生学什么

每条 SFT 样本对应教师的一个轮次。输入是截至该轮的公开历史：任务原文、当轮工具定义、此前各轮的回复与推理、工具回执。目标是该轮的回复和工具调用；标签为"思考"时目标前加推理段，标签为"不思考"时推理段为空。只有目标部分计入 loss。

| 组成 | 规定 |
| --- | --- |
| 推理文本 | 用教师 `reasoning_content` 原文作目标（用户 2026-11-08 确认）。四个封存批次中 32.2% 的响应推理 token 为 0。[用量审计](audit/teacher-reasoning-usage-20261108/summary.json) |
| 思考标签 | 执行事件、教师自选、LoGiC、固定间隔四种来源，外加每轮思考、从不思考两个端点。定义见[第 1 步规格](specs/01-thinking-events/spec.md#四种思考标签)。 |
| 标签要求思考但教师推理正文为空 | 保留该轮及其动作目标，记录标签与正文的冲突，有效监督按“不思考”计。[第 1 步技术方案](specs/01-thinking-events/plan.md) |
| 隔离 | 私有状态、隐藏检查器、整题评分和后续轮次不进入输入或目标。整题评分只用于筛选轨迹，筛选规则在采数前冻结。 |
| 本轮题池 | 教师示范和最终的系统对比均使用已确认的原基准 600 题。建议把同一会话的全部任务、重复执行与逐轮样本放在同一侧，两侧各 300 题，交替训练和评测。[冻结题单](../experiments/flockcue-benchmark-600-v1/) · [采数与训练草案](specs/02-benchmark600-sft/spec.md) |

旧的 W3 样本契约禁止推理进入学生输入或监督，它的 61 条开发样本保持冻结，不改写。新样本使用新版转换器和加载器，复用旧版的调用 ID 关联、wire 哈希核对、私有字段清理和 tokenizer 检查。[旧契约](AGENT_SAMPLE_CONTRACT_CN.md) · [ID 适配](STUDENT_TOOL_ID_ADAPTER_CN.md) · [旧输入环境](../training/README_INPUT_CN.md)

### 对照设计

| 臂 | 训练数据 | 回答的问题 |
| --- | --- | --- |
| 从不思考 / 每轮思考 | 同一批轨迹，推理全删或全留。全留与教师自选若形成相同监督，报告二者重合 | 两种端点可提供的监督 |
| 执行事件 | 事件轮保留推理 | 本文方法 |
| 教师自选 | 原样保留教师的推理与空推理 | 直接模仿教师是否已经足够 |
| LoGiC | 原第 1 步固定 Qwen3-1.7B 评分，平均每 token 对数似然下降阈值为 0.001 nat/token。采用新学生时，评分模型与阈值在采集和对照评测前另行登记 | 文献信号与执行状态信号谁更好 |
| 固定间隔 | 每 *k* 轮保留推理，在共同可判轮次上尽量匹配执行事件的思考比例，报告实际偏差 | 收益是否只来自思考次数 |
| RSI（权重不动） | 不训练，只按 dev 错例迭代 Harness 说明 | 训练权重是否必要 |

同一折的训练方法共用教师轨迹、基座、训练设置和 Harness。Qwen3.5-2B 是原 G1/G2 的主模型，也是后训练优先验证的学生。正式评测拟按完整会话重复 3 次，并按原题池的任务族、场景难度和实际机队规模报告。在相同协议下配对比较原 Agent4Drone 与 FlockCue（同一 DeepSeek），以及 FlockCue 中的原版和蒸馏学生。[600 题系统对比](specs/02-benchmark600-sft/spec.md#最终怎样比较)

### 资源与预算

教师采数与训练部分为后续阶段的启动前估算，按对应批次的实测和当时报价更新。

- **教师采数。** 首档拟在 30 个完整场景各采一遍，共 600 个教师题次。二遍为 1,200 题次，四遍为 2,400 题次。[历史开发成本](results/deepseek-cost-pilot-20261103/REPORT_CN.md)
- **训练。** 单卡 LoRA，单卡上限 80 GB，40 GB 更好。实际峰值显存、吞吐和上下文长度在第 1 阶段实测。旧 68 个请求中有 18 个超过 4,096 token，长度分布需在新样本上重测。
- **学生推理。** 原 Qwen3 接入已完成 Mac 无卡回归。Qwen3.5-2B 的模板、真实权重单题执行均已在 Mac 验证，Linux 与 29 题配对的后续结果见[正式筛查报告](results/flockcue-a100-g1g2-20261110/REPORT_CN.md)。600 题教师采数、训练与最终评测单独核算。[学生接入报告](results/thinking-student-cpu-20261108/REPORT_CN.md) · [第 1 步技术方案](specs/01-thinking-events/plan.md)

付费调用和 GPU 在各步 plan.md 中写明上限，用户批准后执行。

### 第二篇论文的衔接

第一篇产出的小模型和执行事件定义，是第二篇的起点：轨迹验证器把事件扩展为按机、按作用范围的诊断，再作为过程奖励用于 GRPO。第一篇不训练验证器。[2026-11-07 验证器草案](history/verifier-plan-20261107/spec.md)
