## 目标与范围

第一篇论文研究**多无人机小模型 Agent 什么时候需要思考**。本步交付三样东西：

1. 一套只从公开回执就能机械判定的**执行状态事件**定义，以及抽取器。
2. 每个主模型轮次"思考或不思考"的四种标签来源，统一格式。
3. 第 0 阶段三道门槛的验收办法。门槛不通过，就不进入教师采数。

本步不训练模型，不新增付费调用。教师采数、SFT、LoGiC 复算与正式评测留给后续步骤。旧草案中的 F2（执行效果）和 F4（未知与时间顺序）改写为下文的事件定义。F1（调用前依据）、F5（规则遗漏机会）和验证器训练移到第二篇论文。[研究路线](../../RESEARCH_ROADMAP_CN.md) · [后训练方案](../../research/posttraining.md)

## 一个轮次的定义

主模型的一次回复算一个**轮次**，可以带一组并行调用，也可以只有文字。请求失败且没有回复时，登记该次尝试和原因。轮次 *t* 的证据截止于该轮实际发给模型的请求。用上一轮各调用的 ID 关联其中可见的回执，结合任务原文和此前已公开的事实判定变化。子程序内部动作仅在其效果通过主模型可见的回执传回时作为证据。当前回复及用量只供教师标签和事后分析。

## 执行状态事件

命令回执的原始分类为 `completed / partial / blocked / error / unknown`。执行状态按调用身份给出 `effect_status` 和 `effect_reason`，结合两者可区分几何受阻、明确拒绝及效果未知。仅使用截至当轮公开的投影，后续查询保留为新的观测。[回执解析](../../../flockcue/evidence/command_results.py) · [执行状态](../../../flockcue/runtime/execution_state.py)

| 编号 | 事件 | 判定方法（只用公开回执与任务原文） |
| --- | --- | --- |
| E1 | 动作受阻 | 某个动作调用的结果为 `blocked`，例如航段穿过已知障碍。 |
| E2 | 效果未知 | 某个动作调用的 effect_status 为 `unknown`，包括超时、传输异常、回执主体不符。 |
| E3 | 部分完成 | 某个动作调用为 `partial`，或子程序交回时仍有剩余航点。 |
| E4 | 明确失败 | 回执证实调用被拒绝或执行失败，包括参数校验失败。已归 E1 的几何拒绝及 E2 的传输超时各按其原因记一次。 |
| E5 | 新信息 | 感知或查询（含组合动作的感知部分）首次返回某个有公开身份的实体或障碍，或同一任务的公开进度相对上次读数发生变化。重复回显同一实体、时间戳变化不触发。 |
| E6 | 义务变化 | 任务原文点名某架机，且本轮证据首次证明该机的可核验条款完成或原路径受阻。重复确认同一状态不触发。单次路径受阻只涉及这一条路径。超出首版语法的条款单列覆盖率。 |
| E0 | 无事件 | 非首轮，上一轮调用的回执齐全、可判、均成功，本轮在支持范围内未发生 E1–E6。首轮单列 `start`。 |

同一轮可同时出现多个事件，逐项追溯到调用 ID 与飞机，机队级观测注明作用范围。若回执缺失或归属不明，仍保留能确认的事件并标记证据缺口；只有证据缺口、没有可确认事件时，事件标签记为不可判。公开回执明确报告动作超时可判 E2。抽取器不读取私有状态、隐藏检查器、评分结果或后续轮次。

## 四种思考标签

| 来源 | 规则 | 角色 |
| --- | --- | --- |
| 执行事件（本文方法） | 本轮之前出现 E1–E6 任一事件，或本轮为 `start`，标为思考；E0 标为不思考。 | 待检验的方法 |
| 教师自选 | 真实回复中有明确计数时，推理 token > 0 标为思考，等于 0 标为不思考；缺失单列。 | 教师基线 |
| LoGiC | 保留首轮推理，从第 2 轮按序尝试删除，沿用此前已接受的删除。仅当本轮至末轮每个参考动作的平均每 token 对数似然下降都不超过阈值时接受。完整轨迹只供离线打标。评分模型和阈值在 plan.md 冻结，本步标记为待计算。 | 文献基线。[RACE §3.1 与算法 1](https://arxiv.org/html/2610.12061v1#S3.SS1) |
| 固定间隔 | 每个回合按同一起点、每 *k* 轮思考一次。在共同可判轮次上选最接近事件臂思考比例的整数 *k*，报告两臂思考数、分母与残差。后续等预算比较在 plan.md 预定的容差内解释。 | 频率对照 |

另设“每轮思考”和“从不思考”两个端点。区分标签要求思考、教师是否有推理正文，以及按缺失处理规则可实际监督的比例。若“全留现有推理”与“教师自选”生成相同的训练目标，应报告重合。G2 直接比较学生推理开关。四种标签的后续比较控制思考比例或总推理 token。

## 第 0 阶段门槛

**已确认的开发筛查判据。** 四批教师数据来自另一组开发任务。冻结的 dev 只有 5 个父场景、29 题，目前有脚本质量检查，缺少同协议的教师成绩。用学生自身的成功题数判断 G1，用同题开关的净改善判断 G2。下文的 3 题（约 10 个百分点）是决定是否投入下一阶段的筛查阈值，无统计显著性含义。[冻结划分与暴露记录](../../results/task-coverage-splits-20261103/REPORT_CN.md)

| 门槛 | 观测与通过条件 | 其他结果如何处理 |
| --- | --- | --- |
| G1 改进空间 | 以 Qwen3.5-2B 开思考臂判门槛，Qwen3-4B 的同条件结果单列。在 dev 29 题各运行一次，独立评分。主臂至少成功 3 题，且至少 3 题在上下文容纳、服务正常的情况下因任务执行失败，才算既能完成任务又有可测的提升空间。 | 接近满分时评估提高任务难度。低分时逐题区分超长、工具格式、决策失败和运行故障。确认的成功与可归因失败均达门槛即通过。即使补全未知量也无法达标时未通过；缺评分或缺归因仍可能改变结论时待判。每题报告峰值上下文和超长题数 / 29。 |
| G2 思考开关 | 两个模型各自在同题上做开、关配对，复用 G1 的开启臂。对 2B，以“仅开成功”减“仅关成功”至少 3 题，且至少两个父场景各有净改善为通过。公布两臂均成功、均失败及两种单侧成功的题数，并逐父场景报告；4B 结果单列。 | 平局、反向或未达到阈值，记录方向和 token 代价，暂缓采数。2B 因基础设施或独立评分缺失导致配对不全，或墙钟/单请求超时、上下文超长集中在 2B 开臂时记为待判。按[技术方案](plan.md)分臂核对停止原因与累计 token 代价。此开发筛查不能断言选择性思考无效，转备选假设需另作研究决定。 |
| G3 事件有区分度 | 对四批教师归档统计非首轮中至少含一个 E1–E6 的轮数 A、E0 轮数 B 和事件不可判轮数 U，三者合计 183。报告可判轮比例 A / (A+B) 与全体非首轮的可能区间 [A/183, (A+U)/183]。区间全部落在 10%–90%（含边界）时通过。分别报告各事件频次及事件轮、E0 轮的教师推理 token 分布，按批次、臂、自然或注入条件分列。 | 区间全在门槛同一侧时复查触发条件；跨过门槛或没有可判轮时记为待判。首轮与请求失败逐项对账。结果描述这些开发回合中的教师行为，方法收益由后续对照检验。 |

G1、G2 共用 **2 个学生模型 × 2 个思考开关 × 29 题 = 116 个计划回合**。每臂以 29 为计划分母，保留失败、超时、未评分与未运行。三道门槛全部通过才建议进入 train 侧教师采数，任一未通过或待判均暂缓。

**本次模拟验收。** 用同一份 29 题清单和五个父场景构造有已知答案的四臂结果，验证分母、缺对、截止偏倚、净改善和逐场景统计。每题原 checker 的独立结果决定整题成功；公开动作、回执和完成声明的顺序作补充诊断。Qwen3-4B 来自另一模型系列，只提供参照，其分数不会改变 2B 的门槛判定。模拟报告单独标识；真实 G1/G2 仍待测。本轮租卡、训练和教师调用额度均为零。

## 验收标准

| 编号 | 通过条件 |
| --- | --- |
| AC1 抽取器确定且只读 | 同一归档重复运行输出逐字节一致。覆盖 E0–E6 各至少一个正例和一个反例，包括乱序并行回执、回执主体不符、超时后再查询。改动当前回复、未来内容或隔离评分后，该轮的事件判定不变；泄漏检查为 0。 |
| AC2 四个批次复算 | 行为、契约、成本、悬停四批的 run-01 共 31 个回合。218 次请求中，214 次有回复（31 个首轮、183 个后续轮），另外 4 次末尾请求无回复。逐轮给出可计算的三种标签、原始推理 token 与不可判原因；无回复请求单列，保留各回合已有前缀。 |
| AC3 标签格式 | 记录归档路径与哈希、回合与逻辑轮次、请求截止位置、上一轮调用 ID、事件及作用范围、各来源标签与版本、教师推理正文是否可用。固定间隔报告配平残差，LoGiC 留空并注明推迟计算。格式在 plan.md 冻结。 |
| AC4 门槛报告 | 提交 G1–G3 各自的结果、分子、分母、缺失原因和采数建议。完成本步允许得出“暂缓采数”。未运行的门槛保留待判，不登记为已验证。 |

## 已知风险

- 现有划分的测试侧只有 5 个父场景、29 题。正式测试前另冻结扩大测试父场景的新版本划分，旧版不动。[划分与暴露记录](../../results/task-coverage-splits-20261103/REPORT_CN.md)

- E6 依赖任务条款解析，首版只覆盖可机械核验的部分，覆盖率单独报告。
- RACE 在其四个基准上报告，采用 LoGiC 的 SFT 相对标准 SFT 减少 4.3%–20.0% 的推理 token。FlockCue 的降幅待测，是否预留一小段 RL 在第 2 阶段之后决定。[RACE §4.3](https://arxiv.org/html/2610.12061v1#S4.SS3)
