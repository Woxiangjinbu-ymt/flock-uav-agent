## 两条数据流

本步回答两个可以分开验证的问题。四批旧轨迹用于判断事件标签能否区分决策轮次（G3）。学生实验用于测量零样本能力和思考开关的影响（G1、G2）。两条路径只在最终报告中汇合。旧轨迹的思考标签不会出现在学生的零样本输入里。

```text
四批封存索引 → 校验归档 → 当轮请求的公开前缀 → E0–E6、start 或不可判 ─┐
                       └→ 回复与 usage → 教师标签、正文可用性 ──────┴→ 逐轮表 → G3

冻结的 dev 划分 → 29 份可恢复初态 → 两种学生 × 思考开/关 → 116 个计划槽
                                      ↓                 ↓
                               实际模型输入与输出    独立进程评分
                                      └────── 同题配对 ──┴→ G1、G2
```

复核四份封存索引本身时，按表序将各自的 SHA-256 小写十六进制串各写一行（ASCII，含末尾换行），所得字节的 SHA-256 应为 `112b0e62173bb16b4605d9385b6ef175db3d1d73f4366e8911ad423b911f458b`。

1. 按回合、逻辑调用 ID、HTTP 尝试 ID 连接请求和回复，按 chunk 序号重组并验证回复。一次实际主模型回复只产出一行。重试、无回复、损坏或无法关联的记录均留有审计项，缺 usage 与明确的零用量分开。末尾请求失败的回合保留此前可核验的所有回复。
2. 对第 *t* 轮先产生公开前缀：任务原文、上轮调用的 ID/工具/参数，以及在本次请求截止前已返回且确实传给主模型的证据。工具结果须同时对应上轮调用和当次 wire 中的 tool 消息。乱序并行靠 ID 关联，保持原回执次序。带 M1-R 附加段的消息逐字核对原回执与已知附加格式，已核验的附加说明不重复生成事件。任务原文与证据说明分开，未识别的改写记为缺口。事件抽取函数的参数不含模型回复、推理正文、终局 ledger、评分或归档文件句柄。
3. 在批前的事实集合上判断本批变化，再合并同一并行批的事实。每个事件保留对应的公开证据位置，同一实体可引用多个调用。决策轮次之间有确定先后；同一批中无公开顺序依据的动作不推导时序义务。若发生上下文裁剪，以该轮实际可见的历史为准。

## 逐轮产物与对照（AC2、AC3）

下列为拟实现的 Python 接口与数据契约，版本定为 `thinking-events-v1`。

| 接口 | 输入 → 输出 |
| --- | --- |
| `read_turns(source)` | 一份已核验的归档 → 有序的请求前缀、独立的回复元数据与请求尝试记录。 |
| `extract_events(prefix)` | 仅含策略可见字段的前缀 → `events[]`、`gaps[]`、条款覆盖情况。给它相同的前缀就得到相同的结果。 |
| `label_turns(turns, schedule)` | 事件与独立核对的教师用量、统一间隔规则 → 每轮原始标签、可用监督及冲突原因。 |
| `summarize_gates(turn_rows, attempts, slots)` | 逐轮表、请求尝试和开发实验槽 → 可追溯的分子、分母、G1–G3 判定及采数建议。 |

**每行字段。** 事件判定状态为 `start / event / E0 / indeterminate`。主键为批次、回合、逻辑调用 ID；另存回合内从 1 开始的轮号、尝试 ID、归档相对路径及 SHA-256、请求截止序号、上轮调用 ID。事件含类型、飞机或机队范围、调用 ID、回执证据位置、条款引用。记录 `reasoning_tokens`、`has_reasoning_text`。每种来源有版本、`requested_think`、`effective_think`（布尔或空）及原因。四批行均标为开发数据。逐轮表不复制推理正文，回查正文用归档指针。确定性输出按批次、回合、轮号排序，以 UTF-8、固定键序和换行写 JSONL；运行时间与机器信息另存。

| 来源 | 计划冻结的规则 |
| --- | --- |
| 执行事件、教师自选 | 按规格输出原始标签。若原始标签为真但教师正文为空，保留同一动作样本，有效监督取假，记 `requested_think_without_text`；原始标签为空则有效标签也为空。分别报告冲突数、请求思考率、有效保留率及保留的推理 token 数。教师用量与正文不一致时单列。后续构造每个训练臂的前缀时，同样应用该臂此前的保留掩码。 |
| 固定间隔 | 各回合首轮思考，此后按 `(t−1) mod k = 0`。在事件标签可判的共同轮次（含首轮）遍历整数 k，从 1 到最长回合轮数，选思考数与事件臂最接近者，并列取较小 k。四批合并选一个开发 k，保留真实轮号。报告实际有效保留率的绝对差；≤2 个百分点才作思考比例配平比较，超差仍报告原结果。后续训练侧独立定 k，在留出数据上固定。 |
| LoGiC | 封存的 G3 标签配置登记 Qwen3-1.7B 为延后的离线评分模型，两种学生共用一份标签；阈值 ε = 0.001 nat/token。这是对原论文 9B 评分模型的适配。后续在完整成功轨迹上按规格逐轮删除，分别对本轮及之后各轮整个参考动作（含同轮并行调用或终止文本）计算平均 token 对数似然。未来内容仅进入离线评分器。本步两项标签均为 `null`，原因 `deferred`。[RACE 方法与设置](https://arxiv.org/html/2610.12061v1#S3.SS1) |
| 两个端点 | 记录“全留现有正文”和“全删”的有效监督量；全留与教师自选若逐行相同，后续共用同一份训练结果。G2 的开、关端点由学生实际生成和独立任务评分测量。 |

每个槽从同一份开发初态启动新 worker。worker 的 SDK 继续归档请求/回复，受限传输把该请求中的公开消息与工具通过预接通的本机进程管道交给常驻 GPU 进程。GPU 进程只读权重和模型输入，仅返回生成 token、计数和解析出的回复，不持有场景、checker 或工具执行权。每次请求绑定槽、轮次和截止时间，服务端不跨槽复用会话或 KV cache。worker 排空并退出后，独立 scorer 从冻结终态运行原 checker。取消未获确认时先停止并回收对应 GPU 工作；保留未排空、未评分或未运行的槽及原因。恢复中断批次时从封存的未启动槽继续，已启动的槽不覆盖。[现有 worker 与 scorer](../../../scripts/harness_natural_runner.py) · [请求截止和排空](../../../scripts/harness_request_limits.py)

## 付费前的 G3 判定与 Linux 主机准备

`replay` 在 CPU 上生成 `g3.json`，封存 A、B、U、区间、三态结论及其对应的来源和逐轮表哈希。仅 G3 通过才启动付费准备、冒烟与 dev 实验。G3 未通过、待判、缺件或校验失败时，将原因写入阶段报告，116 槽保留未启动，G1/G2 待判。归档代码和学生端代码仍可并行开发。

目标为同一台 Linux 主机上的 worker、仿真、scorer 与独立推理进程。优先在无卡环境和持久盘准备环境、模型与项目快照。转移冻结源码、输入和引用的封存文件，在目标机重建环境。将源码及初态按相对路径和内容哈希移交，目标机另记绝对运行路径和解释器绑定，核验原冻结内容后在不同路径重跑 CPU 夹具。使用 **CPython 3.11.16**，分别按 `agent4drone/requirements.txt` 和 `server/requirements.txt` 安装到各自的 `.venv`；Agent 的测试使用对应 dev 锁。新版候选后端须在目标 Linux 实际验证两个固定修订的推理能力。T36a 先建立新的 Transformers/CUDA 及备选 vLLM 独立环境锁，登记库版本、驱动、wheel 来源和哈希；T37 用真实权重验证开关、实际输入与生成 ID、EOS 和速率。旧版 Transformers 4.57.3 与 vLLM 0.11.2 锁仅认证原协议；2B 在 Mac 上通过的分词与 MLX 证据仅适用于相应环境。正式槽统一在单张 A100、BF16、batch=1 和同一已验证后端上运行。在目标机执行依赖一致性检查、`agent4drone/.venv/bin/python -m agent_harness check` 以及脚本模型 smoke，保存解释器版本、93 个源码文件校验和独立评分结果。挂卡时核对 A100 40 GB、驱动、BF16 可用性及实际包版本。[基线校验](../../../agent_harness/__main__.py) · [已有组件锁与安装办法](../../DEPENDENCY_SETUP_CN.md)

经官方源或镜像按上文的两个完整 commit 预取权重、配置与 tokenizer。按官方固定修订的文件清单逐一核对配置、分片及存在的索引，用可信来源的文件摘要或 LFS SHA-256 校验字节，留存下载源、清单及哈希，再离线只读加载。将任务初态、私有 checker 和实验账本留在协调器与评分侧。[Hub 固定修订下载](https://huggingface.co/docs/huggingface_hub/guides/download)

## T37 测速与 T38 准入

仿真按单调墙钟推进时间线，独立计时器在 500 秒冻结评分终态；跨截止的动作会回滚。请求准入和父进程 watchdog 另有实时时限。现有链路没有同时暂停这些时钟的接口。本步保留实际时钟，选择 **同一套 token ID 输入输出的 vLLM 后端**作为超时风险的补救办法。[仿真时钟与终态](../../../scripts/harness_full100_world.py) · [请求截止](../../../scripts/harness_request_limits.py) · [worker 的截止绑定](../../../scripts/harness_natural_runner.py)

1. **自然生成测速。** 在 dev 之外预先冻结公开合成前缀、模板哈希、种子与采样规则。两个模型、两种开关各预热一次后，以约 4,096、8,192、13,000 个实际 prompt token 三档各跑三个自然终止的请求（每档三条独立夹具）。记录实际输入和新生成 ID 数、首 token 时延、首至末 token 的解码速率、协调器发出请求至完整返回的时延。分模型、开关、输入长度给出每条原始记录、样本数和汇总；没有可计算速率的短输出或超时单列。
2. **满长开臂测速。** 两个模型各用约 13,000 token 的公开前缀独立测 20 次满长开臂请求。仅在这项压力测试中固定生成 2,048 个新 ID，并约束思考段在达到目标长度前不提前结束；不派发工具。公布实得长度、成功数、超时数，以及 20 次端到端时延的最近秩 P95（第 19 个顺序统计量）。达到 120 秒仍未返回记为右删失；若第 19 个值只能确定下界或采样不足，则标“P95 未确定”。压力样本与自然生成和 116 个正式槽分开记账。
3. **预先计算墙钟占用。** 每个模型用开臂三档自然请求端到端时延的均值 `L4、L8、L13`（秒）计算两个公开工作负载的模型等待时间：7 轮为 `L4 + 2L8 + 4L13`，12 轮为 `7L4 + 4L8 + L13`。记录两值与 500 秒的比值，取较大值进行准入判断。两种组合均在原 100,000 个累计 token 协议下设计，夹具冻结时校验实际长度。该估算只代表合成负载，正式批次仍需核对实际停止原因。
4. **统一切换或停线。** 默认测 Transformers。两个模型估算都 ≤250 秒、满长 P95 可确定且功能冒烟通过，才准许该后端进入 T38。任一模型估算 >250 秒、自然样本超时使估算不可用，或满长 P95 未确定时，在余下原额度内让**两个模型的开、关四臂统一**改测 vLLM。直接传入原模板产生的 `prompt_token_ids`，取回生成的 `token_ids`；固定权重、BF16、batch=1、采样、EOS、预算与调用解析，禁用跨槽前缀缓存。复核相同夹具的输入 ID、参考输出 ID 的解析、用量、取消与工具权限，然后重复上述测速。若替代后端不能通过、测速不足或额度不足，封存停止原因，T38 保留未启动、G1/G2 待判。正式首槽启动前锁定唯一后端和依赖清单，恢复时核对同一哈希。两个后端的预热、测速与装载均计入同一个预算。[vLLM 0.11.2 token 输入](https://docs.vllm.ai/en/v0.11.2/api/vllm/inputs/#vllm.inputs.TokensPrompt) · [生成 ID 输出](https://docs.vllm.ai/en/v0.11.2/api/vllm/outputs/#vllm.outputs.CompletionOutput)

**G1 缺测与归因。** 仅看 2B 开臂。S 是有独立通过评分的题数，F 是有独立失败评分和具体模型执行失败证据的题数，A 是已判失败且归因仍有可能属于模型执行的题数，U 是缺少独立评分的题数。四项互斥。S ≥ 3 且 F ≥ 3 时通过。否则，若 `max(0, 3 − S) + max(0, 3 − F − A) ≤ U`，补全资料仍可能达标，记待判；其余未通过。一道缺评分题最多补一个缺口。已确认因预算、运行时长或输入上限而停止的失败题单列。

**Mac 配对计分。** 从冻结 dev 划分得到有序的 29 个任务及所属父场景，同题、同模型下连接开关两条记录，与四臂计划表逐项核对。已知模拟答案覆盖数值门槛、跨场景条件、超时和超长偏开、普通累计 token 停止、缺评分。按实际可评分对生成四格，将缺对单列，所有臂均保留分母 29。动作成功回执与首次完成声明的先后可辅助诊断原检查遗漏，独立 checker 仍决定整题分数。输出带模拟标识的中文及机器可读报告；正式实验使用独立的运行目录，不接收模拟结果。

**G2 如何识别停止集中。** 对每个模型的 29 个同题配对，按臂逐题记录首个真实停因、剩余回合秒数、累计输入/推理/其他输出 token 及是否评分。500 秒回合截止、120 秒单请求超时、32,768 上下文超长分别计数，也计算三类合并去重的题数；若请求时限被剩余回合时间压短，到期归回合截止。100,000 累计 token 耗尽、2,048 生成截断、12 次请求用尽分别列账，另列历史推理占 prompt 的 token 量，保留这部分真实代价。

每一类及合并项都计算“仅开臂因该原因停止”的配对数与“仅关臂因该原因停止”的配对数。对 2B，只要任一项前者多于后者，按预先约定的保守口径判 **G2 待判**，保留两臂成功 / 29、四格与逐父场景净差。2B 若因基础设施故障或缺独立评分而缺少配对，亦待判。4B 的缺测在 4B 表中逐题登记。其余完整配对应用规格的净增至少 3 题且分布在至少两个父场景的判据。4B 作独立参照。单独的累计 token 停止照实进入预算下的独立评分与成本，不能单凭这一项触发速度混杂判定。

** 本次 Mac 演练支出上限为零。以后恢复租机时沿用下列上限。G3 使用本机 CPU，新增模型服务费为 0。116 槽若均耗满 500 秒，任务墙钟约 16.1 小时，其余约 3.9 小时还需覆盖装载、测速、可能的后端复测、评分与封存；能否完成全部槽位以实际账本为准。任何一项上限先到即停止，保留未运行槽并出具阶段报告。教师调用额度、训练卡时均为零。实施依项目流程在 task 与 checklist 确认后开始。
