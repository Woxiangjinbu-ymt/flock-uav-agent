**状态：G3 和学生链路的 Mac 无卡验收已完成。11 月 9 日改以 Qwen3.5-2B 判 G1/G2，保留 4B 参照。Linux 目标机与正式 GPU 批次待验收。** 本清单对应[规格 AC1–AC4](spec.md#验收标准)、[技术方案](plan.md)和[修订后的任务清单](task.md)。勾选时附测试记录、归档位置或运行目录及其哈希。实际运行因门槛或预算停止时，未执行项保留空框并注明原因；相应的停线与报告可单独验收。

## 归档、事件和标签（AC1–AC3）

以下六项以逐轮产物、边界夹具与四批真实复算核验，测试和产物哈希见[复验记录](../../results/thinking-events-g3-20261108/verification.json)。

- [x] **来源与尝试（T01、T02）。** 从封存清单重建四批回合，用同归档重试、无回复、缺 usage、零 usage 和故意损坏的副本验证身份及归属。核对四份 seal 合并摘要、worker 退出封存、wire 长度和哈希；重试只保留一次实际决策，损坏项有原因。
- [x] **决策截止与隔离（T03、T04、T10）。** 在同名并行倒序、缺回执和 M1-R 装饰夹具中按 ID 回查当轮请求，保留真实可见顺序。分别替换当轮推理、未来回执和终局评分，再比较事件输出字节；前缀与事件组件访问私有状态、评分、终局 ledger 的次数为零。
- [x] **动作效果（T05、T06）。** 用几何拒绝、错主体、明确超时后再查询、部分完成但无剩余数量、参数校验失败各跑一次，并与成功回执对照。E1–E4 各有正反例；单独的 `needs_replan`、缺回执及后续查询均按原来证据范围处理。
- [x] **新信息、义务和轮状态（T07–T10）。** 用同批重复发现与后续回显、进度变化与矛盾读数、具名悬停及航点夹具核验 E5/E6；错机、错坐标、缺显式悬停或时序不清均有记录。首轮、E0、有事件且伴随缺口、仅有缺口可区分，多事件均能追溯到公开证据。
- [x] **标签契约（T11–T13）。** 从逐轮表回查归档哈希、逻辑轮次、截止位置、上轮调用、飞机/机队、证据、标签版本与缺失原因。规格的 24 token 超时恢复示例两种原始标签均为思考；零 token 参数失败示例保留同一动作行且记录原始/有效监督差异。LoGiC 两项均为空且标 `deferred`。手算不同长度回合的固定间隔 k、并列取值及 2 个百分点边界，与报告的共同分母、有效保留率及残差一致。
- [x] **门槛 G3（T14、T36）。** 对真实复算及边界夹具核对 A+B+U=183、多事件每轮计一次、可判轮比例及完整区间。10% 和 90% 纳入通过区间，跨界或无可判轮为待判。分批、分臂及按自然/注入条件列覆盖；事件轮、E0 轮各有样本数、零推理比例、分位数及可回查的教师用量。

11 月 8 日按原 1.7B/4B 交付包在新路径重建环境，79 项 Agent 回归、21 项学生回归均通过。[Mac 验收记录](../../results/thinking-student-cpu-20261108/REPORT_CN.md)

- [x] **生成边界（T15–T18）。** 用两轮同名并行调用比较开、关臂的模型输入 ID、历史推理与回执关联。关臂空前缀只计入输入；从新生成 ID 核对推理/总 token、各模型合法 EOS。生成长度截断、未闭合、意外嵌套及半组工具调用的夹具保留原始证据，无法完整解析的调用组派发数为零。
- [x] **请求准入与进程管道（T19–T21）。** 两臂复核固定采样设置、剩余累计 token 为 0/1、上下文 32,768/32,769、第 13 次请求及回合仅余 5 秒的行为。挂起、迟到和错槽回复可归因，关闭后无迟到动作；自动截断、SDK 重试和云端回退次数为零。推理进程只收到本槽公开输入。
- [ ] **冻结与唯一导入（T22–T25、T31）。** 从冻结 dev 划分重建 5 个父场景、29 份初态和 116 个唯一槽；同题初态、checker、逐轮种子与开关次序可复算。按任务清单设置 `PYTHONPATH`，运行验收范围内的 `python -m thinking_events` 子命令，并在 Agent 测试环境运行 `python -m pytest scripts/tests/test_thinking_*.py`，核对退出状态。在 CLI、测试和冻结的 worker/scorer/GPU 进程核对模块名与真实路径，同一业务源码只加载一次，子进程源码来自冻结目录。
- [x] **退出、评分及恢复（T25–T31）。** 用独立正反例校验 worker 排空、退出封存后才由另一进程评分；错哈希、未排空的槽留有未评分原因。在领取后、评分前和封存后中断再恢复，每槽最多启动一次。用两轮实际输入/生成 ID 手算累计用量及含历史推理的 prompt，未知和迟到用量单列。
检查后续启动次数为零，退出前已持久化槽表、归档、封存与账本。起租、预热、两后端测速及收尾共享额度。

## 付费前置、测速与后端选择（AC4）

- [ ] **G3 准入（T14、T29、T36、T36a、T37）。** 对 `run-dev --g3` 分别传入通过、未通过、待判、缺失以及与逐轮哈希不符的证据。只有可核验的“通过”进入付费准备；其余分支由 CPU 输出 116 个未启动槽、零付费准备/冒烟、G1/G2 待判及原因。
- [ ] **Linux 主机（T36a）。** 在目标主机核查 CPython 3.11.16、Agent/server 独立环境及对应仓库锁，为本次两个模型登记并验证 Transformers/CUDA 和备选 vLLM 的独立 Linux 环境锁、包源及哈希。旧锁的版本只在原交付范围内作证。官方或镜像预取的两份模型按固定 commit 的可信清单核验配置、tokenizer、索引和所有分片，再离线加载。迁至不同绝对路径后复核冻结内容哈希、重新绑定路径并复跑 CPU 夹具。在该主机运行 `agent_harness check` 得到 93 个源码文件、零 provider 调用，且独立目录的脚本 smoke 有 worker、仿真与独立评分记录。
- [ ] **自然生成测速（T20、T30、T37）。** 两个模型 × 两种开关各预热一次，用 dev 外冻结夹具按约 4,096、8,192、13,000 个真实 prompt token 分档，每档三个自然请求。抽查原始 ID 数、首 token 时延、解码速率与端到端时延；样本数、短输出和超时可追溯。按方案从开臂三档的均值重算 7 轮和 12 轮的模型等待时间及两者占 500 秒的比例。
- [ ] **满长开臂（T37）。** 两个模型各在约 13,000 token 前缀上测 20 次，以生成 2,048 个新 ID 为目标；工具派发数为零。从原始数据重算最近秩 P95（第 19 个值）；样本不足或只能给下界时标为未确定。
- [ ] **切换与锁定（T29、T37、T38）。** 在 250 秒、刚超过 250 秒、自然估算不可得和满长 P95 未确定的夹具上校验两个模型的准入判断。适用补救时四臂统一改测 vLLM，核对模板输入 ID、参考生成 ID 的解析与用量、取消、权限、跨槽缓存隔离，重复全部功能与测速验证。准入时封存唯一后端及锁哈希；恢复时尝试切换须被拒绝。复测不合格或余款不足时正式槽零启动。[测速与准入公式](plan.md#t37-测速与-t38-准入)

- [x] **模拟输入的 G1、G2 配对（T32、T33）。** 用锁定的槽记录及用量格式输入合成配对。2B 开臂至少 3 个独立成功且至少 3 个可归因任务失败时 G1 通过。G2 完整配对、无截止偏倚时，净多成功至少 3 题且至少两个父场景净改善才通过；缺评分对时待判。已核对四格、各父场景净差、4B 单列表及缺失评分不可同时补作成功和失败的边界。[配对边界回归](../../../scripts/tests/test_thinking_paired_scores.py)
