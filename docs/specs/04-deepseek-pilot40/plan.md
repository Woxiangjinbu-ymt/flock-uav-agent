实际有多少合格教师轮由试采测得。40 题各有 500 秒任务窗口，顺序执行的任务窗口总和最多 5 小时 33 分 20 秒，另计准备、排空、评分与归档。试采后用本批观测重估余下 560 题。


1. **冻结输入。** 对母集摘要、两场原件、拟议两折和 40 个指令逐条核验。清单内指令摘要为原文 UTF-8 SHA-256。运行器侧保存本轮代码、工具数组、提示、权限、底层环境与依赖摘要。教师与学生在同一 FlockCue 方案下使用相同公开工具；感知工具采用本轮复测的新说明，完整描述 SHA-256 为 `d5b1e501ed100173ea316f45f819e757deefcec343af9302382ec60770ec09a1`。拟议场次为各场第 1 遍，本地运行种子分别为 3443555164 和 664273811，生成式与应用范围见清单。原始场景的生成 seed 未知，重现初态靠原场景字节。云教师请求采用官方支持的思考模式，单次记录服务返回的模型名及可得 fingerprint。[感知说明全文](../03-sense-tool-example/plan.md) · [冻结母集](../../../experiments/flockcue-benchmark-600-v1/)
2. **完整会话。** 每场冷启动一次，按 1–20 题执行。依原协议在题间落地、充电，继承位置、世界状态和共享黑板，校对前一题终态与后一题准备前状态摘要。每题使用当前命令与规范允许的公开反馈；一次模型请求只带当时可见的信息。落盘真实请求及返回、工具 ID 与回执、时间戳和 usage。归档不含密钥。每题先关闭新动作入口、排空已派发动作、封存终态，再用隔离进程运行原 checker，并对题初是否已满足同一检查另行标记。
3. **教师参数。** 采用 `deepseek-flash`，思考开启，`reasoning_effort=high`，同步非流式，SDK 自动重试为 0。带工具的同一题内按服务要求传回历史各助手消息的 `reasoning_content`，与 `content`、`tool_calls` 分开归档。设置单请求 60 秒、最多 8,192 个输出 token、单题最多 12 次 HTTP，全批最多 480 次。每题累计 usage 达 200,000 token 时收到当次响应后停止新增请求；最后一笔可能跨线。新题与第一场、第二场的边界均由有身份的状态记录驱动。[思考模式与工具调用](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/) · [现有教师消息适配器](../../../scripts/harness_deepseek_adapter.py)
4. **派发前预留。** 单流账本在发送前原子占用当次完整最坏价。沿用已验的 1,048,576 输入 token 上界、8,192 输出上界、200,000 请求字节限制。人民币单次预留 `(1,048,576×2 + 8,192×8)/1,000,000 = 2.162688` 元，美元为 0.3244032。每次同时检查已结算、未决预留与本次预留能否满足单题及整批上限。正常响应按 usage 结算再释放余量。余额不足时保留原分母及停因。试采计划无自动补题、重采、切换付费模型或扩量。
5. **故障恢复。** 为每个题位和请求分配稳定身份。正常返回的题位只读复用。下一题需要经过核对的世界、时钟和黑板交接；中断后无法证明继承状态时，保留本场余题为未启动。单题超时记录独立终态与动作排空结果，按已验证的题间规则决定能否接续。基础设施失效、缺测、模型自报、独立检查失败分别计数。
