## 要回答的问题

在十月原版 1,500 题部署所用的执行和评分条件下，当前完整 FlockCue 在冻结 600 题上能独立通过几题？同一批题的历史原版 Agent4Drone 首遍通过 506/600（84.33%）。分别给出新成绩和历史逐题配对，说明同名在线服务跨时期可能变化。以完整首遍的行为及失败证据决定后续模块取舍。此前巡逻与搜索 40 题的限额试采和据其产生的训练样本各保留原用途。[冻结母集](../../../experiments/flockcue-benchmark-600-v1/README_CN.md) · [历史 40 题审计](../../audit/harness-paired40-20261111/REPORT_CN.md)

## 本轮要求

1. 从十月完整运行计划按已确定的场景 ID 选回 30 场，保持原文件名升序、每场 20 题原序、源场景字节及原检查树。包括 15 个“任务族 × 难度”组合，每格两场。11 月两个试采场景同其他场景一起首次正式派发。每题只占一个正式席位。
2. 采用十月封存的真实本地 HTTP 仿真、场景并发、模型客户端设置、截止、排空、题间状态继承、失败计分和完整分母。以本批冻结的 FlockCue 作为被测策略，保留当前提示、合法工具、C 版感知语义、执行反馈、状态记录与适用子程序。以原部署允许的资源测量这一组合。开始后封存版本，不根据途中分数改提示、删模块或追加题次。
3. 每题记录公开指令、模型请求与回复、可取得的用量/指纹、工具调用与执行回执、截止与排空、冻结世界及原检查结果。每场进程和归档隔离；原始请求日志去除凭据。策略只读取原协议允许的公开信息。
4. 主指标为独立评分的整题 Task Pass / 600。按十月首次部署规则另报严格部署成功率，并逐项列通过、检查失败、超时已评分、终止性服务故障和未启动。若批次因服务或基础设施中断而不完整，额外给出实际覆盖，标为中断批次。
5. 对不一致题用可见历史解释失败发生在哪一步，先区分服务故障、世界继承、模型动作、工具回执和 Harness 机制。历史净差用于诊断。模块是否删减由正式首遍后的证据和必要的同条件消融决定。
6. Harness 定型后，收集并审阅真实 DeepSeek 教师轨迹，再推进约 2B 学生的 SFT、RL，以相同 Harness 和评测条件下的任务 pass rate 为主指标。Think/No-Think、选择性思考等研究延后。首遍结果用于开发时记录场景暴露，训练及最终留出评测按场景区分；“足够好”的 2B 数值标准在训练阶段开始前确定。[研究路线](../../RESEARCH_ROADMAP_CN.md)
