## 入口与免费验收

1. 在隔离的运行目录使用十月封存的调度器、仿真服务与评分。仅将已核验的 600 题子计划作为其输入，将当前 FlockCue 及 C 版工具接口接到 Agent 服务，保留模型客户端原始参数。当前常规命令只识别 smoke、pilot、calibration、full，`full` 会运行 1,500 题；当前付费教师入口绑定两场的固定摘要。须有专用入口，否则无法正确派发本批。
2. 从本地配置显式选 `deepseek_official`，创建独立、脱敏的运行配置。为每个场景进程设置独立的模型/回执/仿真记录路径，分开进程和凭据。技术验证检查实际请求体、模型内步数限制、共享黑板、工具使用、子程序可执行性及重试请求的独立用量记录。使用回环假服务验证多轮原始工具、C 接口以及真实动作/终态，并演练截止、并发请求归属和重复派发防护。
对比两期应用同一会话和任务 ID，标记子程序是否实际触发、哪些回执影响了随后动作、何处出现未满足的检查义务。任何中断先保存和复查原证据，整场重跑不计入正式首遍。
4. 免费验收后完成原模型预检，在各 worker 的首个真实请求核对模型、配置、工具及账本。仿真、模型，以及十月资料与十一月实际服务的差异，随最终报告一并归档。

十月原调度器在临时隔离工作区已通过其封存的 5 项本地 HTTP 集成测试，覆盖并行题序与黑板隔离、超时已达标、部分完成、超时后另一场继续，以及工作进程不能退出时保留分数并停止场内后续题。运行使用固定动作、1–2 个 worker 和缩短的测试时限，用时 32.986 秒，外部教师调用为零。当前 FlockCue 的两个脚本模型悬停回合也已独立复跑，完成判定分别符合缺少和具备悬停回执的预期。正式入口接入后仍须完成上表的联合验收。[十月执行器重跑日志](../../results/flockcue-600-original-protocol-preflight-20261111/october-runner-tests.txt) · [当前 FlockCue 本地复验](../../results/flockcue-600-original-protocol-preflight-20261111/flockcue-smoke.json)
