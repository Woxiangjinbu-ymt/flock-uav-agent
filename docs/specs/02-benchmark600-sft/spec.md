## 先让一次完整会话跑通

在 Mac 上用脚本模型验收连续 20 题。每个系统从同一份原场景文件单独初始化，按原顺序做题。题间依原协议落地、充电，位置、环境变化和共享黑板沿着该系统自己的轨迹保留。独立评分器在每题结束时用原 checker 对冻结终态打分。检查第 2 题确实继承上一题的状态，下一次整场重复恢复原初态；同时演练超时、服务中断和无法继续后续题的记账。2026-11-08 的 Mac 验收已完成。场景 `04cd6269` 的两次正常运行各有 20 份独立评分，79 项检查逐项一致。该场标注为本轮工程开发已见。超时、服务中断和后续未启动题均已按原顺序归档。根据用户的最新安排，目标 Linux 的独立复验顺延到租用 GPU 主机时，和 T36a 一起在测速前执行。此前可在 Mac 上核验数据格式。[完整会话验收报告](../../results/flockcue-mac-session-20261108/REPORT_CN.md)

## 教师数据如何采、如何做成教材

1. **先试采，再扩量。若试采沿用同一冻结协议并完整记录，计入首遍的 30 场、600 个教师题次。协议若因调试而改版，保留试采原账并单列该项成本。第二遍累计 1,200 题次，第四遍累计 2,400 题次。是否扩量取决于本折的有效示范、罕见恢复轮和重复率。扩量规则先定，折外成绩不用于决定采哪些场。
2. **逐轮生成训练样本。每条样本的输入是当轮可见的任务、可用工具、此前对话和按 ID 关联的回执；目标是教师当轮的回复、工具调用，以及该版本保留的教师推理。仅对目标算训练损失。按场景、执行遍次、任务、逻辑轮和原始请求摘要记录来源。私有场景数据、原检查树、终局评分和后续回执留在隔离的评估侧。
3. **先查质量再训练。** 拟以独立评分成功、工具合法、归档完整、有可归因动作的轨迹作为第一版示范。因继承状态而在题初已满足检查、服务失败、工具回执缺失、同一动作高度重复等情形单列，抽查后报告保留率。失败与剔除原因进入账本。后续可单独研究失败轨迹中确有依据的恢复片段。首轮、有执行事件、普通轮、未知轮和“应思考但教师无正文”分开统计，无正文仍可保留合格动作。
4. **同一批示范派生多种训练版本。** 先准备“全留教师已有推理”“全删”，再比较执行事件、教师自选、固定间隔和 LoGiC。前文历史也采用本版本在此前各轮的保留规则。LoGiC 在独立评分环境计算；评分模型随下一版技术方案固定。人工抽核和规则修正只使用当前训练侧或预先指定的公共开发夹具。[标签定义](../01-thinking-events/spec.md)

按过往 31 个开发回合的 214 个决策粗估，600 个教师题次约产生 **4,100 个筛选前决策轮**。原基准的长会话和难题会改变这个数，预算依据以整场试采为准。[历史轮数](../../results/thinking-events-g3-20261108/REPORT_CN.md)

试采如用于调试工具、提示词或标签规则，使用事先指定的开发夹具。600 题正式试采以锁定的版本执行，先查看运行状态、用量和故障计数。每个折的示范抽查、人工纠错和规则选择与另一折的训练过程隔离。教师可见的工具由运行环境提供；原场景 JSON 中的检查定义和预置动作字段只供仿真、评分或审计。

## 怎样训练，怎样选模型

| 顺序 | 实际操作 | 可以往下走的证据 |
| --- | --- | --- |
| 1. 固定输入和起点 | 两边从同一份原始权重分别开始训练，用固定 tokenizer、思考模板和工具解析，先检查小批样本的历史回执、推理段与损失掩码。 | 从样本能回查原始请求，长输入和截断有计数。 |
| 2. 甲训乙评、乙训甲评 | 甲侧训练的学生只参加乙侧 300 题；另从原始权重用乙侧示范训练一个学生，只参加甲侧 300 题。甲乙各自只访问训练侧的教师示范；从训练侧按整场留出内部验证集来选学习率、训练遍数、停止点及思考频率。可在选定设置后重训本侧全部 300 题。 | 两个独立权重各有训练场景清单、输入数据摘要、超参数和版本。两个方向及各标签方案在查看任何折外结果前一并锁定，测试场景与相应权重训练场景交集为零。 |
| 3. 从端点到选择性思考 | Linux GPU 上先单卡 LoRA 训练两个端点，确认可重载、能执行一整个会话；然后固定基座、数据、训练设置，比较各类思考标签。若两种标签实际产生完全相同的监督，记录重合并复用权重。 | 内部开发整题成功数、工具合法率、超长比例、推理及总 token、显存和耗时可查。评估时学生依据公开回执自行做决定。 |

每种训练方法最终汇总两份权重各自的 300 题成绩，形成一个覆盖 600 题的折外结果。若另做面向演示或部署的单份权重，可在实验结束后用全 600 题重训，单独登记；这个权重若再跑同一题池，只能报告已见题表现。

## 最终怎样比较

| 系统组合 | 比较用途 |
| --- | --- |
| A · 原 Agent4Drone + DeepSeek | 系统基线。 |
| B · FlockCue + 同一 DeepSeek | B 对 A 衡量同一模型更换 Harness 的差异。模型服务版本、时间窗和有效采样配置留档。 |
| C · FlockCue + 原版小模型 | 小模型的零样本起点。 |
| D · FlockCue + 同基座 SFT 小模型 | D 对 C 衡量蒸馏效果；D 对 B 衡量与教师的任务成功率、token 和时延差距。事件版与固定间隔等版本在相近思考比例或推理 token 下比较，差异和容差预先登记。 |

统一原始场景、顺序、底层可用工具和权限、500 秒任务窗口、排空、独立评分与服务失败的处理。每题记录原 checker、部署成功、超时、服务故障、未启动以及模型自报。预登记计划分母；服务故障按统一口径计入，保留实际未评分原因。按场景配对、按任务族和难度分组，另报各组实际机队规模。历史 **506/600** 单列为参考。新 A/B 拟在相近时间运行；B 的首次教师轨迹只有在运行前已登记为同配置的正式重复、完整保留全部结果时才可同时用来计分和派生示范，训练筛选不改变评测分母。

第一轮可先各系统整场跑一遍，覆盖 600 个题次；原路线的三次正式重复按整场从头做，形成每系统 1,800 个计划题次。A/B/C/D 四组各三遍为 7,200 个评测题次；增加标签对照另计。D 的两折合计每遍 600 题。教师 API、训练 GPU、学生评测 GPU、存储及收尾分别记账，以试采实耗和单独核准的上限决定批量规模。[既有预算范围](../01-thinking-events/plan.md)

## 验收与交付顺序

1. **已冻结的输入。** 原始 ZIP、30 份场景原件和 600 个有序任务 ID 通过摘要核验；甲乙折并集等于母集。
2. **完整会话与试采。** Mac、Linux 得到 20 个有序任务的账本、跨题继承与重启证据；
3. **SFT。** 每条训练行可追回原轮，抽查无私有字段；每份权重能重载并跑完整场，训练与外评分组无交集。
4. **系统与论文结果。** 相同题单上形成 A/B/C/D 配对和选择性思考对照，能追溯失败、未运行、停线和实际成本。RL 的在线采样及过程奖励另立后续规格。
