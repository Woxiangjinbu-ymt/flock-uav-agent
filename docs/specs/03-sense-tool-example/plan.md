## 输入准备与推理边界

1. 协调器只读载入 [50 条请求索引](../../results/flockcue-a100-interface-20261111/sense-prefixes.jsonl)，校验规格中的索引哈希，并验证原 `run/campaign.sha256` 为 `ba8b8e2d10bdc54af7c5ff97c6919f5b2727a50de7e68db80efb9c7f67f5d2d6`。以 `slot_id + turn` 定位 worker 封存的决策，再按 `sdk_body_sha256` 从 `policy/modelio` 中唯一匹配原始 HTTP 请求体。校验 base64 解码字节的摘要、原轮种子、已耗 token、原工具 schema 和思考开关。
2. 直接按原字节反序列化 JSON，保留工具列表、属性顺序、公开消息、历史思考字段和工具回执。B 在原对象的深拷贝上修改现有描述值。按序比较 A、B 全部字段，允许上述一个值变化；分别用冻结模板重新渲染并逐条核对上表。A 的历史生成 ID 再经原解析器复核其归档结果。所有检查通过才装载权重。[2B 渲染与整组解析](../../../scripts/flockcue_qwen35/adapter.py)
3. 沿用 T37 已验收的 Transformers 环境、Qwen3.5-2B 修订 `15852e8c16360a2fea060d615a32b45270f8a8fc`、A100 40 GB、BF16 和 batch=1。一张卡、一个常驻模型，逐请求重置原种子。采样使用 temperature 0.6、top_p 0.95、top_k 20、repetition_penalty 1.0 和原 EOS。使用冻结 `run/source/scripts` 的 `StudentProcess.request` 与 `student.output_budget`；恢复该位置的 `spent_before`，按 A 或 B 实际输入长度执行 32,768 上下文、100,000 累计 token 及 2,048 本轮上限。单轮从本次发出请求重新计 120 秒，原 50 个位置的回合余时均超过 120 秒。[进程与计时](../../../scripts/thinking_events/student_process.py) · [推理及用量](../../../scripts/thinking_events/student_service.py) · [预算函数](../../../scripts/thinking_events/student.py) · [T37 记录](../../results/flockcue-a100-g1g2-20261110/T37_CN.md)
4. 按索引行号从 1 开始，奇数行先 A 后 B，偶数行先 B 后 A，各 25 对。两个条件各自从同一份原始历史开始。推理服务只接收公开消息、工具及必要的轮次、种子、预算和计时元数据；历史结果标签、私有 checker、仿真状态只供离线核验。模型给出的调用止于解析，整个实验发起 100 个计划单轮请求。

## 实现入口、恢复与交付

拟新增独立入口 `scripts/diagnose_sense_example.py`，按 `prepare`、`run`、`report` 三步使用。准备阶段读取索引和封存归档，在新实验目录写入依赖摘要、干预文本、两侧输入 ID 摘要、实际预算和 100 行运行顺序。执行阶段只读准备结果，向常驻服务发起单轮请求。汇总阶段从逐条记录重新计算配对结果，可在 Mac 上离线复算。A100 使用独立目录 `operations/sense-example-20261111/`，回传 Mac 后在 `outputs/` 保留完整运行目录；正式 G1/G2 的 116 条评分始终由原归档提供。

- 每个 `(slot_id, turn, A/B)` 先落盘领取，再发请求，终态原子提交。记录输入与输出 ID、结束原因、EOS、严格解析结果、输入/推理/全部 token、时延、峰值显存及服务身份。复用项目已有的文件锁和原子写入。正常完成的槽只读复用；恢复时核对模型、运行代码、输入表和说明的摘要。[封存写入](../../../scripts/thinking_events/campaign_storage.py)
- 请求超时触发取消并关闭相应推理进程，下一条可在预算内重载同一模型。对已有完成回执的槽恢复记账；进程退出且发出状态不明的槽记基础设施缺测。两种情况都保留本槽唯一尝试。分别报告完成、超时、错误、缺测和未启动数量。按 A/B 列出输入、推理与总 token，已知样本数、请求时延 P50/P95 和峰值显存。超时不可观测的 token 量记为未知。
- 该步交付原始记录索引、逐前缀 A/B 表、分组统计、中文结论和阶段时账。复算需从归档验证原始 ID 的解析、两臂分母与总账一致，再发布结果。

## 计分与解释

主事件为解析器接受整个回答，且返回的 `message.tool_calls` 至少含一个 `sense_nearby_entities`。每个条件以 50 为分母，每条至多计 1。一个回复内感知调用合法、同组其他调用无效时，该组判未通过。思考文字或解释中提到函数名不构成调用。

以完整可比较的 A/B 对生成四格，另列缺对。从配对请求中计算仅 B 通过减去仅 A 通过的净变化。按原缺参 42 条、原字段展平 4 条、原有回执 4 条及原思考开关（27/23）分组。另列新 A 的输出 ID 与历史逐个相同的数量、主事件重现数量。干预效果以本次新 A 对 B 定义。

除主事件外，分别统计整组可解析但跳过感知、感知参数错、同组其他调用错、其他格式错或无法定位、生成截断、请求超时及无输出。仅在完整回答段的工具块上用同一解析逻辑定位错误；截断或异常使具体调用归属含糊时保留原因。健康服务的协议超时按观测到的停因计为该条件未通过，服务故障或丢失响应单列缺测。报告各栏时说明主事件与诊断计数的对应关系。这个实验测量参数说明与合法调用的关系；在线任务效果仍需独立运行和评分。
