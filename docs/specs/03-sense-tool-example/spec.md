## 研究问题

11 月 10 日原始 2B 的 58 个开发回合中，46 个终止于 `sense_nearby_entities` 参数错误，涉及 24/29 道题、全部五个父场景。其中 22 道题的开、关思考两臂都出现该错误。原批次另有 4 次该工具通过整组解析，在下一轮公开历史中可以找到感知回执。工具定义要求外层提供 `input_json`，现有说明给出的例子只展示内层字段。要检验的是：仅让说明给出完整调用参数后，模型在相同决策位置生成有效感知调用的频率如何变化。[原评分](../../results/flockcue-a100-g1g2-20261110/REPORT_CN.md) · [失败审阅](../../results/flockcue-a100-g1g2-20261110/TOOL_ARGUMENTS_CN.md) · [逐请求证据](../../results/flockcue-a100-interface-20261111/sense-prefixes.jsonl)

## 配对范围

固定上述 50 条原始请求。每条取调用前模型实际可见的历史、工具清单、思考模式、原轮种子及该轮剩余 token 预算。27 条开思考、23 条关思考，合计 28 道已暴露的 dev 题。索引 SHA-256 为 `2384472a4916f86981e1c8e137e259f1c9b9e5107cf83a5df566b8945954f8c7`。数据由旧输出表现选取，推断范围限于这批决策位置。私有评分记录在评估侧保存。

A 条件重放 11 月 10 日的公开工具说明。B 条件只改 `sense_nearby_entities` 的描述，指出默认查询也必须传 `input_json`，并给出完整外层参数的默认与定向两例，例如 `{"input_json":{}}` 和 `{"input_json":{"drone_ids":["<从机队回执取得的 ID>"],"detail":"summary"}}`。正式技术方案应固定实际示例文字。两个条件共 100 次单轮生成，均用同一 2B 修订、严格解析器、整组验收规则、BF16 后端及采样参数。对两种描述逐请求交替先后次序，各使用一次原种子。每次生成最多 2,048 个新 token、120 秒，并服从原轮累计 token 和上下文限制。测量工具选择及其参数，不向仿真器派发本次生成的调用。

## 测量与验收

1. 逐条验证 A 的公开请求与原归档，复算输入 ID 及原输出的解析结果。B 的公开请求只允许上述一个描述字段发生更改，记录两侧实际输入长度及输出预算。新 A 的生成结果与历史真实输出分别封存，公布重现数量及差异。
2. 主指标为每个条件中「模型主动调用该感知工具且同轮整组通过严格解析」的次数 / 50。逐条配对列出均通过、仅 A 通过、仅 B 通过、均未通过。另列未调用该工具、该工具参数错、同组其他调用错、其他格式错误和超时或无输出。基础设施缺测保留原分母并标注，单列可比较对数。
3. 对原来的 42 条缺参、4 条字段展平、4 条有回执分别报告结果，同时列开关思考的分母、时延、实际 token 与运行成本。若合法调用增加，同时报告回避该工具或发生其他错误的数量。工具可解析只衡量接口使用能力，整题成绩以此前独立 checker 报告为准。
