## 输入和配对能否重建

- [x] **T01 · 来源唯一。** 在 CPU 上从原运行归档准备输入，以封存的索引、campaign 与请求体 SHA-256 核对每个位置。应恰好匹配 50 条，覆盖 28 道题，开思考 27 条、关思考 23 条。分别注入摘要错误和重复匹配，准备流程应在装载权重前停止。[原始索引](../../results/flockcue-a100-interface-20261111/sense-prefixes.jsonl)
- [x] **T02 · 旧说明可重建。** 把 A 的输入 token ID 与历史记录逐个比较，须 50/50 完全相同。用冻结解析器重放历史输出 ID，并核对公开工具回执，应复得缺外层参数 42 条、字段展平 4 条、有感知回执 4 条。保存每条的核对结果。
- [x] **T03 · 新说明仅改一处。** 按字段路径和原顺序比较 A/B，唯一差异须是目标工具描述，两个完整描述的摘要须与方案相同。每条 B 比 A 多 48 个输入 token，两侧可生成上限均为 2,048。另改一个字段或调换工具顺序，准备流程均应报错。
- [x] **T04 · 排序可复现。** 独立准备两次，比较两份清单摘要。须得到相同的 100 个唯一槽，每个位置各有 A/B 一槽，两个条件沿用原种子。按索引从 1 数，奇数行先 A、偶数行先 B，各 25 对。

## 派发、取消与预算能否核验

- [x] **T05 · 两侧从同一公开历史开始。** 用 CPU 替身捕获发给模型的两份请求，逐项核对消息、公开工具、思考开关、原种子和已耗 token。按实际输入长度复核上下文与输出上限，每次从本次请求重新计 120 秒。检查请求内容和调用记录，确认历史结果标签、私有检查及仿真状态留在评估侧，生成的工具调用止于解析。
- [x] **T06 · 中断后每槽最多派发一次。** 模拟并发启动、派发后中断、原始回执落盘后中断。核对逐槽派发次数，已有回执的从回执恢复，派发状态不明且无回执的列为缺测；改变模型、运行代码或准备清单摘要后续跑，应在派发前停止。
- [x] **T07 · 卡时上限可以实际执行。** 用可控时钟验证，服务已就绪且余额恰有 180 秒时可派发一次（120 秒请求、60 秒收尾），少 1 秒时停止。另测需重载且余额不足以覆盖 180 秒装载、请求和收尾的情形。
- [x] **T08 · 超时与缺测可区分。** 分别模拟健康服务的协议超时和服务退出丢失响应。前者记已观测未通过，取消并关闭进程；下一槽仅在预算足够时重载。后者记基础设施缺测。两者均保留尝试记录，不可观测的 token 记未知。运行改动涉及的 Python 编译检查、CPU 回归测试及仓库已有适用检查，保存命令和退出状态。

## 从输出能否算出同一结果

- [x] **T09 · 按整组调用计分。** 从原始生成 ID 重放冻结解析器。依次输入合法感知、只在思考文字中提到感知、合法感知与坏调用同组、同轮两次合法感知，主分须依次为 1、0、0、1。逐例核对跳过感知、感知参数错、同组其他调用错、其他或无法定位的格式错、截断、超时和无输出的诊断记录。
- [x] **T10 · 固定分母与净变化。** 用已知答案验证汇总。例如 50 对中，均通过 2、仅 A 通过 3、仅 B 通过 5、均未通过 38（含健康超时）、两侧均缺测 2，应报 A 为 5/50、B 为 7/50、可比较 48 对、配对净增 2。再将一个缺对改为仅 B 有合法观测，应报 B 为 8/50，可比较对数与配对净增保持原值。实测表须列原 42/4/4 类与思考开关 27/23 类，并分别列出新 A 与历史 A 的输出 ID 完全一致数、主事件判定一致数及可比较数。

## A100 运行到 Mac 复算

- [x] **T11 · A100 原始证据。** 先在服务器用 CPU 重建清单，再核对固定 2B 权重修订、T37 后端、采样参数、BF16、batch=1。按冻结顺序执行，逐槽核对状态与回执。对已返回的输出核对输入和生成 ID、EOS、停因、整组解析、用量、时延与服务身份。完整运行应有 100 次派发，并列明每次尝试的终态。遇到预算或故障停线时，按实列出已派发、缺测和未启动槽及原因，标记为部分运行。
- [x] **T12 · Mac 离线复算与交付。** 将原始目录回传 Mac，校验文件摘要后独立生成逐前缀 A/B 表和中文报告。与服务器逐对核对分类、主分、分母、用量及时间账本。结论注明这 50 个位置按历史输出选自已暴露的开发题，度量的是单轮合法感知调用；整题成绩引用[原 116 个回合独立评分](../../results/flockcue-a100-g1g2-20261110/REPORT_CN.md)。
