面向多无人机协作任务的小模型后训练Harness 引导的数据构建、监督迁移与条件式策略优化

以阶段一的执行与接管机制为基础，将强 Teacher 在多无人机环境中的真实决策与执行反馈转化为可验证的训练数据，先建立约 2B Student 的 SFT 与回接评测闭环，再依据奖励、采样信号和资源条件决定是否开展 Agentic RL。

01 / RESEARCH POSITION把可验证的协作决策能力迁移到小模型

阶段一主要改变模型周围的运行机制：用公开证据组织状态，以计划契约管理技能执行，在依赖失效、效果不明或修复耗尽时交回模型。阶段二进一步改变模型参数，使小模型能够在同一机制下选择技能、分配无人机、填写工具参数、处理接管并判断剩余任务。两阶段围绕同一个协作问题组织，Harness 同时承担数据生产、执行约束和评估支撑的职责。

本路线沿用集中式主 Agent：一个语言模型调度多个 UAV，并利用 Harness 暴露的工具和技能完成任务。学生目标规模约 2B，承担高层任务与工具决策；低层飞行控制、几何计算和既定技能内部流程仍由环境与程序实现。基座、推理部署与训练配置尚待选择。

研究问题要建立的证据不预设的结论
RQ1：什么轨迹值得学习？结构、执行效果、任务完成和决策质量联合验证，能否提高训练样本的有效性？Teacher 输出或最终成功不自动意味着每一步都正确。
RQ2：SFT 能迁移哪些能力？同一基座、同一 Harness 下，任务成功、工具使用、接管与停止判断是否改善？训练 loss 降低或格式正确，不等于端到端能力提升。
RQ3：何时需要进一步 RL？SFT 后仍存在的决策错误，是否能由有效 rollout 与可验证奖励提供改进信号？RL 不作为必须完成的阶段，也不保证优于 SFT。
RQ4：提升来自系统还是模型？固定 Harness 比较训练效果；固定模型比较 Harness；对关键数据规则单独消融。系统技能、公开权限或预算变化不能直接归因于模型学习。

建议的首轮切入点：优先围绕“技能选择、退出与接管”选定一个具有实际决策机会的协作失败族，明确模型在什么状态下需要重新选择 UAV、工具或剩余子任务。广义规划、分配和恢复可作为能力标签，但不同时扩展为多个互不相干的研究题目。若自然任务中没有恢复机会，应收缩研究问题或另设有独立标识的受控协议，不能用零机会回合推断恢复能力。

本报告将“蒸馏”理解为 Teacher → Student 的能力迁移思路，第一条实施路径为轨迹 SFT；不额外预设一个独立的蒸馏训练阶段。研究假设、工程交付与实证贡献需分别验收。

02 / METHOD OVERVIEW以执行证据连接数据、训练与评估

图 1 从共享环境出发，将 Teacher 交互、数据验证、Student 优化和回接评测连接为一条主线。实线表示核心流程，绿色虚线只表示开发反馈，紫色虚线表示条件式 RL 路径。颜色区分模块职责，不表示实现进度。

模块阶段二职责与阶段一的连接
Teacher Agent在规定权限和预算内产生规划、工具调用与接管决策，记录实际模型身份与完整交互。复用主 Agent、公开上下文与技能接口；不为 Teacher 开放隐藏状态。
Harness / Environment执行动作、维护公开证据、管理技能生命周期、结束与归档独立回合。复用计划契约、适用性门控、局部修复、原工具接管和执行记忆；按实验冻结版本。
Verifier / Dataset Builder检查轨迹结构与实际效果，分流样本，生成带来源、质量标签和监督掩码的数据。在模型 I/O、工具回执与独立 scorer 结果之上构建；现有 JSONL 只是原始输入。
Student / TrainerSFT 学习有效决策；条件成熟时通过交互奖励优化策略。替换模型策略；确定性技能动作仍属于运行机制。
Evaluation固定模型外部条件，量化成功、工具正确性、恢复、泛化与成本。复用独立回合和隔离评分，增加训练版本、数据版本及模型对照。

Teacher 与 Student 应共享任务、工具和公开信息的语义。两者可以使用各自模型要求的序列化模板，但必须记录差异；不得把 Teacher 的额外上下文、人工提示或后验信息悄悄当作 Student 可见输入。

03 / PREPARATION先冻结研究接口，再扩大数据规模

数据格式、输入预算和部署接口需要在大规模采集前对齐。准备工作可与 Harness 的有界修复交叠推进；近期交付应围绕被选定的决策职责，避免为了训练准备而扩张全部架构。[研究路线]

  1. 冻结决策职责。明确是学习技能启动／恢复／取消／原工具接手，还是还包含细粒度动作；列出可见状态、可调用工具、动作约束、接管机会与任务成功标准。
  2. 冻结独立划分。建立新场景、种子和任务族清单；同一场景的改写、重复采样与衍生版本按组划分，防止相邻轨迹进入不同集合。训练集用于采样与优化，开发集用于选型和错误分析，测试集只在配置冻结后评价。
  3. 对齐 Teacher 与 Student 接口。验证工具 Schema、消息模板、角色边界、上下文长度、截断策略与推理输出解析；先验证样本可训练、模型可回接，再扩大付费采样。
  4. 完成运行与资源预检。—

划分边界。历史 main300、dev240、validation60、fast100、full1500 等已用于开发或分析的数据，不能重新命名为未见测试。历史错误可以指导新训练任务设计；开发反馈形成的数据修订也必须保留来源。若某批开发案例被直接转作训练，它就不能继续承担该轮开发评价，需更新划分清单。

正式泛化结论须区分“同任务族的新场景／种子”和“留出的任务族”，并核查场景模板与派生数据的重叠。新增故障注入应单列协议，遵守现有环境约束，不能混同于原静态障碍 benchmark。

04 / WP1 · TEACHER DATA构建执行感知、可追溯的决策轨迹

4.1　从完整归档生成可训练视图

原始回合是证据载体，训练样本是对原始证据的受控投影。每个样本应能追溯到回合、模型请求和决策位置，重建该决策产生时的公开信息；后续工具回执与终态可以用于质量验证，但不能被提前放进该决策的输入。

记录层核心内容训练用途
回合与配置episode ID、场景／种子／任务族、划分、代码与 Harness 版本、模型身份、采样参数、预算、时间和终止原因。重现、分组划分与统计；元数据不自动拼入提示词。
公开模型交互实际请求消息、工具定义、模型响应、tool call ID、调用顺序／并行关系、公开工具回执。重建因果上下文；审核真实 assistant 输出后生成监督标签。
执行与 Harness 事件任务进度、公开证据更新、技能开始／暂停／失效、局部修复、接管、实际动作效果。解释执行结果、标记决策机会；仅在当时确实暴露给模型时进入上下文。
隔离评分证据终态、隐藏检查、任务完成分数、归档完整性与评分器版本。离线质量标签、最终评价或经设计的 RL 奖励；与策略可读消息分离。

若 API 实际返回 reasoning_content，可原样保留并记录来源；未返回时不补写“原始推理”。Harness 执行某项宏技能时产生的内部动作，不能伪装为模型逐步生成的工具调用。评估侧私有信息和原始归档应按回合 ID 关联，训练器只读取经过审核的公开视图。

4.2　四层质量验证

层级主要检查失败后的处理
L1 · 结构消息完整、角色合法、工具 Schema 可解析、call/result 关联正确、并行调用与结束状态明确。标记截断、缺失或异常；不能将断裂轨迹作为完整成功示范。
L2 · 执行UAV／目标绑定、参数合法性、动作实际效果、重复执行、效果未知与过期技能恢复。保留具体错误位置与可见证据；区分程序执行问题和模型决策错误。
L3 · 任务由独立 scorer 检查任务义务与终态；区分完整成功、部分完成、失败和不可评分。不能用模型的成功宣称代替检查；评分失败保留为独立状态。
L4 · 决策质量无效调用、冗余、恢复价值、接管选择、停止时机，以及输入是否足以支持目标决策。按明确规则标记质量与筛选理由；对边界样本抽样复核。

以上验证组合成数据筛选方法，规则与阈值由训练／开发阶段确定并版本化。其是否带来学习收益仍需实验验证，不能把“增加检查器”直接当作已经成立的方法贡献。

4.3　样本分流与小规模 pilot

首版正向 SFT 优先使用完整成功轨迹与经验证的恢复决策。在恢复样本中，先前错误和失败回执可以保留为因果历史，但错误 assistant 输出不默认成为正向目标。部分完成与失败轨迹留作诊断、纠错任务设计及后续策略研究；若要回收其中的有效局部决策，需单独验证上下文完整性与标签正确性。

成功、恢复、工具使用、接管是可重叠的能力标签；成功／部分完成／失败／不可评分则是回合结果分类。统计时分开报告，避免把重叠标签比例相加。pilot 先检查样本是否足够覆盖目标决策，再决定扩量，不预先以一个大回合数替代质量门槛。

  • 数量与覆盖：回合数、唯一场景与任务族数、有效决策数、恢复／接管机会数、结果分布。
  • 完整性与质量：结构通过率、缺失／截断／重复比例、四层筛选通过与排除数量、抽检分歧。
  • —序列长度、决策轮数、有效标签 token、工具调用、每条合格样本的采集成本。

WP1 交付：可追溯的录制与转换流程、四层 verifier、带排除原因的数据清单、冻结划分、首版训练／开发数据及统计报告。已有离线接口通过和旧 JSONL 记录均不能代替该验收。

05 / WP2 · STUDENT SFT训练模型负责的决策，并验证其能在环境中执行

5.1　监督目标与样本边界

训练目标覆盖任务理解、子任务规划、无人机分配、工具选择与参数、多轮状态判断、异常恢复、接管与停止决策。这些是能力维度，不要求 Teacher 额外生成一套并不存在的结构化分析字段。首先保持真实对话与工具协议，再检验是否需要更紧凑的公开上下文。

ℒSFT = − (1 / ∑t mt) ∑t mt log πθ(yt | x, y<t)

这里 mt 仅在审核通过的真实 assistant 决策与工具调用 token 上取 1；system、user、tool 回执及未批准的错误输出取 0。已执行的错误可作为历史保留，环境响应作为观测条件使用，二者不因此变成要模仿的正确答案。没有有效标签的样本不进入训练。

TRL 的 SFT 工具调用数据使用带 tool_calls、tool 角色响应的 messages，并提供 tools Schema；assistant_only_loss 依赖模板能返回 assistant 生成掩码。项目仍须验证选定基座的角色边界与 token 掩码，并在 assistant 范围内叠加质量筛选，不能把“只训练 assistant”当作样本已经审核。[TRL 官方文档]

长轨迹可按决策窗口切分，但必须保留目标决策依赖的公开状态、工具定义、调用关联与接管证据。上下文压缩或摘要需要记录转换方式并核对信息充分性；不得在截断前提后继续保留只有完整上下文才能解释的标签。原始归档始终保留，训练时与部署时的输入构造保持一致。

5.2　推理内容采用受控变体

变体样本内容比较重点
决策与工具调用审核后的实际动作决策和必要输出，不要求额外生成长推理。作为较简洁的起点，评估工具正确性、任务成功与推理成本。
简短可见解释保留真实简短解释；若另行生成摘要，标记为派生数据并单独审核。输入／输出长度与决策效果；不把事后摘要标成当时原始推理。
完整返回推理仅使用 API 确实返回、允许使用且与 Student 模板兼容的推理内容。监督长度、有效信息与成本；验证长轨迹是否适合小模型学习。

这些变体是候选消融，首轮不要求全部实施。比较时报告有效监督 token 和训练计算量，避免把更多训练量带来的差异归为推理形式本身的效果。

5.3　训练、导出与回接验收

初期采用参数高效微调作为候选实现。LoRA 通过可训练低秩更新适配冻结权重；QLoRA 进一步结合量化基座与低秩适配，提供降低内存需求的候选路径。二者均需在所选模型、序列长度和训练器上实测，不能由论文中的显存结果推断本项目配置必然可行。[LoRA] [QLoRA]

  1. 样本与模板验收。检查角色／工具模板、标签解码、掩码、长度分布及上下文依赖；使用小批数据验证训练链路。
  2. 形成首个可部署检查点。记录模型 revision、数据版本、训练配置、随机种子、峰值显存与时间；一并导出 tokenizer、模板、Adapter 或完整权重和推理配置。
  3. 回接同一 Harness。实测多轮工具调用、错误响应后的继续决策、技能接管和停止；检查训练端与推理端的参数和序列化差异。
  4. 在开发集上与基座比较。同时看端到端成功、工具错误、机会条件下的恢复和成本；根据错误来源修订数据／上下文，再冻结待评模型。

WP2 交付：可复现的 SFT 配置、可加载模型或 Adapter、统一推理入口、基座与 SFT 的开发集对照和失败分析。若 SFT 无增益，优先定位数据、输入、监督边界与分布偏移；不直接通过增加 RL 阶段掩盖问题。

06 / WP3 · CONDITIONAL RL只有交互信号可用时，进一步优化策略

Agentic RL 的对象是模型在真实环境交互中产生的决策序列。Student 根据公开上下文选择工具或技能，环境执行并返回观测，隔离评分侧计算奖励；训练器据此更新模型。确定性技能内部动作不具有模型生成的 action log-probability，不能作为学生逐步采样的动作参与策略梯度计算。

准入条件需要的验证不满足时的行动
可用 SFT 起点能够稳定解析工具、完成有效回合，存在值得进一步优化的模型决策问题。先修复 SFT 数据与回接，不启动大规模 RL。
可验证奖励成功与进度语义明确，私有检查隔离；提前终止、重复动作和部分进度套利通过反例检验。收缩任务与奖励，保留 SFT 路线。
有效 rollout独立初态、终止语义、超时排空、归档与评分可追溯；奖励能区分策略质量。补齐训练器适配和运行器；若奖励几乎恒定，先调整任务难度或采样设计。
成本可承担测量有效回合／小时、采样成功率、GPU 时间、显存与总预算。减少范围或暂缓 RL；不影响 SFT 与统一评测交付。

奖励以端到端任务成功为核心，公开可验证的进度、无效动作和调用成本可作为辅助候选。奖励项、范围、权重及终止规则需在训练／开发数据上校准，防止模型通过过早停止、重复领取进度或不完成任务来优化成本。不得用测试评分反复设计奖励；基础设施异常与策略失败要分别标识，既保留全部尝试，也避免把不可评分回合的缺失值直接解释为策略信号。

PPO 与 GRPO 保留为算法候选。PPO 提供交互采样与策略更新框架；DeepSeekMath 中提出的 GRPO 使用组内相对奖励构造优化信号。若选择 GRPO，需要同任务条件下相互隔离的多条 rollout 和有区分度的奖励；组内结果近乎一致时，学习信号可能不足。算法在其他领域的效果不能直接外推到本项目。[PPO] [DeepSeekMath / GRPO]

环境可以从现有“fresh worker → 归档 → 退出 → 独立 scorer”路径起步，但需实测吞吐和训练器接口。现有 World.restore 尚不能代表通用 RL reset；同样，也不必把全量向量化 reset 系统设为 SFT 准备的前置条件。[环境复用依据]

WP3 交付（如开展）：版本化奖励、rollout 适配、训练记录、策略检查点，以及同协议下相对固定 SFT 起点的收益与成本。若不开展，报告准入证据与限制，不把候选算法写成已完成训练。

07 / WP4 · EVALUATION固定外部条件，分别回答系统与训练是否有效

统一评测先固定任务集合、初始状态、工具权限、技能语义、Harness 版本、顺序／调度、采样参数和预算。训练消融使用同一基座；报告实际模型版本、分母、评分协议与失败类型。Teacher 可作为能力与成本参照，其成绩并非严格上界。

对照组控制方式回答的问题
同基座 + 基线运行方式
vs 同基座 + Harness		固定外部任务、原工具权限、初态和预算；明确宏技能等接口差异。整个系统方案的贡献。若要单独判断门控作用，进一步固定技能与动作能力。
同基座 + Harness
vs SFT + 同 Harness		保持公开输入、工具和执行机制一致；记录模型模板必要差异。监督训练带来的策略变化。
SFT + Harness
vs SFT+RL + 同 Harness		从固定 SFT 检查点出发，冻结评测与奖励协议。RL 的增量收益及额外训练成本，仅在实际开展后报告。
关键数据／系统消融优先比较验证规则、有无恢复／接管样本，或固定技能下的门控；配平数据规模或监督 token 并说明偏差。所提方法中的哪一项机制解释了提升。

“基座 + 基线运行方式”应在实验中给出具体实现，不能用不同工具能力的简化壳层替代 Agent4Drone，却仍声称复现了原论文对照。原论文排行榜与历史非同协议结果可作背景，不作为新训练实验的直接提升基准。

09 / REPORT-READY TEXT可直接纳入阶段研究报告的路线说明

第二阶段拟开展面向多无人机协作任务的小模型后训练研究，重点是利用阶段一建立的 Agent Harness，将强模型在环境中的协作决策能力迁移到约 2B 学生模型。整体采用集中式主 Agent，由语言模型负责任务理解、无人机分配、技能选择、工具参数、异常恢复和控制权接管；Harness 负责公开状态组织、执行约束、技能运行、证据归档与独立评估，从而保持模型策略与确定性执行机制的责任边界。

研究首先在冻结任务协议与独立数据划分的基础上，采集 Teacher 的真实环境交互，保留模型输入输出、工具调用关联、执行回执与 Harness 事件。随后通过结构完整性、执行正确性、任务完成度和决策质量四层验证构建版本化数据集，优先使用完整成功轨迹与有效恢复决策。训练数据只包含当时可见的公开上下文和经审核的模型输出，隐藏检查与私有状态用于隔离验证，不进入策略输入或示范；技能内部动作也不被误标为模型决策。

学生模型优先通过监督微调学习工具使用和多轮协作策略，监督范围限定为有效 assistant 决策与工具调用。训练后模型将接回同一 Harness，在相同任务、权限、初态与预算下与未训练基座比较。只有在 SFT 起点可用、奖励可验证、交互采样稳定且资源可承担时，才进一步开展 Agentic RL，并以固定 SFT 检查点为对照评估增量收益。

最终评价以端到端任务成功率为主要指标，同时报告工具正确性、恢复与接管机会、泛化和全流程成本。通过固定模型比较 Harness、固定 Harness 比较训练模型，以及对关键数据规则开展消融，区分系统机制与模型学习的贡献。当前已有执行与归档基础，Teacher 数据集、SFT 和 RL 尚未完成；下一步将优先完成协议冻结、可训练样本转换与小规模闭环验证。
