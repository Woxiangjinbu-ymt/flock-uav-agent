# FlockCue 第 1 步 · 轨迹验证器判断契约

**状态：待审批　｜　日期：2026-11-07**

## 目标与范围

让两位不了解结局的读者看到同一段轨迹时，能分别回答以下两个问题。主 Agent 提出的这组工具调用，按当时所知是否有依据？回执到达后，哪架无人机的哪项任务有了进展、遇到阻碍，哪些事实仍未知？每个结论都要能指回当时可见的一条指令、工具约定、观测或回执。

第 1 步交付判断口径、真实开发轨迹的双人试标结果，以及值得小模型学习的问题清单。首批正式训练按 **300 条合格训练样本**估算，属于后续阶段。本步复用已封存的真实 DeepSeek 决策及仿真反馈。已有开发样例只用于澄清口径与验收。候选动作排名、反事实收益、在线提醒与训练效果由后续实验评估。[开发路线](../../RESEARCH_ROADMAP_CN.md) · [轨迹与划分背景](../../audit/trajectory-verifier-plan-20261107/REPORT_CN.md)

## 同一次决策的两个判断时刻

一次真实主模型回复提出的一组调用，算一个**决策**。一组可以涉及多架机，也可以只有一次查询。前后两份判断共享这个决策的身份。并行四次调用算一个决策、四个调用。子程序内部的工具动作作为执行证据，不能再算一次主模型决策。

| | 调用前 · 选择判断 | 回执后 · 执行判断 |
| --- | --- | --- |
| 在哪里截断 | 主模型已提出完整调用组，任何一个调用都还没执行。可看任务原文、当时可见的工具约定、此前公开历史，以及本组工具名和参数。 | 在前视图上增加本组已能和调用对应的公开回执。通常在本组回执收齐时截断。如果下一次主模型决策或回合终止先发生，就用那一刻之前已到的回执，并列出缺项。 |
| 核对什么 | 逐调用核对主体和权限、服务的任务要求、参数与前提、与同组动作的时序或冲突。查询要说清拟消除什么不确定性，探索要说清当时为何值得尝试。 | 逐机区分动作效果、任务要求的变化与新获得的信息。查询成功可以确认某个状态。查询本身不计为造成该状态的动作。 |
| 两边共用的证据边界 | 只使用主 Agent 当时有权看到且已收到的事实。可以引用先前的失败，但须核对飞机、目标、航段、场景条件和时间是否仍适用。 | 保留原始事实，剥离程序直接给出的恢复建议、验证结论及教师私有推理。未来事件、隐藏地图、故障注入标志和整题评分均留在审计侧。两份判断只给诊断，工具执行权仍归主 Agent。 |

## 判断要求

| 编号 | 可观察的行为 |
| --- | --- |
| F1　选择是否有据 | 对每个拟议调用给出 **有依据／有明确冲突／信息不足**。有依据须指明任务要求或待核实的缺口，以及工具与之如何对应。明确冲突须指出违反哪条当时可见的约束。已证实的约束冲突优先于笼统的任务相关性。风险尚未达到可证实冲突时，指出风险及缺少的前提。多个可行动作可以同时有依据。 |
| F2　回执支持什么 | 对动作效果记录 **已执行／部分执行／明确未执行／未知**，以回执实际覆盖的动作或子目标为准。只读调用单列“取得什么观测、查询被拒或未取得结果”。对所涉任务要求另记 **已证实／有进展仍待完成／未见新进展／证据不足**，并单列新信息或已证实的违反。一条受阻回执可以同时说明“本航段未完成”和“新发现通行限制”。 |
| F3　结论属于谁 | 每项判断均指明飞机或会话、任务条款、支持或反驳的公开事件，以及尚缺的证据。并行结果按调用身份逐项对应，乱序时仍须正确归属。任务明确允许其他飞机代办时，才能将其动作计入相应义务。环境信息则按作用范围共享，即使要求 B 亲自到达，已证实且对 B 同样适用的静态点位障碍也可供 B 规划，但 B 的到达义务仍待完成。整队进度使用对应的公开会话证据。 |
| F4　保留未知与时间顺序 | 超时、仅受理、观测矛盾均须指出哪一部分仍未知。后来查到目标状态，可以更新“现在在哪里”，同时保留早先“是否收到动作成功回执”的原判。归档破损、身份对不上或无法重建截止点，记录为“样本不可用”及原因。一个完整记录里的超时本身是可标的证据。 |
| F5　识别值得进一步验证的机会 | 每个决策另记是否存在会影响当前任务判断、且可引用证据的具体问题，例如调错飞机、忽略动作依赖、把单机受阻推广到全队、在效果未知时准备重复执行。合理探索、正常核实和正确处理未知也要保留。逐例标明同一公开输入和当轮工具约定下，固定版本的现有规则能否正确给出同样诊断，待复核项单列。 |

能从公开回执机械核实的事实，以该回执及其调用身份为依据。对意图、主体义务和反馈范围的解释，由标注者独立给出证据并复核。仅凭一次轨迹无法认定另一种选择更优时，动作优劣留作未评。**业务上的未知、两人意见不同、样本记录损坏**分别统计。

## 第 1 步的验收标准

以下是实施后要提交的证据。双标指两人各自判断同一材料，再对照差异。

| 编号 | 验收办法与通过条件 |
| --- | --- |
| AC1　时间边界与溯源（F1–F4） | 对全部试标决策，前后视图分别能回到原始回合、本轮提案、调用身份和截止事件。先提交并锁定前判，再展示本批回执。抽去下一轮、评分与私有信息后仍能复核所有被引用的事实。验收集中未来信息泄漏、跨机错配、用后续观测改写早先超时均须为 0。发现一例即修订并重验。 |
| AC2　真实对照（F1–F4） | 上表四例逐条复核，分别产出前判和后判。其中四机例给出四个可对应的结果。另用真实重复进度查询复核“信息增量”。同一搜索回合三次查询分别看到 0%、66%、100%，只有读到相应回执才能确认新进度。只调换同一并行组回执的展示顺序，保留事件时间与调用身份，逐机结论应一致。[逐响应索引](../../audit/trajectory-verifier-plan-20261107/query-repeats.json) |
| AC3　双人可重复性（F1–F4） | 以成本对照批的 8 个非故障注入开发回合为试标主体，共 52 个模型回复，其中 45 个含工具的决策逐一登记。选至少 30 个不同决策让两人独立双标，覆盖动作、查询和多机并行。已看过本规格预期答案的对应决策只作校准，另选盲标项。对前判类别、后判执行或查询效果、任务进展三项分别报裁决前一致数／可比数、各类别分歧、未知数与不可用数。每项纳入两人均收到同一可溯源材料且该项适用的决策。业务上的未知照计，一方判未知、另一方判完成记为不一致。无法重建与不适用分别报数。多机决策须各调用都一致才记该项一致。建议首轮通过线为三项各 ≥80%。不足或有系统性主体混淆，则改写相应口径，用未展示答案的开发决策复验。裁决结果与原始两份标注并存。 |
| AC4　真实机会与规则覆盖（F5） | 对上述 45 个有工具决策报告“经复核有具体问题”的决策数／45，另报受影响回合数／8，以及规则覆盖数、规则遗漏数和待定数。52 个回复中的 7 个无工具回复保留在总表。26 个纯查询或感知决策完整覆盖，调用或视图数不能重复充当决策分母。单列受控故障与精选对照，在结论中注明开发场景范围。[原批角色及分母](../../audit/agent-call-role-20261107/summary.json) |
| AC5　决定是否进入采集设计（F1–F5） | 提交一页试标结论，列出可交给规则的事项、仍需语义判断的事项、现有证据判不了的事项。拟进入 300 条采集预算的学习问题，需能在至少两个不同父场景举出可复核的规则遗漏。若只在一处出现，或双标仍不稳定，先缩小任务或补开发证据。得出“暂不扩量”也可完成本步验收，不能当作采集或训练已启动。 |
