# B1 导航与动作结果契约修复

日期：2026-10-06（北京时间）。本版本修复工具执行中的确定性错误，作为成功优先执行框架的第一步。版本目标是正确识别执行结果、完整检查到达位置、恢复明确的障碍阻挡。调用数减少不是验收条件。

版本标识：`b1-navigation-contract-v1`。开发分支：`codex/b1-navigation-contract`。修改前的 Git 代码参照为 `1794e45e421fb5de03094f0b63f9ca95f86ab42f`。

本提交仅包含 B1 代码、测试和本说明。开始工作时已有的依赖、README、controller、view3d 及其他未提交工作保留在工作区，不纳入本版本。此 Git 参照和标签不代表已把本地整个实验环境或所有历史证据归档进 Git。

## 修改内容

| 问题 | B1 行为 |
|---|---|
| 服务器返回 `status`，导航读取 `success` | 客户端为动作响应增加统一 `outcome`，同时保留原有状态、消息和路径进度字段；兼容旧布尔回执 |
| 平面位置到达便直接成功 | 使用 XYZ 欧氏距离判断到达，包括初始检查、直接移动后和绕障后；省略 z 时保持观测到的当前高度 |
| 障碍错误无法正确进入恢复分支 | 只有明确的空间阻挡触发一次感知、路径规划和一次 `allow_partial_move=false` 的路径执行 |
| 电量、参数和无人机状态错误也可能尝试绕障 | 返回对应错误与原始依据，交给下一步决策；不自动重发动作 |
| 部分完成和未知结果可能被误读 | `partial`、`unknown` 均不判导航完成，不自动重放路径；保留已完成及未完成航点 |
| prompt 声称工具会多轮重规划 | 明确实际的单次 fallback 行为以及 XYZ 到达条件 |

输入中的非有限坐标、非正或非有限到达容差和安全缓冲会被拒绝；缺失或无效的观测高度不再自动替换成 0。

## 结果语义

[`command_results.py`](../../../agent4drone/command_results.py) 提供 `command_outcome` 与 `normalize_command_result`。规范化仅用于 API 客户端的 `/command/` 响应，新增字段采用以下含义：

| outcome | 含义 |
|---|---|
| `completed` | 回执支持该命令完整执行 |
| `partial` | 回执明确支持部分执行，仍有工作未完成 |
| `blocked` | 命令被明确的路径或障碍因素阻挡 |
| `error` | 其他命令失败 |
| `unknown` | 响应缺失、不支持或证据互相矛盾 |

`blocked` 表示本次动作的阻挡原因，不证明整个任务不可达。当前 Server 主要通过消息描述原因，分类器使用受限的空间阻挡匹配规则；将来 Server 消息协议变化时，应同步更新契约测试。电量、输入和状态失败不会因为包含 blocked 字样就进入绕障。

HTTP 记录中的 `success` 继续表示传输成功。例如 HTTP 200 携带 `status=error` 时，记录可以是 `success=true`，同时响应 `outcome=error`。传输、命令、导航和任务完成是不同层次。

导航结果增加 `arrival_verified`，表示观测位置是否在要求的三维容差内；`distance_remaining` 由原来的平面距离变为三维距离。导航 `success` 要求命令完成且观测到达；若开始时已经在目标三维容差内，则无需移动即可返回成功。

若命令回执成功但观测位置未到，导航层返回 `outcome=error`，`last_move_result` 仍保留原命令的成功回执。即使部分完成回执对应的观测点已接近终点，也不会把整段路径升级为完整完成。默认摘要保留失败原因和路径进度，绕障结果也保留直接移动的回执。

## 版本边界

B1 保留现有二维路径规划算法、当前黑板结构以及单次绕障上限。没有新增实体绑定、任务条件账本、自动局部修复、多轮探索、Worker 取消机制或模型调用预算策略。`[TASK DONE]` 的任务终止机制也尚未修改。

Server、隐藏检查、benchmark、场景顺序、实验 runner 和冻结的首轮结果均不属于此次修改。新版本需要独立记录为 B1，不覆盖 B0 结果。本轮仅验证代码正确性，没有启动模型批次，也没有新的任务成功率数据。

## 验证结果

在仓库的 agent 环境运行全部测试：

```bash
cd agent4drone
MPLBACKEND=Agg .venv/bin/python -m pytest tests -q
```

结果：**250 passed，3 warnings**。警告分别来自现有 Starlette 弃用提示和两个绘图测试在 Agg 后端下不显示窗口。Agg 设置使全量测试无需交互关闭绘图窗口。

新增契约测试使用实际服务器的 `status` 格式，覆盖直接成功、错误高度、空间受阻、非空间错误、部分路径、矛盾回执、无效坐标与参数及摘要中的失败依据。

其中 5 项集成测试通过 FastAPI TestClient、真实 Server 控制器和 `UAVAPIClient` 执行：正常到达、同 XY 升降、真实圆障碍后一次绕行、电量不足、无人机状态错误。测试不启动网络监听或模型请求；每个案例在临时目录和短生命周期子进程内隔离。若 agent 环境缺少 Server 所需 pygame，测试使用已安装的 server 虚拟环境提供该依赖；两处都没有时会明确跳过。本次 5 项均实际通过，没有跳过。

已有离线导航探针的修复前后行为：

| 探针 | B0 | B1 |
|---|---|---|
| `status=success` 且位置已到 | 导航失败，剩余距离 0 | 导航成功 |
| `status=error` 且路径受阻 | 仅直接移动，未进入恢复 | 进入感知和一次路径 fallback |
| 同 XY，从 z=10 请求 z=20 | 无移动即成功 | 执行移动，观测 z=20 后成功 |

旧探针的 fallback 假客户端只返回成功而不移动，B1 会正确地继续报告未到达；真实 Server 集成测试另行验证了能够成功绕行的情形。原探针、分析脚本和历史 JSON 证据均未改写。
