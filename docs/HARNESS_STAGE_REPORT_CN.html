01 / RESEARCH POSITION从任务工作流，推进到可检查的执行与接管边界

本项目继承 MultiUAV-Plat 的仿真、AGENT 接口、任务与隐藏检查器，并在 Agent4Drone 的集中式主 Agent 上扩展 Harness。这里的 Harness 指包围模型决策的运行机制：组织公开上下文、管理已提交的计划、执行与监视有界技能、处理失效和接管，并保存完整交互证据。几何导航、覆盖规划和平台可视化有上游基础，不能计为本阶段从零实现的贡献。[1][2]

原论文已经具有观察、记忆、规划、执行、验证和重规划，因此研究重点应落在这些职责如何被落实为可执行、可检查、可消融的契约。例如，一次移动失败可能只要求替换技能内的候选点；一次动作响应丢失则可能意味着效果未知，不能直接重放。二者都表现为“异常”，但对是否需要新一轮 LLM 决策的要求不同。

当前最有依据的贡献候选

在既定技能仍适用时，由程序继续有界执行；在依赖失效、效果不明或修复耗尽时，携带实际证据和执行游标交回模型。研究正确性、模型往返与动作成本之间的关系。

完整架构的延伸目标

将任务义务、执行证据和交接内容统一起来，使后续约 2B 学生能够学习技能选择、退出和接管。此目标尚无本项目 Teacher 数据集、SFT 或 RL 成果。

本报告采用集中式组织：一个主 LLM 控制多个 UAV；辅助 worker 或多个无人机实体不等于分布式多 Agent 协商。这里给出候选方法组织，尚未确立文献新颖性或最终论文主张。

02 / BASELINEAgent4Drone 原架构：六项概念职责与反馈闭环

对比依据为 Zhang 等的 MultiUAV-Plat: An LLM-Oriented Platform, Benchmark and Framework for Multi-UAV Collaborative Task Planning，arXiv:2606.31073v1，§3.3、Fig. 4（PDF 第 8 页，后续说明见第 9 页）。本报告将 Agent4Drone 作为本研究 baseline；原论文内部另以 ReAct 作为对照，两层含义需要区分。[论文]

论文以任务、合法观测和记忆产生下一项高层子任务与有界工具链，再用执行反馈更新状态。Memory 与 Decision Artifacts 支持后续决策；Verification 比较预期和实际变化，并决定完成、重试或重规划。六个模块描述的是概念职责，并非六个独立 LLM Agent。[1]

论文概念与当前源码分开看。论文描述平台验证反馈；当前主 Agent 注册工具中未发现对应的整任务检查工具接线。能够直接确认的是执行后独立 Checker，以及局部状态、动作反馈和特定公开进度读取。不能据此推断论文历史实验的实际接线，也不能将隐藏检查树作为策略输入。当前黑板主要保存感知实体与注释，完整任务语义并非现成的通用状态机。[阅读与代码核对]

03 / COMPLETE ARCHITECTURE方法总体架构：四层组织、一条执行证据闭环

整体组织为任务与证据层、模型决策层、有界执行层、回合与评估层。模型负责需要语义判断的选择和重规划；Harness 承担已有技能的确定性执行契约；仿真环境产生真实效果；独立评分给出最终任务判定。完整设计扩展现有组件的语义和接口，近期不引入分布式协商或通用重型协调器。

3.1　任务与证据层：把“要求什么”与“发生了什么”对应起来

任务义务表示。目标设计将原始指令转换为带来源片段的义务集合：执行主体、对象、动作、空间约束、先后关系和最终状态；无法解析的条款保留为未支持或待澄清。现有实现只支持有限语法，例如完整简单动作链、特定搜索指令和部分路线表达，不能宣称已实现任意自然语言的义务图。

公开证据账本。来自状态查询、局部感知和实际动作回执的事件进入任务/场景范围内的记录，保留 actor、来源、时间或序列及效果。动作意图、接受回执、已确认效果和任务满足分层表示；名字线索不自动等于已定位的目标 ID，沿途发现不自动等于端点坐标，公开聚合进度也不证明其他任务条款。TaskEvidence、TaskProgress 和 ExecutionMemory 已提供有界基础；统一跨任务语义仍为目标。

决策上下文投影。向模型呈现当前可见事实、已完成步骤、剩余步骤、未知项和相关失败；压缩不改变事实或作用范围。execution_memory_v7 仅对完整支持的路线语法使用精简投影，其余回退 v5。它与搜索技能的 observed_target_v7 是不同组件，当前自然候选未同时开启二者。[3][4]

3.2　模型决策层：选择执行方式，并显式提交一个有界计划

主 LLM 读取原始任务、公开上下文和工具定义，决定选择技能、恢复仍有效的计划、取消计划，或调用原工具处理不支持的任务与剩余工作。当前 run_harness 接受 start / resume / cancel；模型提交的是技能选择，具体 DecisionFrame 由技能工厂编译，不是模型自由生成任意计划图。

DecisionFrame 将计划身份、来源义务、执行主体、游标、证据引用、继续条件、失效因素、局部修复范围、停止条件和预算放在同一个可审计对象中。现有 source_obligations 主要引用整段命令；continue_guards 等字段记录契约，具体检查分布在 runtime 和技能逻辑中，尚非通用声明式规则解释器。[状态与运行时][技能工厂]

3.3　有界执行层：把继续、观察、失效和退出落实为机制

运行时只在既定任务/场景作用域内推进游标，检查截止、API 与修复预算，并在检查点决定继续或交回。applicability 调度在技能仍适用时继续；failure 则在失败检查点暂停，由模型决定后续。两者可复用相同技能和强制失效守卫，形成有意义的调度消融。

当前完整技能只有 simple_chain 和 public_search 两类，且要求整条原始命令匹配。搜索内部已有飞行状态修复、受阻目的点记忆、精确 XYZ 目的点冲突的跨机共享、已观察固定目标的一次跟进和退出前公开进度确认。共享限制在同计划、场景与 epoch，并依赖静态障碍契约；路径受阻不能泛化为任意起点都不可达。目标跟进交给首次发现者，尚未实现动态责任重分配。

原工具路径始终可用。相关外部动作使挂起计划的依赖失效，防止恢复旧游标时隐含假设已被改变。恢复仅在同进程内有效；取消不会撤销已经发生的动作；技能 completed 只表示自身公开停止条件成立，不能作为整任务完成标签。[3][7]

3.4　回合与评估层：保证结果可归因，并准备后训练接口

当前本地运行器采用“每回合新 worker → 实际请求/工具归档 → 截止与排空 → worker 退出 → 独立 scorer”。单 Agent 的 execute/reset 等入口互斥，异常结束显式关闭或禁止复用。World 的 snapshot/restore 不能直接等同于同进程可反复训练 reset，因此首轮采数可以复用新进程整回合路径。

归档连接逻辑请求、实际 HTTP 尝试、模型消息和 tool ID，保留实际请求/响应及完整性标签。独立评分可使用隐藏检查和私有最终状态，策略输入只保留公开信息。后续样本转换器可使用隔离评分做质量标签，但不能把隐藏规则或真值写进示范输入；确定性技能内部动作也不能自动标成 Teacher 的 assistant 输出。轨迹转换、过滤与 label/mask 仍待实现。[8][9][10]

04 / EXECUTION CONTRACT一个回合如何运行，以及何时交回模型

  1. 建立回合。加载冻结初态、任务、公开权限和预算，创建新 worker 与独立记录。隐藏检查留在隔离评估侧。
  2. 读取公开事实。将指令、状态、局部感知和历史回执组织成模型上下文。未知仍标未知；未支持的任务条款不被丢弃。
  3. 模型选择。对支持的完整命令显式 start；否则用原工具。技能工厂形成 DecisionFrame，绑定任务、场景和初始游标。
  4. 程序执行。调用公共 API，记录实际回执，按技能检查状态与进度。满足继续条件或既定局部修复条件时推进，避免把每个低层动作都变成一次新模型决策。
  5. 失效或交接。效果不明、依赖改变、不可处理失败或预算耗尽时，返回状态、原因和证据。只有仍可恢复的 ready/paused 计划允许 resume；needs_replan、completed、cancelled 等终止计划不可重新启动来重放已发生动作。
  6. 完成与评价。模型根据公开证据处理剩余条款。停止后排空并封存，再独立评价整任务。当前统一剩余义务报告尚未完整实现，必须将其与已有技能终止返回区分。
动作失败 ≠ 计划必然失效；技能完成 ≠ 整任务完成。

接管示例：起飞效果不明，剩余任务不能简单重放

假设指令要求某 UAV 起飞、转向并悬停，起飞请求发出后响应丢失。系统应把效果记为未知；必要的公开状态读取帮助判断当前状态，随后交回模型处理剩余动作。它既不能把“请求已发出”当作已完成，也不能未经核对再次起飞。历史机制实验中的实际已起飞与未起飞两类回执异常均有对应轨迹；这些是受控故障案例，不能改写为自然任务中的普遍成功率。[5]

08 / REPORT-READY TEXT可直接纳入阶段报告的架构说明

本阶段在 MultiUAV-Plat 平台与 Agent4Drone 工作流基础上，研究面向多无人机协作任务的 Agent Harness。整体采用集中式主 Agent：LLM 根据自然语言任务与合法观测进行任务理解、无人机分配、技能选择与重规划，Harness 管理已提交计划的执行、证据更新、失效检测与控制权交接。完整架构由任务与证据层、模型决策层、有界执行层及回合与评估层组成，并预留面向小模型后训练的轨迹接口。

相对于原论文已有的观察、记忆、规划、执行和验证闭环，本研究的重点是将执行与接管边界具体化。模型选择受支持的技能后，系统构建包含计划标识、执行游标、主体绑定、证据引用、适用条件、修复范围和预算的 DecisionFrame；运行时根据实际回执和公开状态继续执行或实施既定局部修复，在效果不明、依赖失效或预算耗尽时交回模型。原工具保留为未支持任务和剩余任务的处理路径，相关外部动作会使旧计划失效，从而限制过期恢复与动作重放。

当前已实现有限技能的执行状态机、任务证据与可选执行记忆、局部搜索修复和跨机冲突证据共享，以及回合隔离、模型 I/O 归档和独立评分。受控真模型实验表明，在初始技能已正确提交的条件下，部分可恢复事件能够减少模型交互；其中 8 对动作内容一致的起飞失败案例，双方均成功，模型调用从 41 次降至 23 次。该结论限于机制验证，尚不能推广为完整自然任务成功率提升；既有自然校准未产生可恢复暂停机会，搜索与记忆改进也保留局部无增益和退化结果。

完整设计中的通用任务义务建模、统一交接与完成报告、自然接管评测及版本化训练样本构建仍待补齐。后续将围绕一个明确协作失败族组织同权限、同初态与同预算的机制消融，并同步准备公开轨迹到训练样本的转换与独立数据划分，为约 2B 学生模型的 SFT 和回接评估建立基础。
