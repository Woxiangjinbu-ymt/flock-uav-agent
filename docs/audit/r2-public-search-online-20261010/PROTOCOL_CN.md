# R2 公开反馈搜索：同期在线配对规则

日期：2026-10-10。延续[晚期触发开发审计](../r2-public-search-trigger-20261009/REPORT_CN.md)。本次仍使用开发过触发门槛的 fast100 场景，因此结果只作探索性机制与回归检验，不作独立泛化估计。

## 封存方案

- 原 R2 对照源码固定在 Git 提交 `69dd34c067ec97b746db5180684594c546a35172`，进度模式为 `evidence_r2`。
- 处理臂从同一提交生成，只增加 `evidence_r2_search` 显式模式、公开进度回执后的晚期触发器和确定性公开反馈搜索；原工具表和检查器沿用 R2。搜索模式默认关闭。
- 两臂使用同一个官方 DeepSeek `deepseek-flash` 配置、原 500 秒整题窗口、原 API 与检查器、场景内原任务顺序、每场景独立服务端、零自动重试。
- 场景 `3973d0d6` 取原顺序前 20 题，`823c15d5` 前 19 题，`35ce64d8` 前 13 题。每臂共 52 题、220 个检查点；覆盖六道匹配题的三个原场景前缀。
- 触发只依赖题面、公开 `get_mission_progress` 回执和任务已用墙钟：题面含 `all targets` 与 `session task progress exceeds 95%`、当前公开进度 `<=95%`、已用 `>=400` 秒且至少余 30 秒。每题最多触发一次。

冻结文件和哈希在 [`study.json`](../../../experiments/m1r2-public-search-prefix-v2/frozen/study.json)。`prepare` 与 `preflight` 均未调用模型。初次 `v1` 尝试因沙箱拒绝本机端口，在 0/52 题评分前中止；`v2` 使用相同研究方案重新封存、预检和首次运行。`v1` 不计入成对成绩。

## 预定读取

主报两臂 52 题整题通过数、220 个检查点通过数、超时数、总墙钟和 token；逐题对照六道同题型任务的通过/失败、公开进度、处理臂实际触发时刻、搜索 API 调用与终止回执。三道原成功题单列回归；三道原失败题单列新增通过。若没有触发，须区分已达阈值、无晚期公开查询与其他原因。服务端原检查结果仅在整题结束后读取。

这不是六道任务的随机抽样，也没有盲定门槛。场景顺序与任务检查未变，但两臂是两次独立在线执行，模型随机性与服务商时变状态仍可能影响逐题差异。
