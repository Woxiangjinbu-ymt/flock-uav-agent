# 公开反馈协调搜索：限时短技能本地试验协议

日期：2026-10-09。承接[闭环离线审计](../r2-closed-loop-search-20261009/REPORT_CN.md)。本轮先实现一个可关闭、无模型调用的研究原型，并从三道 R2 总进度题各自保存的原题前状态独立启动隔离服务端。三题已用于策略开发，本轮只测执行可行性和墙钟，不作独立泛化验证或在线 agent 成绩。

## 固定策略

- 规划器只接收首次公开机群列表、同场景原 R2 已公开的感知黑板障碍，以及本轮实际公开 API 的 `move_to`、无人机状态、`nearby` 和会话总进度回执。原题前完整快照只供隔离服务端恢复；任务检查器仅在试验结束后读取。
- 沿用 70 米端点格点、25 米覆盖评分格点、50 米感知半径、机群外接矩形扩 200 米、已知障碍 1 米缓冲、`新增覆盖格点数/(1+距离/250 米)` 的选择分数。每机每轮最多尝试一次，最多 16 轮。受阻边不重复；新感知障碍在下一步对机队共享。单机碰撞错误只有包含明确障碍信息时才归一为 `blocked`；其他错误不盲重试。
- 每道题计时从首次公开 API 查询前开始，包含公开列表、进度查询、策略计算、起飞、移动、状态读取、附近感知和每 10 次尝试后的进度查询。只要公开进度**严格超过 95%**就停止；达到 500 秒也停止。不调用隐藏检查来控制动作。达到候选端点或动作上限时停止，不增加预算。
- 主试验只用原生公开 API `list_drones`、`task-progress`、`take_off`、`move_to`、`get_drone_status`、`nearby`。单个技能被原 agent 启用时才运行；本轮不接入 R2 的 LLM 循环。完整输入与逐次输出另存，避免把旧离线计划当作新运行的决策源。

## 验收及边界

先用 FastAPI `TestClient` 运行真实服务端处理器，逐题记录墙钟、API 与策略计算耗时、动作数、受阻数、进度查询数、停止原因、电量与原检查。随后尝试同机 `127.0.0.1` HTTP 服务，单独记录进程与请求开销；若本机端口权限阻断，保留 TestClient 结果并明确限制。任何服务端失败、进度倒退、端点来源不明或策略偷偷读取完整场景都阻断结论。

代码功能可用且三题都能在 500 秒内达到公开严格阈值，只说明这批开发案例的**本地短技能可行性**。是否能提升原 agent 成功率，需要后来在原场景任务序列中，固定同模型、同工具权限、500 秒窗口和关闭开关，比较同期 R2 与 R2＋技能；不能把本轮三题独立快照的检查通过直接写成论文主表成绩。
