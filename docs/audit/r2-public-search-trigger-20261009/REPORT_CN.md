## 在真实晚期状态分叉

对三道触发题，[分叉脚本](../../../experiments/analysis/pilot_public_search_trigger_branch.py)先逐条回放原 R2 截至触发回执的 **910、1,222、666 次公开 API 调用**，分别包含 **237、262、177 次命令**。核对了全部命令状态与去电量数字后的结果文本，以及 492 次附近实体、1,463 次公开无人机位置读取；三题触发时公开进度均与原回执吻合，且没有跨过分叉边界的并发调用。电量文本有 **46、68、32** 处数值差异，故不能声称逐字节重建了原电池状态；技能接续后的最低电量仍分别为 64.71%、72.10%、73.45%。R2 封存源码中的电量、无人机、障碍、目标及 API 文件与当前源码逐字节一致，差异仍需在正式在线试验中关注。

随后从该公开状态运行同一个确定性搜索器，每 10 次尝试读取进度，达到题面 `>95%` 就停。计时只从技能开始的第一次公开 API 查询算起，原前缀回放不计入剩余窗口。原任务检查器只在技能停止后调用。[进程内完整账本](branches.json)与[独立 Uvicorn 本机 HTTP 完整账本](branches-http.json)的尝试数、动作结果及终点相同。

## 对论文主线与下一步的限定

本轮补强了“原 R2 在接近截止时仍缺目标总进度 → 公开进度回执触发有界协调搜索 → 真实障碍与移动反馈驱动重选点 → 在原剩余窗口内读到严格阈值”的连续机制链。它也解释了为何不能在题目开始时无条件接管：同题型原成功题 `b1ad4f3e` 从 85% 自行升到 100%，此前的朴素题面触发会误碰它。

这六题都在同一开发集；三个失败分叉又从各自历史题前快照独立回放。触发规则是在看过结果后选的，不能据此报告泛化误触发率、整题 W/L 增益或统计显著性。技能未接入原 LLM 调度；模型接管与返回的时间、并发行为和后续场景承接未测。原模拟服务直接更新飞行状态，本机秒数不是物理飞行时间。

**下一门槛**是把默认关闭的触发器接进原 agent 的公开进度调用边界，并在同模型、同工具权限、同 500 秒窗口、原场景顺序下做同期 R2 与 R2＋技能配对。先覆盖这六道同题型任务所在的完整场景序列，主报整题通过数、成功题回归、实际触发时刻、总墙钟和 token；若小规模配对没有回归，再扩到 fast100。R3 航线监视、额外 LLM 工人和更宽时间预算不得混入这一处理臂。

**后续进展（2026-10-10）：**上述原场景序列在线配对已完成，见[52 题、220 检查点的报告](../r2-public-search-online-20261010/REPORT_CN.md)。三道旧失败题在处理臂通过，但只出现一次直接搜索触发，后两题继承同场景进度；整题净增六题仍受非候选题运行波动影响，不作为独立泛化结论。
