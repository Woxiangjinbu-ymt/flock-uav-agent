# Harness 方法定义：带守卫执行、效果确定性与范围化失败证据

日期：2026-11-03。本文以当前维护代码定义方法对象、可检验主张及已有证据，不新增模型调用、采数或训练。系统范围见[通用 Agent 规格](GENERAL_AGENT_SCOPE_CN.md)，运行契约见[统一执行契约](AGENT_EXECUTION_CONTRACT_CN.md)，研究定位见[项目贡献](PROJECT_GUIDE_CN.md)，同能力对照和评分规则见[公平验证协议](HARNESS_VALIDATION_PROTOCOL_CN.md)。

**当前交付是集中式多 UAV Agent 中的有界执行机制与公开状态契约。** 它把已提交的预定义子程序包装为可中断计划，在既定守卫与预算内执行，并提供原工具接续所需的公开反馈。`applicability` 的当前控制语义属于带守卫子程序持续执行；本文不将它描述为新的学习调度算法，也不以代码规模、测试数量或减少模型调用本身认定学术新颖性。

## 1. 系统对象、职责与权限

一个主 LLM Agent 理解任务、选择 UAV、调用原工具，或显式调用 `run_harness(start/resume/cancel)`。辅助 worker、多个 UAV 及同名并行工具调用不等于每机独立 LLM 协商。原工具始终保留；子程序不支持某条命令，不表示整个 Agent 拒绝该任务。

| 主体 | 当前职责 | 权限与限制 |
| --- | --- | --- |
| 主模型 | 自然语言理解、工具/子程序选择、收到反馈后的重新决策与原工具接续 | 只读原指令、公开观测/回执及派生提示；不能读取隐藏 checker、私有快照或评估端世界真值 |
| Harness runtime | 管理 plan、游标、预算、互斥、检查点、失效与停止；调用固定公开接口 | 不调用模型；不从隐藏评分判断任务完成；不自动发明新子目标或通用修复程序 |
| 子程序 | 按完整命令匹配得到固定流程，在局部规则范围内处理执行反馈 | 内部动作是程序决策，不是 Teacher/学生的模型输出；不得静默丢弃额外任务条款 |
| 公开执行状态投影 | 从 ledger/frame 生成效果分类、来源、未决问题和恢复建议 | 纯函数，不调用工具、不自动重试、不执行 resume、不独立证明完成 |
| 独立评价器 | 回合退出并排空后检验整题与行为义务 | 评估结果与策略输入隔离；运行返回、公开自验证、整题评分分别记录 |

接线依据为 [harness_integration.py](../agent4drone/harness_integration.py) 的 `install_harness` / `HarnessMiddleware`。子程序接口白名单为 `list_drones`、`get_drone_status`、`take_off`、`change_altitude`、`rotate`、`hover`、`move_to`、`get_nearby_entities`，另将公开 session 信息转换为 `get_mission_progress`。它不是主 Agent 全部原工具的白名单。

11-03 的限定在线入口 [`deepseek_contract_pilot.py`](../scripts/deepseek_contract_pilot.py) 通过 [runner](../scripts/harness_natural_runner.py) 的显式 `online_contract=task_execution_state_v1` 接入上述契约。它已完成[真实 8 槽验证](results/deepseek-contract-pilot-20261103/REPORT_CN.md)，仍是固定小批入口，不等于通用采数 driver 或 Teacher 生产流程已完成。

`run_harness` 必须独占所在模型工具批次；并发子程序控制被拒绝，原工具尚在运行时控制请求被延后。这里的互斥防止重叠控制，不意味着任意外部服务或真实无人机已经获得全面并发安全保证。

## 2. 执行状态与效果确定性

### 2.1 计划状态与公开任务投影是两个层次

`DecisionFrame` 是执行对象，见 [harness_core.py](../agent4drone/harness_core.py)。本文记为：

`P = (身份, 原始义务, actor绑定, 步骤/游标, 子程序状态, 证据引用, 守卫说明, 预算, 状态/原因)`。

身份包含 `task_id/plan_id/scene_id/scene_epoch`；原始义务保存完整 source span 和命令；证据引用关联实际工具调用。`continue_guards`、`invalidators` 等字符串字段是可审计的说明，**不是一个运行时自动解释任意谓词的通用规则引擎**。实际守卫分布在 runtime 和具体 generator 内。恢复依赖当前进程保留的 generator 及 frame，尚不支持从日志跨进程重建任意运行计划。

`task-execution-state-v1` 则是 [task_execution_state.py](../agent4drone/task_execution_state.py) 的 `build_task_execution_state` 对公开 ledger/frame/lifecycle 的只读投影。它保留原指令、有限解析要求、动作/工具记录、计划状态和未决问题；未解析要求继续由原指令约束，不能被有限清单替代。提示中的 `concise_recovery_projection` 默认最多选择 4 条建议，优先当前候选和较新的记录，并记录省略数；完整公开记录与原工具回执仍保留。

### 2.2 请求、回执与效果不混同

每条公开记录至少区分：`requested`、`effect_status`、`effect_reason`、原始 `receipt`、`applied/remaining`、actor/调用/计划来源及顺序。`applied/remaining` 只复制明示的回执字段；缺失为 null，不用请求参数补全，也不把后来的位置查询改写成过去动作已成功。

底层 [command_results.py](../agent4drone/command_results.py) 将命令回执归类为 `completed/partial/blocked/error/unknown`；任务状态投影将其映射为 `success/partial/failure/unknown`，同时保留原因。HTTP 成功不是动作成功；`blocked` 只用于明确几何错误，电量、状态、参数错误不能自动进入障碍恢复。

| 效果分类 | 依据与含义 | 不允许推出的结论 |
| --- | --- | --- |
| success | 公开回执符合相应成功合同；子程序还可能读取状态核验位置/航向等 | 不等于所有原始任务条款完成，也不保证隐藏世界中任意未检查条件成立 |
| failure | 明确执行失败或工具参数验证失败；保留具体类型 | 失败不普遍等于零副作用；不能把所有失败都作为可共享几何信息 |
| partial | 回执明确部分成功，保留已明示的完成量和剩余量 | 不等于目标到达；未知剩余量不能由请求量相减臆造 |
| unknown | 在途、传输/执行异常、缺失或矛盾回执、错误 actor 等 | 异常不能证明动作未发生；后续观测只提供当前状态，不补写历史执行事实 |

顺序不确定或有重叠的调用不按列表位置串成因果链。后续同请求成功或公开 actor 状态读取可以成为 follow-up 引用，旧记录的效果状态不被追溯改成成功。`mission_completion` 固定为 `not_evaluated`；当前建议数量也不是历史恢复机会数或恢复成功率。

## 3. 守卫、继续、退出和恢复

### 3.1 控制与生命周期

`start` 只接受受支持的完整命令，为该 task 分配 plan 并立即进入执行。每条命令的同一技能最多提交一个实例；重复 start 被拒绝，不能通过重新 start 重放已执行前缀。

| 状态/事件 | 当前控制语义 |
| --- | --- |
| ready / paused | 可请求同一 `plan_id` 的 resume；执行时重新经过共同守卫，不把“可请求”当作依赖已独立复核 |
| running | 正在驱动 generator；不允许另一个重叠控制同时驱动它 |
| completed | 子程序公开停止条件成立；不能 resume，整题义务仍需另行核查 |
| needs_replan | 依赖失效、不能处理的效果/失败或局部预算等导致子程序退出；原计划不可 resume，模型可以依据反馈组织原工具接续 |
| cancelled | 显式 cancel 关闭 generator 并标记取消；不撤销已有动作 |
| interrupted / abandoned | 截止、取消、回合收尾等造成停止；不再把它当作当前可执行恢复机会 |

非可恢复计划的 resume 返回拒绝信息，同时保留原 plan 状态、原因和游标；控制返回 `status=rejected` 与原计划终态是两个字段。当前 cancel 对已有 plan 设置取消状态，不能据此反推它之前没有完成或执行动作。

共同 runtime 守卫检查任务/计划归属、scene/epoch、全局取消/关闭/截止、API 预算及并发状态。相关原工具动作在 ready/paused 阶段使计划失效：搜索计划受经同一 middleware 记录的任意外部动作影响；短链计划检查 actor 交集，并在 actor 信息不足时保守失效。其他客户端或控制台的修改不一定经过该钩子。具体 generator 另外检查 actor 绑定、公开状态变化、实际效果与局部修复范围。

当前 runtime 默认截止为开始后 500 秒，plan 默认 API 预算 2000、修复预算 16，搜索轮数使用固定 `MAX_ROUNDS`；实际实验必须以冻结 profile/manifest 和更外层的时限为准。API 上限在下一次调用前检查；修复计数在观察失败后累加，因此第 17 次已确认失败可以成为触发退出的事件，不能把预算 16 写成“最多发生 16 次失败”。时限检查发生在公开调用之间；在途调用的取消、排空及能否评分由完整回合运行链另行管理。

新版限定在线入口已在真实回合验证“预算结束”和“停整批”的区别：搜索 B 用满 12 次 HTTP，搜索 I 在完整响应后超过 200,000 token 阈值；两者归档 partial，但已排空且实际 usage 全部结算，仍能独立评分并继续既定后续槽。这里的 partial 是交互归档不完整，与动作回执 `partial_success` 是两个概念；见[真实运行报告](results/deepseek-contract-pilot-20261103/REPORT_CN.md)。

### 3.2 两条路径的约束强度不同

子程序 `_checked_action` 遇到 unknown 时，读取一次对应 actor 的公开状态，记录它后以 `unknown_action_effect_observed_do_not_replay` 退出；它不会自动重放该动作。短链的不成功动作退出；搜索仅在预先定义的局部处理范围内继续。

原工具路径收到的“先查询当前状态”“只处理剩余工作”等是**给模型的建议**。当前 middleware 没有通用的跨路径副作用去重器，也没有保证模型绝不重复 raw 动作的策略验证器。因此：子程序的无自动重放规则可以直接检查；原工具接续是否避免重放、是否完成剩余义务，必须另行审计真实行为。不能将本地脚本遵守建议的案例写成全系统安全保证。

## 4. 调度规则及 guarded macro 等价性

检查点是 generator 产出的 `Checkpoint`：短链中是已核验的动作单元，搜索中是一次搜索尝试及其配套状态/感知/进度处理。它不是每一个底层 API，也不保证恰好对应一个物理动作；取消和截止检查粒度可以比检查点更细。

在所有 scheduler 共用相同 generator、公开回执、检查点与失效守卫的条件下，[`HarnessRuntime._drive`](../agent4drone/harness_core.py) 的主动暂停规则为：

| scheduler | 对一个已经产出的检查点是否暂停 |
| --- | --- |
| every_step | 每个检查点暂停 |
| fixed | 本次 drive 内检查点数达到 `fixed_k` 时暂停；resume 后重新计该次 slice |
| failure | 仅 `Checkpoint.failed=True` 时暂停 |
| applicability | 不因检查点本身暂停；继续驱动，直到完成、共同守卫/子程序退出或全局停止 |

`failure` 可在局部程序已经处理过的失败之后交回模型，例如搜索已禁用起飞失败的 actor；它不表示程序尚未采取任何局部处理。`applicability` 检查点日志中的 `valid_or_locally_repairable` 是此执行流程的状态标签，不是额外模型/分类器计算出的适用性概率。

**条件等价命题。** 对一个使用相同 generator、相同 guard/局部处理、相同公开调用合同的普通 guarded macro，若它也在有效时持续执行、失效时退出，则它与当前 `applicability` 的“是否因检查点交回、下一公开调用、游标更新、完成/退出原因”语义等价。条件还包括相同初始 frame、给定相同回执序列及一致的时限/取消/外部修改事件；日志名称和实现组织不属于待比较的控制行为。

理由是逐次 generator 步进：遇到公开调用，两者执行同一个请求并接收相同反馈；遇到检查点，两者均继续；遇到相同停止或失效条件，两者均结束当前计划。这里给出的是受上述条件约束的控制规则推导，不是关于任意行为树、任意宏动作或真实墙钟轨迹相同的通用证明。不同模型等待时间可能改变后续环境、能耗及故障暴露，不能从控制规则直接推出全回合成本相同。

因此，普通带守卫子程序持续执行应作为强工程基线。若其规则与候选逐项相同，应直接报告等价，不把两份同义实现当作两个独立算法重复计数。`every_step/fixed/failure` 对照可以隔离额外交回的代价，却不足以单独证明新颖性。无需为了获得算法名称而强加学习门控；若未来引入新的判定规则，须另版本给出相对等价基线的明确增量。

## 5. 两类预定义子程序的边界

定义见 [harness_skills.py](../agent4drone/harness_skills.py) 的 `simple_plan`、`search_supported`、`simple_chain`、`public_search` 和 `make_skill_factory`。

| 子程序 | 当前入口和执行 | 停止与局部处理边界 |
| --- | --- | --- |
| simple_chain | 三种完整英文模板：指定单机起飞后转向并悬停、起飞后升高并悬停、起飞并原地悬停。完整正则匹配；检查数值及唯一 actor 绑定 | 按顺序执行、回读公开位置/航向/状态后推进游标；起飞前要求地面初态。没有通用局部修复器；不成功动作退出。`completed` 表示该子程序的顺序和公开最终状态检查通过 |
| public_search | 仅匹配源码中完整的“起飞必要 UAV、分配至所有目标、直到 session progress 超过 95%”命令，允许大小写/空白规范化 | 在固定轮数/API/修复预算内选择候选；处理可识别受阻，禁用起飞失败的 actor。公开 progress 必须严格大于 95；不能降低阈值或将其解释为任意任务整题证明 |

额外照片、指定 actor/目标、不同进度阈值、时序或其他未知条款均不能通过截取可匹配子串进入技能。它们由原工具路径承担。技能的有限语法不是通用 Agent 的完整任务范围。

`observed_target_v7` 继承入口观测、飞行状态、共享端点及终止边界进度读取，并允许发现目标的 actor 在正常 move 槽内尝试新公开固定目标坐标，每个目标 ID 至多一次，不增加 API/轮数/修复额度。名称型到达反馈只能抑制可选跟进，不能证明对应 target ID 已完成。这些是搜索策略组成部分；评价调度或共享时必须保持它们一致，不能把同时增强搜索的结果全部归给门控。

## 6. 范围化跨机负证据

当前可转移对象是**严格目的点冲突证据**，不是“这架 UAV 失败过”这种一般经验。一次合格记录包含源 actor、精确 XYZ、原动作及回执、evidence ref、plan/scene/epoch 和序号。其来源必须是 `move_to` 对同一 actor 的明确错误回执，完整错误文本符合服务端目的点几何冲突合同；源 actor 的后读公开 XYZ 相对于移动请求前未改变。路径冲突、状态、电量、权限、参数错误、partial/unknown 均不能据此跨机共享。

当前转移依赖以下前提：

1. 服务端该目的点碰撞谓词依赖目的点 XYZ 和障碍几何，不依赖 actor、起点或能力；该前提来自[服务端合同审计](results/harness-shared-endpoint-20261023/CONTRACT_AUDIT_CN.md)，不外推到一般机器人。
2. 同一计划、场景、epoch，当前搜索固定高度为 20；只排除完全相同的 XYZ，不扩展成邻域、路径或全局不可达区域。epoch 是本地证据索引的清理计数，不是服务端地图版本。
3. 显式声明并实际满足静态障碍及无外部 writer 合同。布尔配置是启用条件，不是静态世界的独立证明；已有本地实验另做 writer 隔离与前后几何核验，私有 digest 不输入策略。
4. 公开观测到已有障碍 ID 的几何变化或已知记录消失时，退出整个计划。局部空 nearby 不清除已有负证据；不可见的远处修改无法只靠此守卫检测。

在这些前提内，源 actor 的目的点冲突可作为其他 actor 排除同一点的依据。`shared_endpoints` 保存在 generator/plan 内，以精确 XYZ 索引；[搜索执行代码](../agent4drone/harness_skills.py)在候选选择时应用排除。它只转移环境约束，不伪造消费者执行过失败动作，也不把来源 UAV 的已到访、照片或完成义务转移给其他 UAV。

这个规则是有明确前提的负证据缓存与复用。目前没有动态地图版本协议、跨计划长期记忆、区域泛化或通用多机器人失败推理。若前提不成立，应禁用共享或退出；不通过放宽“可共享”定义追求重复数下降。

## 7. 有限研究主张、反证与最小对照

核心可检验问题是：**在相同底层工具和局部处理能力下，如何利用效果确定性、依赖与证据范围决定继续或重新决策，使有限预算转化为有效任务完成，并控制重复副作用及无效续行？** 这个问题定义是研究对象，不构成已证明的新问题或新算法声明。

| 候选主张 | 必要对照与观测 | 反证或收缩条件 |
| --- | --- | --- |
| H1：局部处理仍有效时，持续执行可减少无必要模型往返 | 同技能、守卫、原工具权限、初态和预算的 `failure/fixed/every_step/applicability`；同时明确 guarded macro 等价基线。比较整题成功、调用/token、动作及实际恢复 | 若只相对主动增加暂停的基线省调用，保留条件性交互收益，降级“新调度算法”主张；若动作/总成本上升，完整报告权衡 |
| H2：公开效果分类和来源化剩余要求能改善原工具接续 | 相同原始回执全部保留，比较无结构化恢复投影与当前投影；在明确失败、partial、unknown、依赖变化及终态控制中测实际后续动作 | 若模型不遵守建议，或增益仅来自额外提供信息/预算，不声称状态表示本身有效；不把只读建议当成硬约束 |
| H3：有范围的跨机负证据能减少可转移的重复失败，同时避免错误传播 | 固定搜索器和调度，比较不共享、actor 内证据、范围化跨 actor 共享；另用不可转移错误/失效条件作负对照 | 若机会稀少、效果只出现在旧开发题，收缩到局部机制；若错误共享损害完成或仅以更多动作换分，保留代价与适用边界 |

主指标为端到端独立任务成功；并列报告工具正确性、模型调用/HTTP/token、墙钟、动作/路径代价。恢复须同时有实际机会、后续行动及剩余要求满足，不能按 `resume`、`completed`、日志中的 `REPLAN` 或恢复建议数量计成功。额外记录未知效果后重复动作、终态控制拒绝、无效继续、错误中断和错误共享；机会不足时相应比率为 null。

整体自然评价保留全部任务分母，原工具成功同样计入；预先指定的机会子集另外报告。受控故障应尽量绑定公开动作或环境条件，避免只按 skill 内部动作序号触发而让原工具回退绕开后续故障。即便使用同一扰动规则，策略分歧后的实际暴露也可能不同，仍须记录。现有新划分提供实例隔离基础，不自动证明已有恢复场景足够或获得独立泛化成绩。

若当前定义与强工程基线等价且没有独立效果，Harness 可作为可靠执行基础保留；不需要为论文扩张架构。后续学习结果也不能自动补足 Harness 新颖性，本轮不进入采数或训练阶段。

## 9. 三类直接相关工作的对照

这里只列与本文规则直接重合的主源，不声称穷尽相关工作。差异描述不是新颖性证明。

| 主源 | 已有思想 | 本文目前的区别与需回答的问题 |

当前最稳妥的论文定位是：**给出带明确权限、效果语义和失效边界的多 UAV 执行机制，报告其在限定可恢复事件中的交互收益及范围化负证据复用的条件效果；把与普通 guarded macro 的等价部分、代价和未验证范围公开。** 能否进一步形成独立方法贡献，取决于上述强对照与可证伪问题，而非本文命名。
