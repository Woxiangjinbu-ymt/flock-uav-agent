# 前 20 对成本校准验收与后续实验建议

2026 年 10 月 16 日。**40 次校准已全部完成并封存，建议暂不按当前实现直接继续剩余 360 次。** 本轮验证了完整初态恢复、自然技能入口和成本日志可用，也找到了搜索技能入口与终止态使用的问题；但没有产生能够区分 applicability 与 failure 的可恢复失败检查点，因而不能证明适用性门控有独立收益。按预先约定的分层规则更新预算后，总预计用量超过原建议的 10 亿 token 软停线。

队列状态为 `calibration_complete_paused_pending_user_decision`，协调器及子进程均已退出。剩余 360 次未启动，未重跑任何任务，也未修改冻结实现、初态、顺序或参数。

## 完整性与计量范围

- 本轮是预先选定的 20 个任务 × 两臂 × 第一次重复，共 40 次；五场景各 4 对。不是完整 100 题结果，也不是两次重复的完整对照。
- 40 份封存文件集和 SHA 校验通过，冻结 manifest 中 410 个文件校验通过，启动记录与 manifest 哈希一致；执行 ID 恰好等于授权集合。
- 20 对完整初态、公开初态及首个实际 HTTP 请求体哈希均相同；worker 0/1、同对先后及各 worker 顺序全部符合冻结表，每次独立恢复。100 题准备阶段的 400 次恢复和 605 个原检查点核对保留不变。
- 本轮评分为每臂 154 个检查点、合计 308 个；没有 checker 错误或缺失评分。40 次进程正常结束不等于 40 次任务成功。
- 907 个逻辑模型调用与 907 个实际 HTTP 尝试逐条对账，usage 缺失为 0。输入、输出、cache hit/miss 与原遥测一致。token 只计算本轮实验供应商 usage，不含本对话、历史 v1/v2 或离线准备。
- 全部动作请求、物理事件 ID 和几何段长重新核算，无事件重复，物理事件与 API 内原历史逐项匹配。截止评分快照与排空后状态一致。

**顺序限制需要保留：**完整 400 次方案按场景、worker、先运行臂及第二次反转设计平衡，但此次冻结前缀实际是 **A 先 6 对、F 先 14 对**，不是 10/10。它符合原冻结队列，并非执行偏差；校准阶段不能宣称已经完成全量顺序平衡。两臂共同初态不能消除模型随机性和服务时段影响。

|区分 applicability / failure 的失败检查点|**0 次**|适用性门控独立收益尚未得到检验|

### 两道简单链

`b1eb0270` 的真实技能事件依次为 Drone 3 起飞到 14 米、转到 353°、悬停；`898cfdca` 为 Drone 12 起飞到 10 米、升至 30 米、悬停。两臂的动作参数、actor 和原 checker 均相符，游标均按 1→2→3 前进，已经生效的步骤没有重复执行。

前一道任务的 A 首次控制调用包含多余字段，被包装层拒绝，模型修正后成功提交。这是**入口参数纠错**，不是技能中断后恢复。简单链两臂总调用都是 9 次，总 token 分别为 122,945 和 120,245，不能据此证明 A 的独立收益。

### 搜索任务的真实接手

`7eba7390` 要求起飞必要无人机并访问目标，直到公开会话进度超过 95%。两臂均先查看状态、进行公开感知，然后自主提交 `public_search`；但公开障碍黑板为空，技能只读取一次进度就触发共同守卫 `empty_public_obstacle_blackboard`。此时游标为 0、进度为 0、三个目标都未访问。

两臂随后用原工具起飞五架无人机并搜索。之后又尝试 start 同一技能，被 `skill_already_committed_use_plan_id` 拒绝；再使用正确 plan_id 调用 resume。两次 resume 都只返回原来的 `needs_replan`、游标仍为 0，且整条轨迹只有一次 `skill_enter`，没有新增技能动作。这是模型对终止态的无效恢复尝试。

接手结果根据实际移动和会话访问记录审计，而非模型自述：

- **A 有效完成：**实际轨迹先后覆盖三个目标。最后 Drone 3 从 `(100,650,15)` 移至 `(50,550,15)`，距第三目标 `(52,545)` 约 5.39 米；物理事件 `204:0` 在约 314.53 秒提交。`target_reaches` 补入第三目标，公开进度为 100%，独立 checker 通过，超过 95% 的剩余义务成立。
- **F 未完成：**存在起飞、搜索和两个目标的真实访问，但第三目标没有访问记录。其实际路径距第三目标最近约 31.31 米，公开进度停在 66%，独立 checker 不通过。147 次动作尝试和 61.72 公里路径不能算有效完成接手。

目标访问依据是会话 `target_reaches` 及实际路径；目标对象本身的 `is_reached` 标记不是该任务的评分依据。两臂的自然语言位置描述存在不准确之处，因此未用其自述替代历史证据。

上述 1/2 只是同一个任务两条轨迹的描述，不能当成跨任务接手可靠率。两臂在该处使用了完全相同的守卫，不能把 A 的成功归因于适用性调度优于 failure。

### 其他入口拒绝与机制覆盖

另有两道不支持完整语法的任务 `784d71f8`、`1905e0ad`，两臂各尝试提交一次被拒绝；`784d71f8` 的 A 还出现一次将控制调用与其他工具混发的包装拒绝。四次语法拒绝、一次混发拒绝、一次多余字段拒绝及两次重复 start 拒绝均保留，不计为恢复或接手成功。

对全部 20 对门控记录按 decision、reason、cursor 和 next_call 归一化后比较，实际决策序列均相同：17 对没有技能门控事件，两对简单链正常完成，一对搜索共同退出。没有局部可恢复故障进入两种策略的分歧分支。**本轮观测不到门控独立收益，也不能据此判定门控机制无效。** 此前 v2 的受控机制证据仍需与此次自然入口结果分开表述。

## 截止 预算与日志质量

4/40 次触及 500 秒，A/F 各 2 次，全部保留完整分母。没有触及 600 工具步骤或 1,800 图循环；最大工具步骤为 270。搜索技能尚未进入搜索循环，因此计划 API、局部修复和搜索轮数上限没有受到实质检验。

其中 A 的 `784d71f8` 有一次动作请求在 499.75 秒发起、500.48 秒返回，按冻结协议标为原子命令未提交；该请求本身返回障碍冲突错误，没有候选物理事件或能耗。未提交动作计入尝试，不计入路径或评分。其余在途模型响应排空后未改变评分快照。

截止后才返回的模型请求共携带 556,290 token，已包含在总成本中。非流式日志不能把这些请求内部的 token 精确分割成截止前后两部分，因此不将其全部称为“500 秒后生成的 token”。无缺失 usage、无终止性服务错误、无自动重试。总计 25 个 partial_success 回执按实际生效段计入路径。

任务目录 `tasks.json` 保留了规划阶段的 `not_materialized` 标签；实际快照状态、哈希和初态审计以已冻结的 `fixtures/*.json`、`fixture-preflight.json` 和逐次恢复记录为准。本次验收核对的是这些真实文件，没有改写冻结目录来美化状态。

## 剩余预算与是否继续

按原方案约定，以场景 × 静态技能组的“本轮实际 / 同任务旧日志”比值外推剩余任务，已覆盖组下限 1.25、未覆盖组保留 2 倍，不将高倍率截断为 2：

- 剩余 360 次预测 **1,454,856,392 token，约 14.55 亿**；加上已用量总计 **1,530,955,973，约 15.31 亿**。超过原建议的 **10 亿软停线**，不能在原预算假设下直接续跑。
- 剩余冻结队列的时间回放约 **12.8 小时**（按 630 秒槽位截断）；不截断的规划外推约 **14.8 小时**。可按约 **13–15 小时**理解当前点估算，另需服务波动余量。若剩余任务都耗满 500/630 秒，双 worker 工作量分别约 25/31.5 小时，均不保证按时完成。
Easy 搜索组仅一对，旧日志基准只有 98,205 token，本轮为 5,275,260，倍率约 53.7；这一小样本很不稳定，但按事先规则不能将其任意压回 2 倍。未覆盖的其他搜索场景仍可能有更大误差。

**建议先暂停原样续跑，优先处理入口和证据覆盖问题。** 直接再花预算运行 360 次能够补齐这个版本的完整端到端描述，却很可能主要增加原工具成本，仍无法可靠回答“模型能否恢复技能”“适用性门控为何更省”这两个核心问题。本次只有两个正常链任务、一个搜索共同退出任务，继续的机制信息收益目前不足以支持该成本。

下一步应先形成新的、单独决定的验证方案：

1. 明确搜索技能对公开观测的要求，区分“尚未观察”和“已经观察但附近无障碍”；研究有限公开侦察或明确的入口预条件，避免正确选择搜索类型后立即不可恢复退出。不得通过注入私有障碍或预提交技能绕过自主选择。
2. 明确 paused 与 needs_replan 的控制契约，使模型能区分“继续原计划”与“接手剩余义务”；终止态 resume 应有明确反馈，避免重复 start→同 plan_id 空恢复。
3. 先在独立设计的小规模自然入口与可恢复事件验证中确认有足够真实机会，并逐例核查游标、已生效动作和剩余义务，再决定是否值得投入完整任务集。新的实现必须另建版本，不能把新结果拼入当前冻结对照。

若论文需要的是“当前冻结版本在完整 100 题上的表现”，也可以保留现方案作为后续选择；但需要明确接受更高预算及可能仍无恢复证据的风险，再由用户决定。本次没有发起任何续跑或新实验。
