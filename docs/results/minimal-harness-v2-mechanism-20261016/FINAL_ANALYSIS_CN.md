# v2 最小 harness：96 次受控事件实验最终验收

验收日期：2026-10-16。范围为冻结的 24 案例 × applicability / failure 两臂 × 两次重复，共 96 次。全部执行结束、证据封存通过；未启动完整 100 题，未重跑任何案例。本文中的 A 为 applicability，F 为 failure。

## 1. 结论与可声明范围

**在正确技能已经提交、既有局部修复仍适用的条件下，适用性门控有独立的模型交互收益。** 12 个可恢复案例的 24 对执行中，A 的模型调用为 78 次，F 为 171 次，减少 54.4%；总 token 减少 64.4%。其中最干净的证据来自起飞失败案例：8 对的实际动作端点、参数、顺序及回执状态完全相同，均成功，但模型调用为 23 对 41，减少 43.9%。这组结果把“减少模型往返”与“改变动作路径”区分开了。

**目前不能声明提高了任务成功率，也不能声明降低所有执行成本。** 全体成功为 48/48 对 47/48，唯一失败涉及 F 的一次约 602 秒模型请求，最终没有可执行动作或有效最终答复。A 同时产生了更多动作尝试，完整实验为 507 对 365。受阻案例中，F 经常改用原工具，绕过剩余按技能动作序号触发的故障，所以两臂后续故障暴露并不相等。

**本轮验证了条件式继续、同计划恢复及失效后的真实接手，没有验证模型自主选技能。** 初始技能由夹具提交，尽管原日志沿用 `origin=explicit_model_tool_commit` 字段，也不能据此声称由模型选择。该实验是一次受控开发实验，24 个案例包含同族变体，两次重复不等于 48 个独立场景。

## 2. 实现、冻结及完整性验收

两臂复用同一份 v1 冻结 agent、技能、局部修复和强制失效守卫；唯一技能调度差别是：局部已处理的失败检查点，F 暂停交回模型，A 在守卫有效时继续。完整控制器对象图恢复覆盖实体、历史、计时器和随机流；每次执行新建模型上下文、黑板及计划。模型使用真实供应商 HTTP，环境使用真实控制器的进程内 ASGI 接口。

- 运行前离线回归 **94 项通过**；24 案例的 48 次脚本化机械预检通过。队列修复另有 14 项回归通过。
- 原始 manifest 的 **266 个冻结文件**全部哈希一致；独立队列修复的源码、测试及 schedule 哈希一致。
- **96/96 份封存**通过，共核对 **1,247 个封存证据文件**，文件集合完整；注册表、计划表和执行目录一一对应，无额外执行。
- **48/48 对**初态结构哈希、共同公开输入及共同前缀一致；24 案例各四次执行的初态一致。
- 每个 worker 的实际顺序符合冻结表；同对两臂相邻；第二次重复反转臂顺序并交换 worker；两次重复间屏障有效；最大并发为 2。协调器及 96 个执行 PID 均已退出。
- 逻辑回调与实际 HTTP 的 usage 逐项对账一致；缺失 usage 的调用 **0**，缺失输入、输出或 cache 字段 **0**。
- 所有目标结论均从最终世界状态及实际动作历史重新计算，并与原 checker 一致。简单动作链核对高度、航向、悬停、动作顺序及起飞次数；搜索核对实际目标访问记录与同时间戳运动段是否进入目标几何的任务半径。

原始协调器误用 worker 1/2，而冻结表为 0/1，导致最初 6 次、即 3 个 r1 配对仅使用一个 worker。随后停止派发，保留在途结果，独立修复协调器只继续剩余 90 次。冻结 agent、夹具、顺序及预算没有改动。**主分析保留全部 96 次**；下文另给剔除这 3 对的描述性敏感性结果。

## 5. 恢复、接手与剩余义务的真实轨迹

对 96 条轨迹做结构化逐条核查，并细读下述代表轨迹及唯一失败轨迹。判定依据为实际动作回执、世界历史和独立目标检查，不采用 `resume`、重新进入计划或 `completed` 字样作为成功替代。

|最终路径|A 次数|F 次数|
|---|---:|---:|
|首次交回模型前技能已完成，目标复核通过|32|8|
|同 plan_id 恢复后技能完成，目标复核通过|0|13|
|从 paused 计划转原工具，目标复核通过|0|14|
|强制 needs_replan 后原工具接手，目标复核通过|16|12|
|没有有效接手，目标未完成|0|1|

F 有 **32 次 resume，分布于 27 条轨迹**。每次都对应真实存在的 paused plan_id，并从该计划先前游标继续；19 次返回 paused，13 次返回 completed。只有后者且目标复核通过的 13 条算作“同计划恢复完成”。另外 14 条通过原工具完成，属于接手而非同计划修复。F 另有 12 次显式 cancel、6 次因相关外部动作引起的计划依赖失效，两者可能重叠。记录中没有错误 plan_id、对终止计划恢复、控制包装器拒绝或模型提交新计划的事件。

强制 `needs_replan` 共 **28 条**，A 16、F 12，全部有其后的真实原工具动作且最终义务成立，没有继续恢复该失效计划：

- **效果不明 16 条：** 真实起飞已发生的 8 条没有重放起飞；实际未发生的 8 条在公开地面状态证据下执行一次起飞。16 条最终均只有一次实际起飞，随后正确旋转并悬停。
- **actor 状态变化 8 条：** 失效后完成剩余旋转及悬停，不重放已完成起飞。
- **修复超限 4 条：** 仅 A 实际到达第 17 次失败并触发 `needs_replan`，随后用原工具完成目标。F 的对应 4 条在第 2、2、2、3 次受阻后改走原工具，未到第 17 次。因此不能宣称 F 在线通过了修复超限守卫；两臂到达该边界时的行为仅有离线脚本化验证。

可复核例子（目录含 toolchain、harness、public-api 及 final-world）：

- [起飞 actor 禁用后按原 plan_id 恢复完成](./experiments/minimal-harness-v2/runs/recoverable_takeoff_actor_disabled-03-r1-failure)：失效 actor 保持地面，其余 actor 搜索并真实到达目标。
- [多次 resume 仍暂停，最终 cancel 并接手](./experiments/minimal-harness-v2/runs/recoverable_blocked_candidate-03-r1-failure)：不能把中间三次 resume 算成三次有效修复。

- [回执丢失但起飞已生效](./experiments/minimal-harness-v2/runs/unknown_effect_receipt-01-r1-applicability)与[回执丢失且起飞未生效](./experiments/minimal-harness-v2/runs/unknown_effect_receipt-03-r1-failure)：分别避免重复起飞、基于地面状态补做起飞，最终高度和航向正确。

## 7. 长尾失败、预算与敏感性分析

唯一失败为 [recoverable_blocked_candidate-06-r2-failure](./experiments/minimal-harness-v2/runs/recoverable_blocked_candidate-06-r2-failure)。第一次受阻后，模型首个请求等待约 **601.79 秒**，HTTP 200，输入 11,478、输出 1、合计 11,479 token，没有任何模型工具调用，任务目标未完成。原生输出为没有最终响应、任务完成未验证。注册表的 `completed` 只代表执行结束并封存，不代表任务成功。

这是单次服务响应长尾与无有效输出同时出现的观测，不能据此识别 A 提高推理/修复成功率的因果效应。该执行保留在主分析，评分就绪记 500 秒，完整处理约 601.844 秒，token 全部计入。所有 **493 次 HTTP 均为 200**，重试索引均为 0；无 HTTP/模型异常事件，无自动重试或重跑。

预算核查：实际工具步骤最大 **20/600**；未出现图循环或工具步骤上限停止；每计划 API 最大 **90/2000**，搜索轮数最大 **7/16**。局部修复最大记录值为 **17**，即第 17 次失败触发既定 16 次修复预算的退出边界，并非允许第 17 次继续修复。只有上述一条触及 500 秒评分窗；在途模型请求没有被 500 秒硬取消，未达到 630 秒看门狗终止条件。100M token 软停未触发。

在线实验从原队列启动到修复队列结束用时 **1,493.277 秒，即 24 分 53 秒**，包含队列纠错停顿、启动和封存，不包含后续人工验收。96 次共消耗 **7,293,646 token（729.36 万）**：输入 7,088,972，输出 204,674；输入中 cache hit 6,238,464、cache miss 850,508。实际 493 次供应商请求。

实际成本低于启动前 3,000 万–1 亿 token、1–3 小时的规划区间，主要因为多数受控事件很短。**不能线性用这 24 个事件预测完整 100 题。** 完整任务有技能选择、较长搜索、不同适用比例及服务长尾；本轮也未制作并验证完整 100 题的独立初态。进程内 ASGI 与 v1 的本机 TCP 路径不同，不作 v1/v2 秒数的因果比较。

当前最稳妥的 contribution 表述是：

> 我们提出并实现一种以计划有效性为执行边界的 agent harness：将技能包装为带 plan_id、游标、来源义务和有界局部修复的可中断计划；在动作失败仍可由既定技能处理时继续执行，在依赖失效、效果不明或修复预算耗尽时交回模型，并以实际动作及剩余义务验证接手。固定技能与初态的受控实验表明，这种调度能在部分可恢复事件中减少模型往返和 token；同动作序列子组进一步支持门控的独立收益。

这仍是架构机制和条件收益的证据，不是通用新颖性、真实机器人安全性、总体任务成功率提高或自主技能选择能力的证明。论文故事应围绕“动作失败不必等于决策失效；继续的依据、必须中断的边界、接手后的义务验证”展开，同时公开多动作尝试的代价。不要将“少调用模型”单独包装为新架构贡献。

## 9. 下一阶段建议及停止边界

本轮机制结果足以支持继续研究，但完整 100 题仍需用户决定。启动前建议冻结以下验收条件：

1. 为完整任务准备并核验独立初态、checker 和所有任务义务；恢复自然的模型自主选技能入口，分别统计选对、误选、漏选以及接手失败。
2. 在不增强任一臂技能的前提下保留 A/F 同技能对照；预先给出适用任务分析及全分母成功率，不能按执行结果筛选适用子集。
3. 将队列 worker 集合、全部区组调度、重复屏障与零重复执行纳入启动前全量干运行检查。
4. 明确 500 秒评分窗与在途请求取消语义；同时保留模型调用、HTTP、usage、就绪时间和完整墙钟，并记录物理动作与路径代价。
5. 用完整任务的已有长度/调用分布重新估算 token 和耗时，再冻结软停规则；不得将本次短事件的平均成本直接乘以题数。

以上是下一阶段建议，本次验收没有启动新的实验、补跑旧预算或修改冻结实现。
