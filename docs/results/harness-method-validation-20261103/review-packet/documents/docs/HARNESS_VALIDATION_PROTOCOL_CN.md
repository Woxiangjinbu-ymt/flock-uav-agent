# Harness 方法验证协议 v1

日期：2026-11-03。对应[方法定义](HARNESS_METHOD_CN.md)及[本轮结果](results/harness-method-validation-20261103/REPORT_CN.md)。本轮停留在 Harness 方法定义、工程验证与实验准备，不进入第五项 Teacher 采集。

## Confirmed Decisions — 固定研究对象

候选配置为 `evidence_harness + evidence_r2 + observed_target_v7 + task_execution_state_v1`，默认调度 `applicability`。不叠加 `execution_memory_v7`。统一状态是公开证据的只读表示和恢复建议，不新增通用语义验证器。主模型集中控制多 UAV，原工具一直可用。

以端到端任务成功为主指标。成本按模型调用、输入/输出 token、墙钟、公开 API、物理动作尝试与错误分别报告；调用下降不等于总体成本下降。程序终态、模型声明与独立任务评分分开。

本轮本地执行使用 `general-agent-v2-local` 的既有维护入口；新增场景均标为 development。真实模型的参数、预算和执行授权不由这个文档或代码指纹自动获得。历史 360 次及 14 槽不续跑，11-02 已终止 pilot 的额度不转移。

## 两条评价轨道

| 轨道 | 要回答的问题 | 对照与固定条件 | 分母及适用范围 |
| --- | --- | --- | --- |
| N：自然入口系统对照 | 整合包是否有用、模型是否选择子程序、何种任务增加开销？ | `raw` vs `integrated`；同模型/初态/时限/请求预算/评分/隔离；明确整合臂多了状态与控制工具，是整合包对照 | 固定18道旧开发覆盖题，各2次重复、每次2臂，共72个拟议槽；尚未授权或执行。按任务、场景、任务族分组，不称独立泛化 |
| M：同能力机制对照 | 在同执行能力下，继续还是交回模型的差别是什么？ | `failure` vs `applicability`；同状态投影、子程序、局部修复、硬守卫、搜索、共享、工具与预算；只改暂停规则 | 故障条件与机会另列；受控初始子程序提交标为fixture，不算自然选技能。正式任务/场景列表尚待实现后冻结，不能冒称已准备完整实验 |
| L：本轮本地合同验证 | 当前实现是否符合方法定义？普通guarded macro是否语义等价？部分完成能否只处理剩余部分？ | 真实runtime/技能的有界控制探针，以及真实Agent+ASGI+脚本模型完整回合 | 按实际运行分别报告；无provider、无模型token收益、不是N/M的真实模型结果 |

N直接采用已冻结的 `experiments/task-coverage-v1-study/manifest.json` 中全部18题及其任务顺序，不按历史成败换题。第1次各题按清单奇偶交替 B/I 起始，第2次反转；每个槽新进程恢复相同初态。72槽是待讨论的完整开发设计，不是本轮付费授权、功效分析或足以支持论文的样本量保证。未来若先做更小的真实接线验收，应另封存独立批次，不能把未运行槽删除后称完成本协议。

## 故障与机会定义

预先保留正常负对照，以及：明确未应用且可局部修复、修复预算耗尽、部分完成、效果未知（实际应用/未应用分别记录）、依赖改变、终态误恢复、可跨机复用的静态目的点冲突、不可跨机泛化的路径/主体特定失败。

故障绑定公开动作语义、端点、环境条件与事先规定的触发次数，不仅绑定子程序内部动作序号。两臂记录是否实际暴露、暴露次数和后续轨迹；暴露不等的配对仍保留，但不能用于“同故障条件的纯调度收益”结论。禁止为了得到正向结果不断增补任务。

事件分母分为：存在符合条件的失败、尚有预算且有后续决策机会、实际采取恢复动作、原计划续行或原工具接续、剩余要求经独立证据完成。`resume`调用次数不是恢复成功数；硬截止后没有机会；分母为0时结果为null/不可估计。局部自动修复和模型重新决策分开统计。

## 强基线、消融与不变量

1. 普通带守卫子程序必须作为方法语义参照。若同生成器、同硬守卫、同回执下的“运行到完成或失效”与 `applicability` 等价，就承认等价，不新增同义产品开关，不把对 `failure` 的节省写成独有算法创新。
2. 系统B/I与机制A/F分别报告。前者允许整合功能差异，后者只允许暂停规则不同；不能用前者证明某一个组件的因果作用。
3. 新状态投影可单独关闭；只有要主张其独立收益时才运行相应消融。当前R2和Harness仍绑定，不能宣称R2独立消融已准备。
4. 共享的独立收益需固定搜索与修复器，比较不共享、仅主体内记忆和范围化共享。现有revision差异不自动等于此消融；本轮不新增这组三臂产品接口。
5. 不关闭防重放、预算或硬失效检查来制造弱基线。评估私有状态和checker不进入策略；有意注入故障只改变执行/回执条件，不把正确后续动作提示给真实模型。

## 评分与统计

原checker保留原协议；对未覆盖的悬停、主体、顺序、摄影等义务，预先制定独立行为审计。分别列出原checker成功与完整义务成功，缺少审计时完整义务成功标记unknown，不把模型声明补作证据。部分恢复正例还必须由实际动作/位置事件证明已执行前缀没有重放，负例确认仅提前声称完成不会通过。

保留计划、启动、正常退出、已评分、超时、取消、基础设施异常和未运行的全部分母。任务失败计入有效任务分母；运行器异常单列且保留全计划口径，不静默删除或重跑挑最好值。

真实评价以配对差异报告，重复按任务/场景聚类；不能把同题重复当独立新世界。样本不足时给原始计数与不确定性，不凭不显著差异认定成功率等价。只有在预定义质量条件得到支持时才作效率结论。独立场景评价另行冻结；当前174题仅同模板静态实例，不能代表任务族OOD或复杂恢复泛化。

## 验收门槛与收缩

| 门槛 | 必需证据 | 本轮可完成的范围 |
| --- | --- | --- |
| 方法可审查 | 状态/决策规则/不变量/代码对应、与guarded macro关系、可证伪假设 | 方法文档、控制探针和代码指纹 |
| 本地运行合同 | 部分效果真实应用、公开反馈、仅剩余动作、独立评分；主要生命周期回归 | 新增正负完整回合与已有本地回归 |
| 新版真实自然能力 | 同一冻结版本真实接口、完整配对、自然选择与恢复机会 | 本轮不以Mock替代；仍待真实批次 |
| 因果与泛化 | 同能力公平故障、关键消融、未调参场景与完整成本 | 仍待后续实验，不能由本地测试升级 |
| 论文定稿 | 方法差异与以上效果证据支撑明确有限主张 | 本轮不自动通过 |

若只证明局部条件下降低往返，则主张限于该条件；若普通guarded macro等价，则把调度保留为执行组织方式；若共享增益仅开发实例出现，则保留局部结论；若无自然机会，收缩自然恢复主张。方法是否有贡献由证据决定，不以继续增加模块或后续SFT代替。

机器可读计划见 [validation-plan.json](../experiments/harness-method-v1/validation-plan.json)。`freeze_harness_validation.py prepare/verify` 只封存方法、配置、对照清单与代码/数据指纹，不发送请求，也不是通用在线运行器。局部实验实际源码另由各运行目录封存。
