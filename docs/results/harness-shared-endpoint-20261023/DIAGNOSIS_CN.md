# 跨无人机精确目的点负证据：封存 v4 公开轨迹诊断

日期：2026-10-23。**本次只重建既有公开回执并检查冻结源码；未执行仿真、模型或候选修复，也未修改生产代码及旧封存。**

结论：`24ac1838` 有 **1 次 / 1 个 XYZ 组**、`b1ad4f3e` 有 **7 次 / 4 个 XYZ 组**，是不同无人机在先前另一架无人机已经收到明确“目的点冲突”回执的精确 XYZ 上再次失败。v4 记录了来源证据，但只向原 actor 排除该候选；其余 actor 仍可选择同点。这是可定位的共享范围缺口，不是已有共享证据过期或消失。当前执行契约支持将它作为**同计划、同场景与 epoch、精确 XYZ** 的共享候选；本诊断不能证明修复后整任务成功或节省成本。

## 4. 原因及可转移范围

冻结 [harness_skills.py](diagnosis-01/source/agent4drone/harness_skills.py) 中，v4 的 mask 以 `(actor, candidate_index)` 保存；每次选择只传入 `a == actor` 的排除索引。source 已有真实回执及后读 XYZ 不变，mask 仍在最终 frame 中；消费者是另一 actor，因此不在该排除集合中。没有 TTL、显式撤销或已登记证据丢失导致本组重试。此时缺少对应几何也使既有几何筛选未提前拦截这些请求。

冻结执行契约提供一个窄而具体的依据：[drone_controller.py](diagnosis-01/source/server/controllers/drone_controller.py) 的 `move_to`（1051 起）先走路径校验；明确的目的点错误来自 `_check_position_collision`（1719 起），传入只有 XYZ，`margin=0`。检查函数不传 actor、型号、heading 或起点；后者用于独立的路径碰撞检查。[obstacle_controller.py](diagnosis-01/source/server/controllers/obstacle_controller.py) 的 `check_point_collision` 使用点、障碍几何与高度。这里仅检查代码契约，没有读取对应私有障碍几何。

因此可以验证的最小候选是：**当前计划、当前场景与 epoch 内，在相同执行契约下，把已有合格目的点冲突及未移动的后读证明共享给其他 actor，且仅排除精确 XYZ。** 原始 actor、完整 action/receipt、evidence ref、XYZ、scene/epoch 应可追溯。实例中都在 z=20，不能把同 XY 的其他高度自动屏蔽；candidate index 只在该计划候选集内有意义。

以下不能从本诊断推出：整个命名障碍区域不可达、附近所有点不可达、通往该点的所有路径有同一失败原因、路径错误也能作目的点证据、其他场景/任务/epoch 可沿用缓存，或动态修改后仍有效。遇到公开成功反证、相关地图更新或作用域变化需要明确的失效处理；本批没有这些事件，不替代专项反例验收。

## 5. 后续前后对照的固定指标定义

以下为拟议对照口径，**尚不是新试验结果**。仍用原 7 题（3 个搜索代表、2 个简单正对照、2 个不支持语法负对照）、相同初态与 500 秒 / 2000 API / repair=16 / MAX_ROUNDS=16 预算，两版本独立进程并保持原评估隔离，不靠新增预算或 raw 接手完成任务。

| 指标 | 定义与解释边界 |
| --- | --- |
| 合格目的点失败 | `move_to` 完整回执明确匹配目的点冲突，actor/command/status 一致、精确有限 XYZ，后读证明 XYZ 未变；路径阻断、状态/电量/运输错误单列 |
| 跨 actor 后续失败事件 | 同 plan/scene/epoch、相同 XYZ，已有其他 actor 的合格来源后仍产生合格失败的请求数；每个后续 request 只计一次。历史 v4 为 24ac=1、b1ad=7 |
| 跨 actor 失败组 | 发生跨 actor 后续失败的不同 XYZ 组数。历史 v4 为 1 / 4；不能当作独立任务样本数 |
| 同 actor 重复 | 仍单列同 actor、同 XYZ、已有来源后的重复请求；保持 v4 已修复机制不回归 |
| 来源与消费者审计 | 每个共享条目保留原 request/command ID/evidence ref、来源 actor、XYZ、scene/epoch；所有新跳过/排除声明可追溯，不能用未来信息补早期决策。若候选集合或搜索路径改变，不要求历史 8 次消费者全部按原时刻出现 |
| 首次动作分歧 | 对齐动作请求顺序，报告第一次 actor/工具/参数差异及当时已存在的来源；同时记录替代动作结果。request ID 随新调用数量变化，不能只按 ID 强行配对 |
| 所有错误与 unique 错误 | 所有错误按真实请求计数，unique 保持原协议的分类签名；报告新增/移除签名及 endpoint/path/other 分类，不只报告重复数减少。unique 数不是独立样本数 |
| 整题与进度 | 原 command、checker 及分母不变；3 搜索的整题成功率为主，公开进度为辅。部分进度增加或重复消失不等于整题完成 |
| 成本与终止 | 动作请求/尝试（含失败）、API、repair 使用、墙钟、轨迹距离、耗电与停止原因分别报告；另核对终态 start/resume 无新增动作。历史耗电可能受墙钟环境时间边界影响，应披露差值，不强称逐字复现 |

静态诊断预计这是一项可有界验证的缺口，但新的路径可能继续遇到新目的点或路径错误。**不能把历史 8 次事件直接换算为净节省 8 次动作、提高成功率，或足以完成这两题。**
