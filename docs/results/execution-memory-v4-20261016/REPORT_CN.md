# Memory 第四版：事实与计划拆分后的三轮验证

日期：2026-10-16。

**这次修正了最初决策中“把准备移动说成已经移动”的问题，也连续三轮避免了同位置重复查询。但整体开销没有改善，v4 还不能算全面优于上一版。**

## 做了什么

将原来的合并理由拆成两部分：`observed_change` 只写已发生的变化及真实回执；`planned_action` 写下一步准备做什么、为什么做。没有观察到新变化就写 `none`，不能用未来的移动替当前查询找理由。

审计在工具执行前，用模型调用前的证据检查变化。**没有拦截工具，也没有为理由说明额外安排专门的模型轮次**；漏写、写错、格式不符都照常执行。记忆中的任务事实保持一致，两个线索场景的初始提示仅比 v3 多 68 个字符，其余四个场景相同。

## 三轮结果

仍是原来的 **6 个场景**。v2（无理由声明）、v3（旧合并字段）、v4（拆分字段）各重新运行三轮，共 **54 次**；每轮轮换执行顺序，不选取最好结果，也未扩大到 100 题。

| 三轮合计，每版 18 次 | v2 基线 | v3 | v4 |
|---|---:|---:|---:|
| 任务达成／正常结束 | 18/18 | 18/18 | 18/18 |
| 同机同位置重复感知 | 3 | 0 | 0 |
| 模型调用 | 57 | 55 | 57 |
| 工具调用 | 42 | 38 | 39 |
| 总 token | 140,951 | 133,423 | 149,010 |

| 轮次 | 重复感知 v2／v3／v4 | v2 token | v3 token | v4 token |
|---|---|---:|---:|---:|
| 第一轮 | 1／0／0 | 47,942 | 46,672 | 40,109 |
| 第二轮 | 1／0／0 | 46,702 | 40,113 | 54,526 |
| 第三轮 | 1／0／0 | 46,307 | 46,638 | 54,375 |

**减少同点重复的结果在三轮中一致，但 v4 相比 v3 没有新增去重收益。** v4 相比 v2 的 18 个配对中，3 次少查、15 次持平，无更多同点重复。前两轮收益来自纵向线索，第三轮来自横向线索。

总 token 方面，v4 比 v2 **多 5.72%**，比 v3 **多 11.68%**。缓存命中、未缓存输入和输出已分别留存。任务成功率没有提升，纯路线和失败重试也没有新增能力；已完成任务后的状态读取仍存在。

## 理由是否更准确

六次初始线索决策中，v3 都将末次空查询 `e15` 标成 `position_changed`，当时新移动尚未执行；v4 六次都正确写成 `none`，把换位置放入计划。人工检查确认，**这一类结构化标签错误从 6/6 降为 0/6**。v3 原来的自然语言多使用未来式，问题主要出在合并字段，并非每句话都在捏造事实。

不过理由仍未全部准确。v4 后续两次把“刚收到的查询结果”当成“最新成功查询之后发生的变化”，混淆了比较起点。按限定的变化类型和时间窗口，人工检查为 **12/14 符合、2/14 不符合**；这不代表整段文字都得到了事实认证。

还发现审计器把计划理由限制在 240 字符，导致 7 条内容因长度无法解析。原实验真实统计是 **7 条格式失败、5 条变化得到支持、2 条不支持**，不能只拿有效的 7 条计算整体准确率。实验封存后，仅将计划理由上限放宽至 1024，保留其他边界，并离线回放全部原始回复；原实验的动作、用量和失败统计没有覆盖。详见[审计修复记录](AUDIT_REPAIR_CN.md)。

## 为什么仍然更费 token

纵向线索的第二、三轮，v4 第一段移动已收到“到达目标”的回执，记忆也标记了访问完成。但模型继续查询目标中心，看到目标对象的 `is_reached=false` 后，又否定已有到达证据，执行“再移到中心、再查询”。每轮多出 3 次工具调用，分别用了 20,842、20,705 token。

这些查询位置不同，所以重复指标仍为零；但对于已经完成的访问任务，它们是额外确认工作。**不能把“没有同点重复”当成“没有无用动作”。** 两轮还出现了上述变化基准混淆，说明拆分字段能解决一种错误，无法自动解决完成证据的判断。

## 下一步

保留事实／计划分离，但优先解决“已有完成证据为何又被否定”：明确移动到达回执与目标对象状态字段各自表示什么，将剩余任务与已完成事项持续对齐；压短计划说明，并统计完成后的额外确认次数。继续小规模验证，不以添加更多提示或硬拦截替代判断。

本轮只说明这六个开发用场景的重复表现，不是独立测试集或 100 题泛化成绩。
