- 原 manifest 全量核验；本轮直接依赖的 manifest、快照、JSON、时间线共 19 个文件在前后校验一致。76 份执行源码复制后运行，前后哈希一致，执行结束时工作区对应源码也未改变。
- 14/14 子进程正常结束，无 watchdog、500 秒截止、基础设施错误、缺失结果、checker 错误或未执行补样。socket 连接阻断器记录的网络尝试为 0，模型调用为 0。

所有 trial 的技能运行均不足 1.4 秒，不包含进程启动。这里是离散模拟器执行时间，不是无人机真实飞行时长，也不是在线模型耗时。两臂初态与时间线相同，但实际读观察的时刻随执行变化，不声称整段世界状态或天气始终逐字段相同。

### `7eba7390`：搜索范围和目标利用仍需诊断

五架无人机入口观测全部为 `valid_empty`，之后执行 16 轮、80 次移动，均返回成功；没有因入口、碰撞或电量错误终止。停止时公开会话进度明确为 `visited_targets=1 / total_targets=3`。

任务期的感知回执共出现两个目标 ID：Fixed Target 1 与 Fixed Target 2。移动回执只报告到达 Fixed Target 1（请求 160、180、291）。不能把对象的 `is_reached=false` 当作没有访问的证明：该标记与会话到访记录并非同一个评分依据。

公开初始机群位置范围为 x=506–984、y=65–627；现有策略据机群包围范围外扩 200 m 构造候选，而不是保证遍历任务全区域。本轮实际请求目的地范围为 x=341–1181、y=35–805。策略选择函数使用新覆盖格与距离，调用参数为公开 fleet 和障碍，不把已见目标坐标作为独立目标访问策略。

这些事实说明“未见目标的覆盖范围”和“发现后如何保证实际访问”仍是诊断候选。**本次没有用私有目标坐标认定剩余目标位于候选区外，也不能断言只扩大区域就能完成。** 公开可确定的是：观察过两个不同目标，实际进度只完成一个，固定轮数耗尽。

证据：[公开 API](run-20261023-01/trials/7eba7390-entry_contract_v2/public-api.jsonl)、[Harness 状态](run-20261023-01/trials/7eba7390-entry_contract_v2/harness.json)、[原检查与成本](run-20261023-01/trials/7eba7390-entry_contract_v2/result.json)。

### `24ac1838`：高度大于零不等于可移动状态

最后一次移动前，公开状态请求 **198** 返回 Drone 30（`a83433e1`）：位置 `(405,1497,57)`，`status=idle`，`battery_level=100`。紧接请求 **199** 试图移动至 `(455,1575,20)`，返回 `Cannot move from current status: DroneStatus.IDLE`。初始公开 fleet 已给出同一高度、状态与电量；本轮没有对该机执行起飞。

现有搜索代码以 `z>0` 构造 airborne 集合，因而在这个公开状态组合下跳过起飞。此处错误的直接证据是状态不允许移动，**不是电量耗尽**。另六次错误回执来自障碍冲突：两个路径交叉错误及四个终点冲突。到达此边界前已有五个目标访问，但这仍远低于大于95%的原义务。

静态核对[服务端命令处理](../../../server/controllers/drone_controller.py)也确认：`MOVE_TO` 要求 hovering/flying/moving；`TAKE_OFF` 接受 idle/ready，再检查电量、最大高度和起飞位置冲突。这支持下一轮单独检验按状态决定合法动作的候选修复，不能据此断言起飞一定成功或整题会通过。

本次只记录该状态契约缺口，不修改初态、自动归零高度、执行准备起飞或改变搜索算法。

证据：[请求 198/199 所在日志](run-20261023-01/trials/24ac1838-entry_contract_v2/public-api.jsonl)、[最终结果](run-20261023-01/trials/24ac1838-entry_contract_v2/result.json)。

## 5. 保留什么、下一步先做什么

1. **入口与终止契约作为 opt-in 候选保留，默认 legacy 不变。** 本轮支持可靠空观察能启动有限搜索、终止控制明确且无重放；不支持启用默认或投入大批在线任务。先处理上述公开状态和任务执行缺口，明确是否值得额外功能验证，不为追求本组通过而修改原任务。
2. **v7跨任务保真在独立批次补验。** 既有R3审计的14道局部合法路线已按原文和公开回执回放，369个读取点两版逐字一致，但原任务compact资格0/14，只支持回退兼容。另列合成探针检验压缩语义；见[独立报告](../execution-memory-v7-cross-task-20261023/REPORT_CN.md)。这些未参加v7原六场景验证，但不是项目从未看过的盲测；几何局部合法也不等于全程可执行。
3. **R3补点增益保持低优先。** 已有34题筛查没有“完整合法且历史基线漏点”的干净整题候选；仅三个局部叶检查可作为可达性/缺口诊断。不能把不可行航点反复重试，或把基线原本能完成的合法路线写成R3救回。

本入口契约批次不包含v7回放，也没有R3在线扩展；两类验证的分母分别记录。原360次不续：旧40次没有真实paused机会或A/F差异门控事件，技能动作仅12/2372；新验证又显示入口打开后原搜索仍不能完成三个代表问题。继续原冻结大队列的主要信息收益仍不明确，且旧外推约14.55亿token、13–15小时只是有不确定性的规划估算。下一次应围绕明确缺口单独定范围，不能将新代码结果拼入旧40次。
