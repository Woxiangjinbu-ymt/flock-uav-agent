# M1 修改方向与研究证据

2026 年 10 月 6 日。建议：**停止扩大冻结 M1 v1；下一版 M1-R 保留现有事件账本，重点补上“任务相关、跨无人机可复用、作用域明确的不完整执行证据”，并以稳定前缀、按事件追加的方式提供给原 Agent。** 不再把通用实体摘要作为主要方法，也不把“发现后忘记交接”当成已证实的主因。

最有价值的新证据是：一些目标虽然没有进入感知黑板，但较早的合法动作回执已经明确报告某架无人机到达过它。当前实现没有把这种“知道存在，但还不知道 ID 和精确位置”的线索带到后续任务。下一阶段先验证这种证据能否被可靠保存、按当前义务读出，再增量验证它能否指导局部定位和指定执行者访问。**保存一个到达名称不是论文贡献；将不完整执行证据转成可检验的协作行动，才是候选贡献。**

本轮完成已有 fast100 全部 100 题的离线审计、22 道 M1 失败题的检查拆分、跨任务回执追溯与相关工作核对。没有新模型调用、仿真重跑、重新评分或方法代码修改。冻结 M0/M1 和原验收报告均保留；后文设计及验收阈值是供下一轮冻结的建议。

## 三个问题的直接回答

| 收窄的问题 | 研究判断 | 下一步修改 |
|---|---|---|
| 状态是否直接服务剩余任务 | 目前不是。实体关联不等于指定执行者的待办；unresolved 又混合了毫无线索和已有名称级到达报告 | 用原文中的执行者、目标、动作组成任务查询；把未知、仅有报告、已定位和执行结果分开 |
| 主动注入是否值得 | 每步动态 system 摘要带来严重缓存退化，当前没有成功率收益；不能只靠增加状态文本 | 保留旁路记录；固定 system；仅在相关证据变化时追加一个有界任务投影，保存实际注入正文与哈希 |
| 共享发现到指定执行能否成为论文机制 | 在当前 fast100，“发现后没有分派”缺乏足够证据；更具体的缺口是动作反馈已经提供线索，却未成为后续可用知识 | 将主假设改成“不完整协作证据的保存、局部定位与指定执行”，先做表示，行动机制作为下一增量 |

这比最初的路线进一步收窄：不先做通用依赖图、全任务验证器、反复尝试控制或统一预算调度。它们未必无用，但目前的证据不足以支持同时引入。

## 实验事实与新的失败拆分

完整验收结果为 M0 80/100，M1 78/100，W=2、L=4，净减 2 题；检查为 556/605 与 535/605。M1 总 token 增加 7.05%，逐题评分就绪时间之和增加 5.62%，输入缓存命中率从 94.50% 降至 6.06%。详见[原验收报告](../m1-progress-fast100-20261006/REPORT_CN.md)。

历史 B0 在相同 fast100 题目上的首次部署口径为 70/100，其中有 6 道终止服务错误。历史 B0 的并发、日期和服务条件与本轮不同，因此可以作为背景，不能据此将 M1 相对 B0 的差值当成新增机制收益。当前要解释的是同轮 M1 相对 M0 的变化。

按本次原文规则归组，22 道 M1 失败由以下任务构成；这是描述性归组，不是互斥根因判定：

| 马拉松航线 | 7 | 1 | 1 | 大量坐标访问失败，并非 M1 引入的新退步 |
| 三角编队 | 3 | 0 | 0 | 有明确终点障碍拒绝，不能当作记忆必然可修复 |
| 坐标巡逻 | 2 | 1 | 1 | 两版均有航点缺失 |
| 全局进度任务 | 7 | 4 | 4 | 全局目标分母、定位和历史承接问题仍在 |

| 显式目标访问等任务 | 30 | 25 | 24 | 搜索、到达与照片混合 |
| 多机目标扫掠 | 5 | 5 | 3 | 本轮最明显的退步类型，但只有 5 题 |
| 其他任务 | 43 | 42 | 43 | 包括本轮四机编队的一个改善 |

70 个未通过检查中，坐标到访 29、终点位置 3、着地 1、指定机到达目标 14、目标照片 3、任意机到达目标 3、全局进度 3、定向距离 14。定向距离的 14 项都集中在一题 `20742d37`，不能写成 14 个独立的协调失败案例。

对 20 个未通过的目标相关检查，最终账本中 **16 个对应 unresolved 目标，4 个对应已绑定目标**。这不是成功率归因，而是信息条件的拆分：

- `ba8b14f3` 的两个失败检查：原文要求 Waypoint 1，模型改为对 Polygon Target 5 做覆盖，原任务两个指定到达检查未完成。模型知道原名，却进行了未经任务授权的目标替换。更准确的任务查询可以暴露偏离，但不能自行解决原任务“waypoint 与区域覆盖”的规格疑义。
- `5aa74653` 的另两个已绑定失败：Drone 2 对 Fixed Target 7、Drone 26 对 Fixed Target 12 都已经实际发起正确方向的导航。回执分别多次 blocked/partial；这不是简单的“发现后忘记交接”。禁止它们结束不会自动找到可行路径。
- 四个 L 全都至少含有一个 unresolved 任务目标。当前证据不支持把退步统一归因为任务义务遗忘。

所有 20 个 unresolved 名称引用，均未在当前题工具返回中出现对应的结构化 `id+name` 对象，也不在前一题或本题结束时的持久感知黑板中。因此没有发现“当前工具已经返回完整实体而 M1 解析器漏掉该实体”的证据。但这仍没有覆盖文字动作回执，必须继续检查下一层。

## 新发现 动作已报告到达而感知黑板仍然未知

现有黑板主要收集附近实体；M1 通过 `id+name` 建立实体绑定。动作回执可能只说“到达了某目标”，没有给目标 ID 或坐标；M1 把完整回执存在本题 events，却没有把名称级线索提取成可跨题检索的知识。新命令又会重建任务账本，只继承结构化黑板。

本轮按场景原任务顺序扫描全部 100 题，只提取真实工具回执中的 `Reached target(s):`，不把用户指令、模型总结或失败查询当证据。发现：

- 16 个 unresolved 目标名称引用分布在 10 题，其中 8 题失败、2 题成功。
- 其中 **7 个引用、5 道题**，在更早任务中已经存在合法到达报告；涉及 5 个目标名称、2 个场景。
- 这 5 道后续题中，**3 题失败、2 题原评分成功**；不是 5 个可追回失败。3 道失败也可能还有其他未定位目标或导航困难，不能预估为必得 3 分。
- 当前题自身没有找到这 16 个 unresolved 目标的同类到达报告；这里的缺口主要是跨题知识承接。

| 后续任务 | 仍未绑定的目标 | 已经存在的较早合法回执 | 后续结果 |
|---|---|---|---|
| `823c15d5/13a30905` | Fixed Target 75 | `ce97a68d/e167` 的 `move_to_and_sense` | 两版均失败；另有 Target 28 缺口 |
| `823c15d5/9e46da10` | Fixed Target 19 | `c6e28e3b/e60` 的 `move_towards` | 两版均失败；另有 Target 97 缺口 |
| `35ce64d8/20742d37` | Fixed Target 10、11 | `b1ad4f3e/e84`、`de294a89/e39` | M0 成功、M1 超时失败 |
| `35ce64d8/2ca9bc1c` | Fixed Target 4 | `b1ad4f3e/e121`、`e215` | 两版均成功，有历史到达承接 |
| `35ce64d8/1905e0ad` | Fixed Target 10、11 | `b1ad4f3e/e84`、`de294a89/e39` | 两版均成功，有历史到达承接 |

最清晰的例子是 `20742d37`：较早的 Drone 3 从已确认位置 `(0,40)` 导航到 `(200,40)` 时，底层返回同时到达 Target 10、11；另一题的路径回执再次报告到达它们。之后五机任务要求 Drone 13、Drone 7 分别访问这两个目标，账本仍显示 unresolved，Agent 还用名称作为 ID 查询并得到 404，随后大量搜索直到超时。

可以合法保留的结论是：“先前 Drone 3 的某段实际运动报告接触过这两个名称的目标，存在可追溯的搜索线索”。不能把 `(200,40)` 当成两个目标的中心，不能凭到达名称制造 ID，也不能把 Drone 3 的历史到达充当 Drone 13/7 的本题完成证据。

平台实现解释了这种差异：目标到达会沿运动路径检查；感知复合工具通常在动作结束位置读取附近实体。所以无人机可能途中触及目标，终点感知却看不到它。**实际访问、获得名称线索、感知到可定位实体是不同事件。** 即使工具名含 `and_sense`，也不能假设已感知沿途所有目标。

两道原评分成功的例子进一步说明限制：后续 Agent 仍称这些目标不存在，但原检查因历史 reached 而通过。我们保留原成绩；更准确的报告或内部状态在这两题上没有新增成功空间。该现象只用于解释作用域，不能通过收紧评分制造方法收益。

这条新证据改变了修改优先级：相比扩展一个通用剩余任务图，先把已有合法动作证据保存成可用于目标定位的线索，更具体、可复现，也更容易设计消融。它尚未证明跨场景普遍性，更不等于已经证明该机制提升成功率。

## 文献约束与创新边界

本轮核对论文原文的方法、失败分析或结论。以下工作提供的是相关能力与边界，不是我们方法有效的外部证明。近期 arXiv 工作按预印本看待，不假定已被同行评审。

| 工作 | 已经做到或明确指出什么 | 对本项目的约束 |
|---|---|---|
| [MultiUAV-Plat](https://arxiv.org/html/2606.31073v1) | 剩余问题包括目标定位、最终条件和协同执行；未来工作包括更强定位、消融与更多后端 | 选目标定位有原论文依据；单纯复述观察、记忆、规划闭环没有差异 |
| [Statler](https://arxiv.org/html/2306.17840v4) | 显式世界状态及独立 reader/writer | “引入结构化记忆”本身不是新贡献；本项目也没有必要复制额外 LLM writer |
| [ReAcTree](https://arxiv.org/html/2511.02424v1) | 子目标树、控制流、共享工作记忆；仍有搜索与错误分解问题 | 任务分解和共享黑板已经充分研究；完整树会扩大实现与消融负担 |
| [LiP-LLM](https://arxiv.org/html/2410.21040v1)、[DART-LLM](https://arxiv.org/html/2411.09022v1) | 多机器人任务依赖、分配或并行执行 | 不能将“执行者—目标—顺序图”单独包装成新的协作算法 |
| [DoReMi](https://arxiv.org/html/2307.00329v3) | 生成约束，并通过感知检测计划与执行不一致 | 验证和恢复已是成熟主线；引入通用 verifier 需要独立证据与对照 |
| [Mimir](https://arxiv.org/html/2608.04933v1) | 世界记忆与任务记忆分离，将证据绑定到活动目标；指出不可见目标不会凭记忆产生 | 与通用 M1 任务账本高度相邻。我们的候选差异应在不完整动作证据的跨执行者复用及主动定位，而非两份 memory |
| [Beyond Memory / PoS](https://arxiv.org/html/2610.01415v1) | 分离知识缺口与执行缺口，验证 belief，并检测停滞以恢复 | “区分不知道和没完成”也不是新颖性；其维护成本与执行能力边界值得吸取 |
| [COOP²](https://arxiv.org/html/2603.00349v2) | 以空间、时间、参与和依赖约束观察协作，并触发定向修复 | 不能宣称首次将协作与任务进度关联；本项目单 LLM 控制多 UAV，也不能冒充去中心化多 LLM 系统 |
| [AeroWeaver](https://arxiv.org/html/2609.18520v1) | 技能激活、机体局部协作与角色经验复用；未来工作偏向长期迁移和实体机验证 | 不复制其多 LLM/技能学习架构；当前资料也不能支持我们有跨任务策略学习 |
| [The Unreliable Progress Bar](https://arxiv.org/html/2609.08589v1) | 模型的进度自报随阶段而变化，不能仅据自报控制流程 | 提示中的 done 与实际证据分离，不由模型一个完成标签强制停走 |

上述比较支持一个较窄的研究问题：**在局部感知的多 UAV 执行中，动作回执提供的局部、历史、执行者相关线索，能否在不获得全局地图的条件下，被另一任务的指定执行者用于完成目标定位与访问？**

尚不支持的创新主张包括：首次任务 memory、首次证据 grounding、首次知识/执行缺口分离、首次协作约束、首次防止重复搜索。没有找到完全等同的实现不构成“首次”的证明。

若最终只实现一个 `Reached target(s)` 正则和更短提示，应按领域适配改进看待，不能强行扩写成新 harness。要形成论文机制，必须给出可迁移的证据类型/作用域、线索到定位行动的规则，并证明比等信息量的静态提示或普通记忆更有帮助。

## M1-R 的最小设计

### 保留原账本 增加两种清楚分工的视图

保留 M0 工具与主模型循环、M1 对原回执的记录和引用。新增一个 session 级动作证据索引，与每次命令新建的任务义务视图连接。跨任务只共享环境知识和历史事件，不能继承上一任务的 done 标签。

任务视图先支持明确指定的无人机和目标访问关系；照片、后续定向动作保留为关联原文与待办，不第一轮就实现全语义 verifier。简单坐标/悬停等任务没有相关线索时保持原流程。任务解析器只读用户原文，不读 task_id、任务模板名、检查树或隐藏世界；歧义保留 source span，不猜执行者，不阻塞原 Agent。

| 字段 | 用途与边界 |
|---|---|
| `source_span` | 原文要求，可追溯；范围提取失败时回退原文 |
| `required_actor` | 指定执行者；与线索提供者分开 |
| `target_name / target_id` | 名称可以有而 ID 仍为空；不把名称直接塞进 ID 接口 |
| `knowledge_state` | `unknown / reported_only / localized / ambiguous` |
| `execution_state` | `unattempted / attempted / partial / blocked / evidenced`；不是终止裁决 |
| `evidence_scope` | session、command、actor、工具调用和完成顺序，区分历史事件与当前状态 |
| `localization_hint` | 可核对的已执行路径片段或较弱的相关区域线索；不伪装成目标中心 |
| `remaining_clause` | 未满足的原义务；错误目标、换执行者和近似替代不会自行消除它 |

`reported_only` 是这次最值得补的状态。当前 unresolved 不能告诉模型“毫无线索”与“有历史名称报告但尚未定位”的差别。name-only receipt 不升级为 localized，更不升级为 required_actor 已完成。

不把一个单焦点锁住整队；每个明确执行者可以保留自己的待办。仅依据原文明确顺序记录依赖，不额外推导“所有无人机必须统一完成前一步才能做任何动作”的全局屏障。

### 从动作回执提取最小证据

先支持可靠的现有输出类型：结构化 nearby 实体、明确成功/部分成功动作中的到达报告、可核验的实际成功路径点、指定无人机的局部观测。错误信息中出现名称、模型文字“我已经完成”和请求参数中的目标不算新发现。

历史事件与当前位置分别更新：到达过某目标的报告在移动后仍是历史；无人机现在的位置要被后续运动更新或标记未知。同机并发动作顺序不清时，不生成确定路径或确定完成关系。移动目标的旧路径仅是过时线索；第一版局部定位机制限定静态点目标，不泛化到运动目标和区域覆盖。

路径线索必须保留真实执行边界：完整路径以成功点为准；partial 只用确认完成的前缀；规划出来但未执行的 waypoint 不能缩小未知目标的范围。名字报告可证明“沿此动作发生过接触”时，只形成路径附近的定位候选，不据此算出精确中心。未知目标大小或三维条件不明时，不宣称确定的几何覆盖保证。

跨任务索引限定同一 session；场景重置、隔离运行或更换环境后清空。它不读取其他方法的结果，也不从磁盘离线世界快照加载知识。

### 模型只看到当前义务相关的投影

模型视图优先包括：指定执行者与目标、尚未完成的动作、有用的最新局部证据、仅有到达报告的定位线索、最近一次相关动作的结果。无关无人机和没有当前用途的历史先不注入。

建议第一版最多 4 个活动条目，总量不高于原 4,000 字符预算；条目不足时不填充无关状态。超过预算时保留明确省略计数和原任务全文，不能把展示子集写成任务全集。4 个条目是待离线冻结的实现上限，不是经验最优超参数。

例如对上述五机任务，投影应表达：

```text
要求：Drone 13 访问 Fixed Target 10。
定位：仅有历史到达报告，尚无目标 ID/精确坐标。
线索：较早 Drone 3 的确认执行路径报告接触过该名称；引用原回执。
本题执行：未获 Drone 13 到达证据。
后续原文：全队目标访问之后的定向移动仍保留。
```

这段内容不能声称 Drone 13 已完成，也不能说该目标不存在。若后续仍无法定位，保留未决状态，允许原模型继续搜寻或给出诚实的未完成结果。

### 注入必须保护历史前缀

DeepSeek 官方文档要求请求匹配已持久化的完整前缀单元；共享前缀可以被后续复用，实际命中还受缓存持久化机制影响。当前 M1 在 system 内反复改变早期内容，很可能阻断后面长工具历史的重用。[官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache/?trk=article-ssr-frontend-pulse_little-text-block)

下一版固定 system 中的规则与 schema，把任务初始化视图只写一次。工具批次结束后，仅当相关状态变化时，把派生证据附加到新产生的真实工具消息，写入后不再修改旧消息；原始回执仍完整单独保存。不要伪造没有 tool_call 的 ToolMessage，也不要在同一并发批次尚未结束时作全队完成判断。

**仅把每轮临时摘要搬到上下文末尾仍不够**：如果下一轮删除旧摘要，前缀仍会改变。需要验证的是“旧消息保持逐字不变，新事实仅追加”的性质。历史增长有成本，第一版用事件触发和上限控制，不同时引入滚动压缩；若以后压缩，应独立记录前缀重建边界。

离线可检查消息序列、共同前缀长度、并发完整性和注入次数，不能据此声称实际服务端缓存已经恢复。新在线实验必须记录每次真实序列化请求的哈希、注入文本、输入/输出及 cache hit/miss usage。现有遥测未保存请求正文，94.50%→6.06% 的因果解释仍待对照确认。

## 唯一建议的后续行动增量

M1-R 先做到信息正确、可读。若它通过基础验收，M2 只增加一个机制：**当必需目标处于 reported_only 时，利用历史执行路径线索请求一次有界的局部定位；获得真实实体后，再把目标交回原文指定执行者。**

这一步利用现有导航与感知工具，不替换 M0 路径规划器。候选区域来自实际回执和合法观测，不能用隐藏坐标。选择线索提供者或当前附近的空闲无人机做定位，需要看当前合法位置和电量；该无人机的“发现工作”与指定执行者的“完成责任”分开。原文指定访问者不能因为另一架更近就被偷偷替换。

初始机制只做有限候选路径上的定位，不做通用全地图搜索优化。不把 repeated call 次数作为失败判据，不新增硬超时或硬重试屏障，也不从线索不存在推断目标不存在。定位成功后停止这项补充搜索；定位未成功则携带结果回到原循环，不能进入自锁。

这是后续候选机制，尚未实现和在线验证。它对已有两条合法接触线索的 Target 10/11 比对纯未知目标更有依据；对从未出现任何线索的目标、严重障碍导航、任务坐标冲突，并没有承诺收益。

## 分阶段验收与累计关系

冻结 M1 v1 是负向研究版本，不能因为版本号要求而强行沿用它的有害注入。累计关系应理解为“保留 M0 和有效证据层、新增可关闭能力”，不是永久保留每个失败设计。新版本名与配置独立，关闭新增模块可以回到对应父版本；不移动旧标签。

| 阶段 | 新增范围 | 可单独验收的证据 | 退出条件 |
|---|---|---|---|
| A 离线设计验收 | 原 ledger 上增加 session 证据索引、reported_only、任务相关读取；验证稳定追加消息 | 原 100 题回放、未曾观测/仅报告/精确定位/错误主体/部分路径/同机并发反例；固定前缀与原工具动作不变 | 误造 ID/坐标/完成证据，或误阻塞动作，立即停止；本阶段不报告性能提升 |
| B M1-R 在线筛查 | 上述状态作为有界建议进入原循环，不自动接管行动 | 同批 M0、静态提示对照、M1-R 的完整 fast100；原分母、W/L、逐场、时间/token/cache | 仍退化则回退；只比旧 M1 好而不优于 M0，不能算主效果 |
| C M2 行动增量 | M1-R 加仅针对 reported_only 的局部定位及指定执行者衔接 | 相对 M1-R 的累计 W/L；新增成功轨迹必须经过线索→定位→指定行动 | 没有整任务收益，或收益仅来自历史 checker 承接，不扩大 |
| D 冻结验证 | 只带晋级版本进入 dev240，再确定最终确认/跨模型范围 | 预先冻结成本与次数；场景层变化与必要消融 | 开发增益不稳定则收缩论文主张，不继续堆 M3 |

B 阶段的最低可解释对照：

1. **M0**：冻结底座。
2. **M0 + P**：同一组固定提醒，要求区分发现、定位、指定者完成，保留原工具历史；无跨题动作证据索引。
3. **M1-R**：同样的固定提醒，加持久证据及任务相关投影。

M1-R 与 P 的差异包含信息保留和读取，不足以单独证明每个内部结构都有用。只有主结果值得继续时，再做最有解释力的一个消融：保留同类条目与注入接口，但去掉跨任务动作证据。若要专门主张“结构比普通记忆强”，再加等信息量的简要历史回执对照。不要一开始运行全部组合。

缓存策略也需隔离验证：先对冻结事件使用同一摘要内容比较旧 system 注入与新追加序列，做无模型的结构测试；必要时再授权短的服务端缓存探针。若未做独立在线对照，只能报告总成本差异，不能给缓存修复单列因果收益。

建议将主方法进入 dev240 的开发门槛预先设为：相对同批 M0 完整配对净增至少 3 题、至少两个场景有正增益，并能排除主要增益仅为历史评分承接；任务时间和总 token 若超过 M0 的 110%，需明确收益是否足以承担成本。该数值是资源分配门槛，不是统计显著性标准，也不是已经获批的实验协议。若状态层持平但功能可信，可只作为 M2 的基础暂留，不能独立宣称论文贡献。

fast100 仍为开发集，只有 5 场；所有方法保留每场 20 题原顺序，世界和黑板承接。同 task_id 不等于相同动态起点。新比较应均衡方法执行顺序，并保存题前状态；不能为挑选有利题而只跑这些失败。dev240 包含 fast100，不能把二者当独立样本相加。

为控制工作量，A 阶段建议设 1–2 个开发日上限；只完成表示、回放和模型输入适配。若还需要全语言合同编译器、完整任务 checker 或新导航器，说明范围已经失控，应停下重新定界。B/C 是用户另行决定的付费实验，本轮未启动。

## 六页论文应讲什么

候选主线是：**协作过程产生的执行证据不总是完整地图观测；若没有明确保存证据的知识等级、执行者和时间作用域，后续任务可能把已获得线索当成未知，或把他人的历史完成当成本题完成。通过任务相关证据读取与有界定位，将线索转成指定执行者的实际任务进展。**

候选英文题目可暂为 *Action Evidence Reuse for Partially Observed Multi-UAV Task Execution*。名字不先承诺通用多 Agent、最优调度或学习能力。

论文贡献最多两项方法内容：作用域明确的不完整协作证据表示；利用该证据进行定位与指定执行者衔接的单一机制。实验完整性是第三项支撑，不另包装“缓存算法、重试算法、验证算法”。缓存修正放实施/成本说明。

原任务成功率是主指标，完整 W/L 为核心解释；时间、token 和 cache miss 为成本约束。只选一个机制诊断：在报告型线索存在且本题有指定目标要求的样本中，是否出现可追溯的“线索→新定位→指定执行”链，并回到整任务结果。适用样本用合法运行证据定义，不能看最终成功再选；事件链不单独替代主分数。

最小论文证据应包含 M0、固定提醒、M1-R、M2，以及一个去掉关键证据来源的消融。Mimir 等相邻工作要正面讨论；若不实现同协议复现，只能列机制差异，不能将其原论文数字与我们的 fast100 数字横比。若只有 M1-R 的表示正确、成本恢复而成功率没有改善，这还不足以支撑当前目标论文。

对旧《改进意见》的处理是：通用去重、无效重试限制、预算预测、多级 verifier 暂不做。保留“既有信息能否服务剩余任务”的主旨，把减少盲搜视为该机制可能带来的结果，不作为第二篇效率论文展开。M3 也不在当前必要清单中。
