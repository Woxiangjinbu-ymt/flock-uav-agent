# R2 观察工人：独立在线前缀试验

2026-10-09。结论：**本轮没有观察到任务收益**。新鲜 R2 对照与 R2＋观察工人均为 **11/12 题全通过、42/44 项检查通过、0 超时**，逐题 0 胜、0 负、12 平。观察工人只在一题实际出动；它完成 3 次感知移动，但没有定位缺失目标，该题最后由指定无人机自行完成。该结果不支持把当前工人写成已验证的成功率或速度改进。

## 问题与试验边界

前一轮 [离线 shadow 回放](../../audit/m1r2-observation-worker-shadow-20261009/REPORT_CN.md) 在旧 R2 的 100 题轨迹中，以“指定无人机连续 8 次完成感知移动却未获得新目标证据、无其他动作无人机、至少留 180 秒”为条件，只暴露了两道当时失败的题：`529c0622` 与 `22e1e1c5`。本轮只在线测试这个规则和一个最多行动一次的观察工人；没有加入 R3、航线监视器、快捷移动或 600 秒政策。

每组加载原始完整场景 JSON，但只按原顺序执行到候选题：场景 `ad34350a` 前 7 题、场景 `35ce64d8` 前 5 题，共 12 题、44 个原检查。每组分别从原始场景状态开始，场景内世界状态与 blackboard 按原执行承接。沿用上游 500 秒任务窗口、原检查器、同一模型别名与配置；两场景并行，同一组内不重试，两组按对照、工人顺序运行。候选题和阈值来自开发轨迹，所以这是机制可行性试验，不是无偏泛化测试。

冻结包的源码哈希核对表明，两组仅有 `agent4drone/uav_agent.py` 的可关闭接线差异，以及工人组新增的 `agent4drone/observation_worker_r2.py`；服务端、控制器、评分器及其他 agent 文件一致。工人只读取公开工具回执，一次性规划最多 3 个探索点，目标定位只接受真实感知或移动回执；原主 agent 保留原工具集。冻结运行时离线检查通过。第一个 v1 尝试在本地沙箱拒绝端口绑定时于服务启动前中断，**0 题评分、0 模型调用**；记录保留在 [v1 试验目录](../../../experiments/m1r2-observation-worker-prefix-v1/)。以下结果均来自新编号 v2 的各组首次可评分尝试。

## 工人究竟做了什么

在 `22e1e1c5` 的工人组运行中，指定 Drone 11 对 Fixed Target 9 仍缺位置证据，连续 8 次完成感知移动后约 **76.3 秒**触发一次。工人先枚举无人机并读取各机局部感知，再调用模型选 Drone 10 和 3 个探索点，实际完成起飞与 3 次 `navigate_to_and_sense`。工人记录为 `searched_without_localization`、`localized_targets=[]`。后续 Fixed Target 9 的访问证据来自**指定 Drone 11** 的 `navigate_to_and_sense` 回执 `e111`，并非工人回执；原检查 2/2 通过。

独立工人模型调用的监测事件显示 **41.866 秒、11,005 tokens**（输入 1,877，输出 9,128）。该题主 agent 完成时间从对照的 **170.4 秒**变为工人组 **331.0 秒**；两条轨迹的模型采样与动作不同，**160.6 秒的差值不能全部归因于工人**，但 41.866 秒是可直接归属的额外模型等待。`529c0622` 工人组未触发，仍为 4/4 通过（对照 305.2 秒，工人组 311.0 秒）。

工人没有提供可用的新目标位置，也没有贡献指定 actor 的访问证明；它当前唯一已证实的效果是一次额外模型调用和三次探索移动。即便这次没有造成评分回归，场景中临时多动一架无人机可能影响后续任务，因此完整 100 题部署仍需另行检验。

## 研究判断与下一次单变量试验

当前证据支持保留“停滞时才考虑额外观察”的**选择性触发机制**，但不支持保留现版“再让一个 LLM 临时猜 1–3 个探索点”作为有效模块。最直接的下一个单变量测试应固定触发规则与 R2，其余均不动，只把工人的 LLM 选点替换成利用公开已知位置和历史覆盖的确定性、限时选点；若离线仍无法提供新位置，就不应扩大到 100 题，也不应在论文中声称多 agent 带来成功率提升。后续应另选未参与阈值选择的新场景，防止继续在同一开发集上反复调参。
