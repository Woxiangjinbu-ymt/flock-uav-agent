# 教师轨迹的调用与工具回执核验

每场按冻结清单保留 20 个槽位。脚本只读本机已落盘的原始字节。正式输出要求工作进程及独立评分进程均已封存，逐件校验使用过的助手归档、工具跟踪、模拟器记录、传输请求和回复的 SHA-256。每题均列出终止原因、SDK 归档状态与明细。提前触及请求上限的题仍在分母中。

1. **助手生成。** 每次已派发且返回的 HTTP 原始回复，与 SDK 归档里的回复字节逐字节比较。再逐项比较助手正文、思考文本与有序工具调用的 ID、名称及参数。保留回复摘要、正文及思考的长度和摘要。若本地限额阻止派发，登记本地停线原因，不计作教师生成。
2. **公开接口 C。** 在每份实际请求中核查感知工具的说明摘要及可选参数结构。仅对感知调用的空参数对象，按 C 规则将执行参数解释为 `{"input_json":{}}`。分别统计原始无参、显式空对象及其余形式。实际回执的感知机号按 ID 与公开 `GET /drones/{id}/nearby` 比较。教师省略选机时，进一步对照同次调用的公开编队列表。记录回执所含黑板的摘要，省略黑板的请求依据实际参数判断。错误回执仍纳入归属检查。
3. **回执归属。** 原始 DeepSeek 工具调用 ID 连接到该助手轮的工具启动记录、该跨度的工具返回及真实后续请求中对应的工具消息。逐条对照后续历史中全部既往助手轮与回执全文，并校验可定位到同一公开任务跟踪的证据注记。按 ID 和作用域匹配，允许多工具回执倒序。对每个回执分开记录已派发的后续请求、仅出现在本地拒发请求中的历史及没有后续请求。工具不一定使用模拟器，黑板内部操作单列为无公开模拟器请求。
4. **动作和事件。** 保留每个调用关联的模拟器请求 ID、端点、动作和提交标志，以及该请求产生的事件 ID。检查每个模型动作有相应调用，每个模型事件的原始调用 ID、名称、请求 ID 和提交状态与其动作请求相符。预定义子程序另按计划 ID、教师控制调用、内部子调用与证据 ID 追踪。逐条校验子调用回执摘要；子调用与公开请求具有相同数量、工具和动作顺序时才记录单一的顺序映射，其余保留匹配候选。独立评分负责判定任务完成。
5. **计数单位。** “多调用”表示同一助手消息同时提出多个调用。按调用顺序与实际工具返回顺序比较是否倒序，此项不测量执行区间重叠。按题区分相同工具和参数的重复尝试、原始 ID 重复、回执 ID 重复，以及缺启动、缺回执、缺历史承接。完整生成数按实际收到的助手回复计；整题 SDK 归档是否完整另列。训练适用性另由逐轮审阅决定。

在首场第 1 题的临时副本上，分别注入重复回执 ID、删除工具结束记录、改写动作事件的原始调用 ID。脚本分别定位到重复 ID、缺失结束记录和事件归属错误。

在项目根目录按场复算，替换 `SCENE` 为 `04cd6269` 或 `ef36e27a`。

```sh

  --scene SCENE \
  --output outputs/deepseek-teacher-pilot40-live-20261111/audit/tool-receipts-SCENE.json
```
