# 两场教师试采的逐轮审阅

本次试采沿用冻结题序。每个场景以 20 个题位为分母。场景 `04cd6269` 已用于连续会话开发，`ef36e27a` 的 20 题均在历史 main300 中。两场的示范、逐题归因和逐轮取舍均限 A 折训练侧。以 B 折训练时应隔离这些材料。[冻结题单与暴露记录](../../specs/04-deepseek-pilot40/pilot40.json)

1. 每场独立评分封存后，核验原题序、场景检查点及工作器和评分器的文件摘要。逐题记录题初检查、终态检查、完整回复、工具调用与执行记录。未启动、未评分、服务失败、初态已满足和终态失败的题位都进入索引。
2. 对题初未通过、终态通过的题，逐项对照原指令中的对象、动作、目标与顺序。核对关联到本题决策的工具回执和实际提交的动作，检查终态结果是否由本题正确行动达成。漏执行明确要求、错机、错地点、缺少可归因行动或仅有完成宣告的整题保留原分数，单列剔除理由。
3. 在上述合格轨迹中逐轮审阅。保留推进任务的动作、支撑决策的观测或恢复，以及有公开回执支撑且符合原指令的最终回答。纯重复查询、无进展动作、无根据宣告、未证明来源的回执、截断和超出学生上下文的轮次分别标记。到单题预算上限时，按此前已经收到的完整动作回执逐题归因，停线原因仍记入索引。单轮有多条并行调用时整体取舍，保持原动作组。
4. 每个保留轮从该轮的原始公开请求重建同一学生输入，归档来源与筛选证据留在单独索引。分别导出含教师思考和移除当前思考的目标，核对两版的消息、工具及全部动作相同。此前已出现在公开对话中的历史思考在两个版本中相同，全部随提示遮罩。沿用固定 Qwen3.5-2B 分词器，遮罩全部提示 token，逐轮验证结束符、工具参数回放和上下文上限。[开发样例验收](../deepseek-sft-dev-examples-20261109/REPORT_CN.md)
5. 事件只使用该轮调用前已出现并已按调用 ID 对齐的回执。按场统计所有可观测轮与最终入选轮的事件状态及事件类型，分别保留起始、无事件与无法判定的轮数。独立评分结果、原始轨迹、通过因果归因的题数和实际导出轮数分列。

本批不填补未获得的真实回复。首批可用条数以实际导出且通过双端点校验的决策轮计。若某题有正确行动但没有合格轮，单列记录该题。

## 复算单场

在仓库根目录运行下列命令。将 `scene_id` 换为另一场景 ID 可复算第二场。默认只读取真实 DeepSeek C 接口的封存文件，输出目录须位于运行目录以外。若只指定运行目录、输出目录和场景，脚本输出待审题位索引；传入对应场景的逐轮取舍文件后才生成两套监督数据。[离线生成脚本](../../../scripts/review_teacher_pilot40.py)

```sh
export PYTHONPATH=scripts:.
export HF_HUB_OFFLINE=1
pilot=outputs/deepseek-teacher-pilot40-live-20261111
scene_id=04cd6269
training/.venv-input/bin/python scripts/review_teacher_pilot40.py \
  --run "$pilot/run" --scene "$scene_id" --output "$pilot/review" \
  --review "$pilot/review/$scene_id/semantic-review.jsonl"
```

每场的 `episodes.jsonl` 记录 20 个题位、原题、独立成绩、终止原因与该题导出轮数。`decisions.jsonl` 逐轮记录原始请求和回复摘要、工具 ID、活动主体、回执定位、是否保留及取舍理由。`keep-reasoning.jsonl` 和 `remove-reasoning.jsonl` 以同一 `sample_id` 对应；`summary.json` 保存两个端点与审阅索引的 SHA-256。每个保留轮可用原始公开请求重建相同的输入与监督 token。末次本地请求因单题上限未派发时也有索引行，计真实回复和可训练决策时按对应字段排除。
