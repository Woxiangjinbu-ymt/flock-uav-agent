# M1-R 封存修复与三个退化案例复盘

日期：2026-10-07。范围：修复未来运行的资源遥测封存边界，离线复盘 M0→M1-R 的三个 L，验证候选机制能覆盖到哪一层。本轮没有付费模型调用，也没有启动、恢复或补跑实验。

**结论：封存竞态已修复并通过测试。三个 L 中，五机扫掠有明确的线索恢复切入点；95% 进度题能覆盖错误完成判断，但成功还依赖继续搜索；顺序访问题受前序状态和原评分范围影响，当前证据不足以用小幅记忆修订覆盖。不能承诺修完三个机制就变成 84/100。**

## 1. 封存修复与旧结果边界

旧 M1-R 全部 100 题已计分，观察值 81/100，历史 M0 为 80/100，W=4、L=3。但整轮终态仍为 `aborted/interrupted`，不是 `completed_and_verified`。本次没有改状态或重新签发原 seal。

问题发生在 `ResourceMonitor.stop()`：等待后台采样线程超时后继续返回，后台采样日后返回仍能向文件追加。ef36e27a 在 22:06:51 封存，23:13:17 又多出一条资源采样记录。该条记录的进程列表为空，未改任务答案、模型用量或评分，但确实破坏了原场景哈希。

当前工作区修复：

- `EventWriter.close()` 与 `emit()` 使用同一把锁，等待已经开始的写入结束，再拒绝后续追加；封存边界以关闭写入通道为准。
- `ResourceMonitor.stop()` 幂等。采样线程等待超时时写入 `ResourceMonitorStopTimeout`，避免再启动第二个同步采样，然后关闭 writer。正常退出仍保留最后一次采样。
- `monitor_stopped.sample_thread_exited` 明确记录采样线程是否退出。这里只保证 stop 返回后该 writer 不会再改文件，并不声称操作系统采样线程一定已经退出，也不保证所有磁盘 I/O 等待有硬时限。
- `reproduction_parallel.py` 只更新封存边界说明，任务执行、评分、预算和方法逻辑未改。

验证：13 项遥测单元测试通过，包含“采样延迟到封存后才返回”“关闭时仍在写入”“正常退出和重复 stop”。2 项本地执行器集成测试通过，覆盖多场景顺序与黑板隔离，以及篡改已完成证据后拒绝恢复。集成使用 fake agent，没有模型调用。

旧证据处理：再次核对终态快照 **1155 个文件全部符合其终态 suite seal**；五场原场景 seal 仍只有同一个资源文件不匹配，其他 963 个场景文件匹配。该资源文件的原前缀为 **1257 行、301794 字节**，哈希严格等于原场景 seal；后缀仅 199 字节、1 条资源记录。新目录保存两份派生副本和证明，原文件保持完整。这不是将原失败运行追认为验收成功。

前序三份报告的 9、8、8 个已哈希产物均保持不变。修复只在当前工作区；后续新实验需重新冻结包含修复的 runner，现存冻结 runtime 不受影响。

### A. 顺序访问：不能按一个独立的 M1 回归来归因

命令要求 Drone10 按序访问 FT59→FT55→FT31，并悬停拍照。原检查只有三个 `target_is_reached`，无 actor 参数、无 `since_timestamp`，也没有顺序、悬停或拍照检查。

- M0 开始时 FT55、FT31 已被其他无人机到达；当题 FT59 最终由 Drone27 到达。M0 超时但原评分通过。
- M1-R 开始时三目标均未到达；当题 Drone10 到达 FT59，FT55/31 没有找到，500 秒截止。场景整体已到达目标起点为 M0 58/100、M1-R 32/100。
- M1-R 截至该题的 8 份 observer 轨迹中，没有 FT55/31 的实体名称观察或正向接触回执；最终两项均为 unknown。71 个移动事件中 46 blocked、4 error，搜索和可达路径预算确实不足。

这里需要区分任务失败与比较归因：M1-R 未完成命令是真实问题；这一个 L 不能证明 M1 记忆直接破坏了本来已经完成的指定机顺序访问。原评分保持不变，只在解释中标注历史承接效应。

**覆盖判断：**保存或提取历史路径无法恢复从未观测到的目标。若继续处理，需要通用搜索覆盖/路径策略，并在相同任务前状态下比较；本轮不将隐藏坐标、目标编号缺口或画布尺寸当作 agent 已知事实，不为此扩张 M1 范围。

### B. 95% 任务：可纠正完成判断，但不能把提醒当成成功提升

M0 从 17/20 到 20/20；M1-R 从 16/20 到 16/20，没有新增独立目标。M1-R 最终答复承认 FT4、5、10、11 未找到，却声称“all discovered targets covered → session task progress at/near 100% (>95%)”。原评分返回 0.8。

该命令没有显式目标名，当前 `references()` 产生空列表，只有一份 items=[] 的投影。证据层没有表达“全体目标覆盖率 >95%”这一整体义务。

接口核查进一步发现：

1. 原服务端 `GET /sessions/current` 的 metadata 包含 `statistics.task_progress`，AGENT 角色可访问，无须调用隐藏 `/check` 接口。
2. `get_session_info` 在工具工厂内已定义，**没有加入返回的工具列表**；`get_task_progress` 也未注册给模型。冻结工具集的离线实例化确认了这一点。
3. 当前 agent 会为会话绑定调用 `/sessions/current`，但没有把完整进度反馈投影给模型。API 日志的 `response: {status: active}` 是 compact 记录，不能据此认定服务端只返回 status。
4. 使用冻结 `Session.to_dict(data=False)` 对 before/after 重建：两个时点都为 progress=80%、total=20、visited=16、unvisited=4；不含 targets/drones/history 等全量实体字段。重建 after 的累计接触次数因历史反序列化出现 124→123 差异，已记录；独立目标数、百分比和完成状态一致。此重建不冒充当时真实的模型输入。

**候选方向：**给整体覆盖任务保留带来源的阈值义务，将实际公开 progress 与 fresh/stale 状态接入；未知分母不能用已发现数代替；未达阈值时保留剩余搜索义务。沿用现有追加式上下文，避免每次重写前缀。可先使用已发生的会话读取建立初值，终止前的刷新必须明确计入调用与时间预算。

**覆盖判断：**可以检测这次“80% 却宣称 >95%”；离线不能证明随后一定找到余下四目标。注册工具或向模型投影新字段会改变冻结的观测协议，应独立冻结、单独归因，历史 M0 80/100 只能继续作为历史参照。

### C. 五机扫掠：最值得优先修订，但需要把线索用于动作

仅两个 actor-target 检查失败：Drone13→FT10、Drone7→FT11；其余 18 个原检查通过。任务开始时两目标已经由 Drone3 到达，但这不满足本题指定 actor。M0 起点已有全部 20 目标，M1-R 起点为 19/20，存在前序承接差异。

M1-R 的摘要已保留两条历史 contact report，标记 `reported_only`、执行 `unattempted`，原始消息中也有位置；`localization_hint` 均为空。因此问题同时包含线索结构化和线索使用，不能声称加一个正则就能保证成功。

前序任务 de294a89（四机扫掠）的合法回执：

- e51：Drone3 完成向南 79m，到达 `(154,36,18)`，报告接触 FT10、FT11。
- e53：Drone3 完成向北 88m，到达 `(154,124,18)`，再次报告两目标。

离线候选解析器只接受格式匹配、actor 一致、completed、无并发歧义、距离/方向一致的相对移动回执；从实际回执终点和已确认移动恢复出 `(154,115,18)→(154,36,18)`、`(154,36,18)→(154,124,18)` 两条线段。保留 session、command、actor、event、tool-call 来源及坐标舍入误差。4 项候选单元测试通过，并成功回放实际两条回执。

这些是**沿动作路径发生过接触的搜索线索**，不是目标中心，不自动赋值 target_id/position，不将 Drone3 的接触转成 Drone13/7 的完成。事后几何诊断显示 e51 终点到两目标中心均小于 50m；该隐藏坐标比较只用于解释线索的潜在价值，没有输入解析器，也不能替代真实导航与感知验证。

**候选动作闭环：**优先消费历史接触线段 → 用合法本地感知定位 → 由命令指定的无人机访问 → 保留尚未完成的义务。前序已访问线段也不能保证当前指定机可达，障碍、路径与预算仍需在线验证。

## 3. 建议的增量顺序与验收

| 阶段 | 增量内容 | 独立验收 | 当前状态 |
|---|---|---|---|
| S0 | 修复资源 writer 关闭与封存顺序 | 封存后迟到采样不能改变哈希；正常与异常退出、旧证据保护测试通过 | 已完成；待下次实验重新冻结 |
| M1-R 下一小步 A | 在现有证据记忆上补相对移动接触线索，并让未定位目标优先消费线索 | 回执来源/actor/任务边界正确；失败回执不造位置；真实案例可恢复线索；后续单独验证指定 actor 访问与成功率 | 离线原型与案例验证完成，未接入正式 agent |
| A 之后增量 B | 增加整体阈值义务与公开进度反馈 | 80% 不得判为 >95%；分母未知保持未知；旧反馈不当作当前完成；后续验证实际成功与成本 | 接口与离线数据已验证，未修改工具集或运行方法 |
| 后续研究候选 | 未知目标的搜索和可达路径策略 | 相同初始状态下的成功提升，且保留前两层能力 | 不在本轮实现 |

论文主线可继续围绕“保留任务义务，将历史证据转成下一步协作动作，并用可观测反馈约束完成声明”。封存修复属于可信实验基础，不作为算法贡献；未知目标探索不宜为了覆盖一个受历史状态影响的 L 而仓促加入。当前不建议直接进 dev240。先以小范围离线回放证明 A 的语义正确性，再由用户决定下一次付费成功率实验。
