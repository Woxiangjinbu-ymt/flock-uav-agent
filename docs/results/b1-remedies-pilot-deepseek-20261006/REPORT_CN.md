# B1 定向补救试点：中断后的证据与历史 B0 对比

本次实验中断，不能发布完整60题最终成功率。保留的原始计分证据支持 **57题已计分、50题通过、7题失败，另3题未计分**；历史B0在相同57题上通过45题。配对为44题共同成功、6题共同失败、6题新增成功、1题回归失败。计划分母仍为60，未计分题没有删除或补判。

**建议暂留当前版本作为候选版本。** 新增成功多于回归，且3道方向飞行题有明确的动作改善证据；但这既不是完整试验结论，也不能证明本轮每个新增工具都有效。没有自动回退、修改Agent、重跑或补跑。自动跟进已暂停。

前三题的动作证据最直接支持本轮“正确理解并执行方向航段”的补救方向。但对照是历史B0，当前版本同时含早期B1导航修改和本轮提示，不能把改善精确拆成某一行代码的独立因果效果。导航例也不能仅凭结果归功于某个新工具。

覆盖两题并未触发错误句柄恢复；原B0的问题主要是目标选错。`c451cd74`新版还有一次导航返回arrival_verified=false、距中间点约1.08米，模型仍继续执行覆盖并最终通过。这说明判断一次工具返回是否影响任务，应结合后续可执行动作，不能直接把局部未到位变成终止整题的门槛。

## 唯一回归与仍然失败的任务

回归`ad34350a/bfc721cc`由4/4变0/4：新版未发现指定Circle Target 3，覆盖为0，三架机也没有拍照。这是实际执行失败，不是更严格的内部标准扣分。

它的题前条件已经不同：B0黑板里有该目标且覆盖约22.38%，新版没有目标信息且覆盖0；三架指定机的题前位置则相同。向前追溯，B0在更早的第2题`64b6560e`的感知移动中已发现此目标，新版在回归题之前没有这条发现记录。因此不能只从本题分数判断是哪个新增模块造成回归，也不能把差异起点简单归为前一轮搜索超时。

新版尝试123次工具调用仍未找到目标，之后把名称`Circle Target 3`直接作为target_id查询并得到404。这个404只能说明该ID查询失败，不能证明目标不存在。它最后承认无法定位并请求信息，却仍发出`TASK DONE`。优先要解决的是从未知目标到正确实体的发现、名称与ID解析及搜索行动选择；仅让最终回复更保守不会补上覆盖和照片。

另6题共同失败：5题的指定位置被原服务明确拒绝为障碍内部（`95fef67d`、`018d1d05`、`f9868b0d`、`b2c116a1`、`18e35f9d`），1题`529c0622`搜索与绕障至500秒超时，记录305次API调用而没有拍照调用。前5题的证据说明服务拒绝了这些请求，不能仅凭模型自述推断所有合法策略绝对不可解；也不能擅自修改检查器或删除失败分母。

## 哪些补救尚未获得收益证据

- `move_within_distance`只有1次已记录调用：`fa30ebff`原距离约16.64米，已小于23米，因此没有移动。B0同题也成功。本轮不能证明距离纠偏能力带来了新增成功；原定向距离失败`82077301`、`0cb39a4a`本来就不在这60题内。
- 覆盖工具的29次带句柄执行均匹配本题生成的句柄，没有触发candidate_plans错误恢复。说明接口能正常使用，不能证明恢复分支已经救回失败。
- `4ccc9027`在原DeepSeek B0就成功；历史Qwen的错误句柄/目标案例不能充当本次DeepSeek收益。此次执行过正确目标和句柄，但也出现更多搜索步骤。
- 收尾、拍照位置、发现后继续行动等全局提示没有被单独消融。观察到一些任务正确执行不等于每条提示都有效；不得为证明它们而改在线Agent使用隐藏checker。

## 时间与可观察tokens

同57题，B0任务窗口中位数70.95秒、B1为45.16秒；窗口之和分别5969.13秒、4811.66秒。窗口取`barrier.frozen_at-window.opened_at`，不含准备和后续worker退出等待，并发窗口之和也不是整次墙钟时间。

同57题可观察tokens为B0 **39,596,960**、B1 **48,948,005**，有usage的调用数分别719和759。B1两个未结束场景虽无performance.json，但逐job保存值与原始metrics一致，未估算补数。未计分`23a9d67d`另外有1,714,906个已观察tokens、1个尚未结束的调用；

因此不能把本轮描述为“更省调用”。目标是提高任务成功，资源量是次要观察；历史8并发与本次2并发、日期和服务状态不同，也不支持严格速度因果结论。

## 保留建议与下一步最小验证

当前证据支持**暂留整包作为候选**，尤其保留方向航段的语义纠正；无需因为这次进程中断就把Agent修改整体回退。它没有表现出此前重型Harness那种大面积通过率下降，但仍有回归，且距离、句柄恢复的收益未被测试覆盖。

下一步建议先处理实验进程与状态落盘的可靠性，明确中断来源后再设计新的正式实验；不要恢复本attempt并把后补结果冒充首次执行。对于Agent，优先研究目标发现/名称-ID映射与缺目标时的有效搜索行动，让失败案例真正执行成功，避免再加普遍的硬性完成门禁。

若另行批准小消融，先比较“早期B1导航”与“早期B1导航+方向提示”，覆盖3道已获益方向题及原成功的同类题；其他工具分开用真正触发纠偏/句柄错误的案例验证。控制场景前序承接或明确从同一合法任务前状态开始，避免把前题探索贡献误认成本题补救。以上仅是建议，本次没有启动任何新模型实验。

## 解释边界与成果

本次是10月3日历史B0与10月6日当前版本的同题比较，模型同API名不保证权重或采样完全一致。三场连续任务的世界、感知与黑板会受前题动作影响；例如B0 `9c0b52a0`题前进度已100%，保留原协议得分但不能称作本题从零完成。60题并非独立同分布大样本，更不能作为“全新UAV Agent架构”的创新证据。

本目录包含60行`paired-tasks.csv`、`summary.json`、合并输入证据的`input-sha256.json`，以及逐例、机制和中断审计。`summary.json`保留原manifest状态，同时另列观测到的中断状态与根/场景快照差异。所有新增文件与分析代码单独提交；原实验目录及用户其他工作不变。

复现统计时输出到新目录，避免覆盖本人工解读报告：
