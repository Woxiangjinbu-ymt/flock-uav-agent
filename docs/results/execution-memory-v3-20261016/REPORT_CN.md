# Memory 第三版：查询前说明原因的验证结果

日期：2026-10-16。

**这一轮确实少了一次重复查询，但改善主要集中在一个案例，还不能说已经稳定解决。** 原来的 6 个场景、两组共 12 次真实实验全部完成，没有扩大到 100 题，也没有挑选重跑结果。

## 这次做了什么

保留上一版的查询记录和简短任务交接，新增一个行动决策步骤：有可复用查询记录时，模型先选择“沿用结果／换位置／重新查询”。如果重新查询，要用一句话说明为什么需要更新、观察到了什么变化，并引用已有证据；没有变化就明确说没有。

说明写在模型原本那次回复中，不增加模型轮次或工具。**工具没有被硬性拦截。** 缺少说明、格式错误或理由不足都只记录，工具照常执行。审计在工具执行前保存，不拿后来的结果替先前理由补证；模型自己的说法不进入环境事实或完成判定。

## 怎么比较

本轮基线是 **memory v2**，实验组是 **memory v3**，两组都重新运行。这样只考察新增决策说明的效果，不把之前 R3 的成绩混入本轮。

逐字节复用原六个场景快照和公开历史。两组的工具、原始信息、读取时点、模型和预算一致；仅两个线索场景首次增加说明要求，其余四个场景的首次视图完全相同。模型仍为 `deepseek-flash`，温度 0.1，关闭 thinking 和 SDK 重试。

## 结果

| 指标 | 本轮 v2 基线 | v3 |
|---|---:|---:|
| 目标达成／正常结束 | 6/6 ／ 6/6 | 6/6 ／ 6/6 |
| 同机同位置重复感知 | 1 | 0 |
| 模型调用 | 20 | 17 |
| 工具调用 | 15 | 11 |
| 总 token | 53,510 | 39,900（−25.43%） |
| 执行耗时合计 | 25.55 秒 | 20.90 秒 |

| 场景 | v2 → v3 token | 实际变化 |
|---|---:|---|
| 水平历史线索 | 6,018 → 6,241 | 两组都直接换位置，无重复；新增提示略增加 token |
| 垂直历史线索 | 20,237 → 6,293 | 重复感知 1→0，模型调用 5→2，工具调用 5→1 |
| 路线中断 | 8,410 → 8,489 | 动作完全相同，均补剩余航点并降落 |
| 路线受阻后恢复 | 8,770 → 8,770 | 动作完全相同 |
| 已完成任务 | 4,197 → 4,184 | 两组都多读一次状态，本轮没有解决这一点 |
| 感知失败 | 5,878 → 5,923 | 两组都正常重新感知，再访问目标 |

实际总用量为 **93,410 token**，整体上限 300,000；没有预算截断或未结算请求。未缓存输入为 5,852→4,846，输出为 2,730→2,030；耗时包含服务波动，仅作描述。

## 哪部分有效，哪里仍有问题

**垂直线索案例出现了实际行动改善。** v2 虽然知道当前位置已查过两次，仍先感知、读状态，再移动；到达目标后又感知并飞到中心。v3 先声明“换观察位置”，直接飞到路径中点，收到本人到达目标的真实回执后结束。少掉的四次工具调用中，只有一次是同点重复感知，其余是状态读取和到达后的额外确认，不能把全部节省都算成去重收益。

**水平线索没有增量收益。** 本轮 v2 自己也直接换了位置；v3 动作相同，只多了说明提示。这与上轮 v2 的表现不同，说明单次小样本存在波动，不能拿历史较差结果替代本轮基线。

**说明格式生效，但内容还不够准确。** v3 在两个相关决策点都输出了可解析说明，并选择 `change_viewpoint`。然而两次都把原因填成 `position_changed`，引用的 `e15` 实际是当前位置的空查询；当时尚未发生新的移动。文字说明表达的是“需要换个位置”，不能作为“位置已经变化”的证据。审计只确认引用存在，没有把理由判为真实。

新版在这两例中都没有选择重复刷新，因此本轮证明的是一次局部行动改善，**没有验证模型在真正需要刷新时能否准确说明变化**。失败重试仍然正常；但该场景本就不触发新要求。两组成功率相同，纯路线也没有新增能力。

## 下一步重点

先把说明中的“已经发生的变化”与“准备执行的动作”分成独立字段，避免将计划移动填成已发生变化；保留没有观察到变化的明确选项。仍只审计，不阻断工具。

在扩大题量前，需要同规模的预先固定重复验证，检查垂直案例的改善能否重现。当前六个案例已经用于开发，不是独立测试集；本轮止于这些首次结果，没有追加调用。
