# R3 航线义务监视器：第一阶段在线配对结果

2026-10-09。**结论：R3 反馈确实进入了长航线任务并识别了缺口，但本轮没有证明它改善航线任务的原始得分。**新鲜 R2 对照为 **17/20 题、158/167 项检查**，R2＋R3 为 **18/20 题、159/167 项检查**；唯一多通过的是非航线题，且两臂进入该题前的世界状态不同。两道可解析航线题分别是双方同为 19/26 和双方同为 39/39。按预注册门槛，本轮**不进入第二场景在线扩展**。

## 试验范围与有效性

依据[预先固定的方案](../../audit/r3-next-step-20261009/PROTOCOL_CN.md)，两臂各从原始 `35ce64d8` 场景启动，顺序执行前 20 题，保留场景内状态和 blackboard 承接；每臂 167 项原检查。固定同一模型配置、500 秒任务窗口、工具、服务端、原检查器，观察工人关闭。R2 源于固定提交 `69dd34c067ec97b746db5180684594c546a35172`，R3 只加入已审过的航线证据模块及其接线；冻结源码哈希比对显示两臂仅三个 agent 文件不同：`uav_agent.py`、`task_evidence_r3.py` 及其测试。离线预检分别通过 33 和 97 项测试。任务原文、检查定义和运行配置见[冻结研究目录](../../../experiments/m1r3-route-prefix-v2/)。

首次 v1 启动在服务绑定本地端口时被沙箱拒绝，尚未评分任何题、也未调用模型；原记录保留在[中断尝试](../../../experiments/runs/20261009-161426-r3-route-prefix-control-a0f0cdbd/)。使用可绑定端口的环境重新冻结为 v2 后，对照和 R3 各自的**首次可评分尝试**均完成 20/20 题、167/167 项评分且 `valid_complete_run=true`。原始尝试分别见[对照](../../../experiments/runs/20261009-161457-r3-route-prefix-control-5175626a/)和[R3](../../../experiments/runs/20261009-165229-r3-route-prefix-r3-f9e1563f/)；没有挑选重跑成绩。

逐题是 R3 **1 胜、0 负、19 平**。唯一胜题是第 13 题 `b1ad4f3e` 的场景目标进度检查：对照 0/1、R3 1/1。该题 R3 解析状态为 `no_explicit_route`，航线监视器没有形成航线义务；题前对照已有 15/20 个目标到达，R3 已有 18/20 个，且 15 架无人机中有 6 架位置不同。对照在 453.53 秒触及 agent `step_limit`，R3 用 295.15 秒完成。**这个 1 题差异不能归因为 R3 航线机制**。场景任务串行承接、远端模型采样不同，表中的时间、调用和 token 差异也只能描述两条实际运行，不能视为模块的因果成本。仅看两道航线题，耗时为对照 414.6 秒、R3 393.0 秒，调用 44 对 42，token 为 2,343,679 对 2,501,088；同样没有稳定效率结论。

## 航线反馈的实际作用

| 题目 | 新鲜 R2 | R2＋R3 | 可观察机制 |
|---|---:|---:|---|
| 第 18 题 `f777f4e3` | **19/26** | **19/26** | R3 识别航线并产生 11 次任务证据注入；两臂失败的是完全相同的 7 项访问坐标检查。 |
| 第 20 题 `cf8ee51f` | **39/39** | **39/39** | R3 产生 15 次注入，三架无人机各有 12/12 顺序回执；新鲜对照也通过，旧轨迹的跳点未复现。 |

第 18 题中，R3 对 Drone 7 最终仅确认顺序前缀 **1/12**，下个未确认点是 `(126,205,26)`；对 Drone 5 为 **2/12**，下个未确认点是 `(141,228,26)`。R3 随后确实尝试精确移动到第一个缺口，回执 `e19` 返回“Destination point is inside an obstacle”；另一失败点 `(844,161,26)` 的精确尝试 `e31` 也被路径规划阻断。对照也尝试第一个点并获相同阻断。七个失败检查对应的 R3 最近成功移动回执距离依次为 **31.0、4.0、17.72、34.0、5.39、8.0、28.0 米**，均大于 3 米检查容差。可见反馈传达与至少部分补点尝试已发生，得分瓶颈仍在实际到达。

进一步使用**与冻结运行逐字节相同的**服务端障碍模型和题前障碍快照，核对七个失败目标的 3 米容差圆盘。两臂障碍配置一致。下表的“最近合法边界”只度量目标到障碍联合边界的平面距离；高度为 0 的障碍在服务端规则下所有高度均不可进入。

| 失败坐标 | 精确目标在障碍内 | 距最近合法边界 | 3 米内有局部空地 |
|---|---|---:|---|
| `(126,205,26)` | 是 | 25.09 米 | **无** |
| `(844,161,26)` | 否 | 0 米 | 有 |
| `(875,404,26)` | 是 | 17.17 米 | **无** |
| `(224,669,26)` | 是 | 31.52 米 | **无** |
| `(880,733,26)` | 是 | 1.23 米 | 有 |
| `(141,228,26)` | 是 | 2.09 米 | 有 |
| `(216,696,26)` | 是 | 24.09 米 | **无** |

因此，**7 项中的 4 项在当前移动碰撞规则下连容差内的合法终点都没有**；对这四项，单靠更好的记忆提示或重试精确坐标无法提升原检查。另三项只证明局部存在空地，尚未证明从无人机当时的位置有安全路径，也未证明模型会选中空地并留下合格 waypoint 回执。几何审计是结果解释，**没有改动原题或评分器，也不从已报告分母中剔除**。全部坐标、障碍 ID 和边界距离见[几何证据](feasibility.json)。

第 20 题 R3 的 Drone 7 第 11 点 `(292,920,27)` 取得真实到达回执 `e99`，模型请求与最终位置一致，剩余距离为 0；原检查也通过。但这不是“R3 救回旧失败”的证据：本次新鲜 R2 对照已独立得到 39/39。

## 研究判断与下一步

本轮达成了“航线文字能被解析、缺口能在运行中反馈、模型会作部分补点尝试”的**机制可运行性**，未达到预定的“至少一个航线缺口获得实际补点及检查改善”的扩展条件。直接扩大样本容易把不可行任务、导航阻断和 agent 记忆失误混为一谈；当前也没有证据支持将 R3 描述为成功率或速度提升。

下一步应先做**离线任务可行性筛查**：在与 R2 开发场景不重合、R3 已识别的 34 道航线题中，仅根据原任务、原场景障碍和原检查容差标记哪些检查具有合法目的地区域，分开报告“局部不可行”“局部可行但路径未证实”“可证实到达”。筛选规则在查看 R3 在线结果前冻结，保留全量分母，不能事后删除难题。若有明确可行且新鲜 R2 会漏点的目标，再从**同一题前世界状态与 blackboard 快照**启动 R2/R3 对照，比较补点动作、原检查与时间；若没有这种目标，应暂缓投入 R3 在线扩展，转向导航或 benchmark 质量问题。任何新的导航工具、跳过阻断点策略或评分调整须作为独立变量研究。
