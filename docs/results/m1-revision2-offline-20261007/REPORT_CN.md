# M1-R2 增量优化与离线验收

2026 年 10 月 7 日。M1-R2 已接入当前 agent，在 M1-R 上增加历史接触线索的使用提示，以及显式会话进度义务和公开反馈。428 项测试通过；100 题保存轨迹回放中，四个正向案例的投影与摘要保持一致。当前具备进入下一轮测试准备的代码条件，在线成功率、成本与退化恢复仍待验证。

父版本为 `77563fb5827629da4dcecc2bb69c828db3907df9`。本轮只修改工作区并做离线验证，尚未创建新的冻结方法或启动付费实验。旧 M1-R 的 81/100、相对历史 M0 的 W4/L3 为诊断观察值；旧 attempt 的封存失败状态保持原样。

## 保留原收益的改动边界

M1-R 的原证据索引、固定提示、追加式上下文、原工具集定义和实际请求审计模块保持原文件内容。旧 `evidence` 模式继续执行 M1-R。R2 不接管任务执行、导航、重试或评分，也不新增模型裁判。

新增逻辑仅在两种条件下进入模型可见内容：

- 指令明确指定无人机访问目标，目标只有正向接触记录而未定位、指定无人机也尚未形成当题到达证据时，给出有来源的历史路径及后续感知提示。限于固定目标和 Waypoint，不将移动目标的旧位置当作当前线索。
- 指令明确要求会话或总体任务进度达到百分比阈值时，保留原文来源和比较运算，并提供公开进度读取。单个区域的 95% coverage 不会触发全局进度逻辑。

在固定的 100 题旧动作上，85 题所有回放检查点的摘要一致；11 题新增整体进度义务，另 4 题增强接触线索。四个正向案例共 66 个检查点，投影、摘要全部一致，且均不增加进度工具：

| 正向案例 | 检查点 | 离线保护结果 |
| --- | ---: | --- |
| 双目标巡检 `ad34350a/529c0622` | 24 | 投影与摘要一致 |
| 四机协同移动 `ad34350a/a53ba7fc` | 11 | 投影与摘要一致 |
| 双机区域覆盖 `ef36e27a/ba8b14f3` | 13 | 投影与摘要一致；局部覆盖阈值未误识别 |
| 固定目标巡检 `823c15d5/ddc3e0b0` | 18 | 投影与摘要一致 |

这是相同旧动作、相同回放初始条件下的局部保护证据。R2 在线运行可能改变前序任务和场景状态，因此不能据此保证四题再次成功，也不能声称与旧运行的全部实际请求逐字相同。

## 历史接触线索增量

R2 从成功完成的直接相对移动回执恢复线段。要求工具、回执类型、actor、距离和方向相符，并排除失败、部分完成、嵌套回退和同一 actor 的并发歧义。解析保留原 session、command、event、tool-call、消息路径以及坐标舍入标记。

未定位目标优先保留原 M1-R 已有的合法路径；原提示为空时，从保留的相对移动线段中选取最短的一段，同长度优先较新记录。排序只使用已观察到的路径，不读取地图或真实目标位置。提示要求沿线索进行合法本地感知、取得确切 ID/位置，再由指定无人机访问，同时保留原顺序、拍照和后续移动要求。

五机扫掠 `35ce64d8/20742d37` 的 FT10、FT11 在初始摘要中同时获得前序 e51 的线索：`(154,115,18) → (154,36,18)`。线索来自 Drone3，当前仍分别要求 Drone13、Drone7；两项保持 `reported_only/unattempted`，没有填入 target_id、目标中心或完成状态。路径曾经发生接触，不保证当前无人机可达，也不保证沿路径每一点都能感知目标。

## 整体进度反馈增量

R2 增加任务范围内的 `get_mission_progress` 工具，只用于明确的会话进度阈值。模型选择调用时，它读取已有的 AGENT 可访问接口 `/sessions/current`，输出会话 ID、任务类型、百分比及允许的总数/已访问/未访问计数。工具不输出实体列表、目标坐标或隐藏评分，也不会自行轮询、调用模型或追加重试。

证据层保留 `>` 与 `>=` 的区别。只有当前命令内有效的读取可支持阈值状态；缺失、读取失败、会话变化、动作后未刷新、读取与动作重叠时均保持未知。百分比与计数的校验沿用服务端整数计算规则。这里的时效检查针对已观察动作，不保证没有外部并发状态变化。

95% 退化题 `35ce64d8/b1ad4f3e` 现在有显式进度义务，不再只有空的目标引用列表。80%、16/20 的本地公开反馈样例会得到 `observed_threshold_not_met`；后续必须继续可行搜索才能改善原任务成功率。原保存轨迹没有调用这个新工具，所以历史回放中的阈值全部保持 unknown，没有把事后重建的 80% 冒充当时模型已观察的数据。

这仍是证据提示，不是最终答复拦截器。模型可能不读取进度、忽略提示，或仍在未完成时输出结束标记；本轮不增加自动补救调用。新增公开反馈改变了观测协议，其在线收益不能完全归因于记忆表示，历史 M0 只能作为历史参照。

## 验收结果

- **428 项测试通过**，18.988 秒：agent 全套测试及实际 service 环境变量接入测试。包含 invoke/stream、旧模式、任务范围内工具注册、无关任务的脚本请求一致性、并发、失败/部分回执、清空后的迟到数据、跨命令隔离和失效反馈。
- **实际 SDK 序列化验证通过**：用本地 MockTransport 截获 2 次请求，正文哈希与实际字节一致，前次消息前缀和本任务工具定义保持稳定；一次公开进度读取使用本地 fixture，无外部网络调用。此验证不等于服务端缓存命中率验证。
- **100 题全轨迹回放通过**：5 场、3,273 个工具事件、1,523 个初始/工具批次完成检查点，observer_errors=0；原回执、参数、工具顺序和重叠关系保持不变。新线索没有改变知识状态、actor 绑定或完成证据；所有展示的消息来源均能解析到原回执，无未来或跨场景来源。摘要最长 3,898 字符，继续遵守 3,900 字符预算。
- **旧证据保护通过**：旧 M1-R 终态快照 1,155 个文件完全匹配原终态 seal；四份前序报告的 9、8、8、19 个已哈希产物保持不变。旧 ef36e27a 的场景封存异常没有被重签或抹除。

两个早期测试断言已修正：旧测试依赖过时的模式报错文案；另一个误将工具说明中的 hidden 一词当成泄漏实体。最终日志和 XML 保存最终通过结果。测试中现有 AnyIO 弃用及非交互绘图警告不影响验收。

## 模式与下一次实验

通过构造参数 `task_progress_mode` 或环境变量 `UAV_TASK_PROGRESS_MODE` 选择；显式构造参数优先。模式需在新 agent/黑板上选择，不在正在运行的旧实验中切换。

| 模式 | 内容 | 可独立验证的增量 |
| --- | --- | --- |
| `evidence` | 原 M1-R | 保留原方法和回退入口 |
| `evidence_r2_hints` | M1-R 加历史接触线索 | 与原工具集相同，可单独衡量线索使用收益 |
| `evidence_r2` | 线索增量加整体进度义务和公开进度工具 | 在前一层上增加反馈，不替换前一层 |
| `evidence_r2_shadow` | R2 观察与遥测，不注入模型内容，不添加进度工具 | 验证 observer 的输入/输出边界 |

下一次若进行成功率测试，应重新冻结本轮 agent 和前一轮已修复的资源 writer。主指标仍是原任务成功率和同题 W/L，同时检查四个 W 是否保留、三个 L 是否恢复、是否产生新的 L，再报告时间、token、缓存和真实调用数。内部阈值状态更准确、线索恢复更多，均不能替代任务收益。

仅增线索模式提供消融入口，不意味着必须立即增加一整组付费实验。若先测综合 R2，应将结果解释为两个增量共同作用；若随后进入论文归因阶段，再决定是否支付消融成本。当前无需扩大到 dev240 或增加新的研究阶段。fast100 只有五个开发场景，世界和黑板承接，多次修订也使用了这些案例，仍不能声称随机因果、统计显著或泛化提升。

论文主线可以保持集中：任务义务保存下来之后，需要把历史证据变成可用的协作线索，并用当前可观测反馈区分局部已知与整体完成。是否形成有效方法贡献，以后续原任务成功率和代价共同判断。

## 复现与文件

`m1-r2.patch` 保存相对冻结父版本的本轮代码和测试差异；`replay.json` 保存逐题初始/最终投影、摘要哈希和检查点；`summary.json` 保存汇总；`verification.json`、`agent-tests.log/xml` 保存测试验收；`preservation.json` 保存旧证据核验。`input-sha256.json`、`source-sha256.json`、`artifact-sha256.json` 分别记录输入、实现和本目录产物哈希。

离线复现入口为 `experiments/analysis/replay_m1_revision2.py --output <新的输出目录>`。它只把题目顺序、原指令和保存的工具事件输入 R1/R2，不读取隐藏世界用于决策，也不启动模拟器或模型。回放固定旧动作，两组索引均从空状态开始，因此不能产生新的成功率估计。
