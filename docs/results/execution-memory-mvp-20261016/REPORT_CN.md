# 执行记忆最小版与小规模对照结果

日期：2026-10-16。

**最小版本已实现，231 项相关测试通过；本轮没有证明实际净收益。** 新记忆能正确记录检查过的线索位置、保留中断后的剩余航点，但模型仍重复感知；路线续接也没有超过 R3 已有能力。没有运行完整 100 题，也没有追加第二轮。

## 我做了什么

1. 增加感知尝试记录，区分成功为空、发现目标、调用失败和无法判断；每条都关联真实工具回执和执行者。
2. 将观察位置与历史接触路径关联，显示哪些线索位置查过。只作局部证据，不推断整段搜索完成或目标不存在。
3. 复用 R3 的真实路线前缀，交接原始未完成航点；改计划不会删掉原任务要求，其他无人机到访不会代替指定机完成。
4. 接入普通 agent 和 harness 的暂停、异常、取消出口，返回 `memory_handoff`。视图按当前决策选择、限制长度，原始证据保留在审计记录中。

新模式默认关闭，可选 `evidence_memory` 或 `evidence_memory_harness`。实现及用法见 [设计说明](../../EXECUTION_MEMORY_MVP_CN.md)。当前仍不支持跨进程自动续跑；降落、拍照和复杂条件等未核验条款会明确保留，不能把有限的路线记录当成完整完成判定。

## 实验怎样比较

6 个人工构建的受控场景，各跑 R3 原视图和新记忆视图一次，共 12 次真实模型执行。包括两例历史接触线索、两例路线中断、一例任务已完成、一例感知结果丢失。

两组使用相同原任务、完整合法公开回执、真实本地 ASGI 模拟器快照、工具、读取时点、模型和预算。新视图替换旧视图，均不超过 3,900 字符。模型为 `deepseek-flash`，温度 0.1，关闭 thinking 和 SDK 重试。模拟时钟固定。准备阶段验证每个场景都存在合法可完成路径。

每次最多 6 次模型调用、12 次工具调用、90 秒、60,000 token；整项实验上限 300,000 token。第一轮实际使用 **168,605 token**。预算预检采用保守上界，会在实际 token 未到上限时提前退出。

**本实验测的是受控恢复时点的记忆内容，不是原 100 题成绩，也没有验证生产 middleware 选择读取时机的收益。** 当前 harness 没有新增路线技能；路线案例通过普通公开工具续接。

## 结果

| 指标 | R3 原视图 | 新记忆视图 |
|---|---:|---:|
| 模拟器目标达成 | 6/6 | 6/6 |
| 模型正常结束 | 6/6 | 5/6 |
| 预算预检提前退出 | 0 | 1 |
| 总 token | 81,251 | 87,354（+7.51%） |
| 模型调用 | 25 | 22 |
| 工具调用 | 22 | 20 |
| 同机同位置重复成功感知 | 2 | 2 |
| 执行耗时合计 | 30.77 秒 | 25.83 秒 |

调用和耗时总数包含新组的一次提前退出，不能直接解释成效率收益。重复感知是诊断指标，不自动等同于无效调用。这里的目标达成来自试验外部检查；新记忆不读取该检查结果，也不会据此决定结束。

| 场景 | R3 token | 新记忆 token | 观察 |
|---|---:|---:|---|
| 水平历史线索 | 25,948 | 20,919 | 都达成；模型调用 6→4，工具 6→4 |
| 垂直历史线索 | 25,700 | 22,030 | 都达成；新组预算预检退出，未正常结束 |
| 路线中断 | 9,175 | 12,795 | 相同动作、参数、顺序；新组多 39.46% token |
| 路线受阻后恢复 | 9,570 | 13,218 | 相同动作、参数、顺序；新组多 38.12% token |
| 已完成任务 | 4,289 | 5,211 | 两组都未重飞路线，均多读一次状态 |
| 感知失败 | 6,569 | 13,181 | 都正确重试；新组完成后多查一次状态 |

任务目标达成的配对结果是 **新组独有成功 0、旧组独有成功 0、同成功 6**。去掉发生预算截断的整组配对，其余五组 token 为 55,551→65,324，增加 17.59%。这是帮助解释截断影响的补充统计，不能替代全部结果。

## 哪些有效，哪些没有

**功能正确，但避免重复检查尚未生效。** 两个线索场景中，新视图已经列出当前位置的两次空感知，模型仍在同一位置再查一次。增加正确记录并没有自动改变行动选择。

**路线交接没有增量收益。** 两组都依次补第三个点、飞到终点、降落，模型和工具调用次数完全相同。R3 原视图已经提供足够的路线缺口；新视图从约 895 字符增至约 2,000 字符，带来额外输入成本。

**水平线索案例只有局部信号。** 两组都先移动到 100，并收到到达目标的回执。R3 随后感知、再移动到目标中心 90、再次感知；新组查询状态后结束。两组此时都已有 `execution_state=evidenced`，因此节省更像一次结束/核验选择差异，不能证明是新线索记录独有的作用。

**失败感知对照出现回归。** 基线本就能区分查询失败与目标不存在。新组没有获得新增成功，反而在访问成功后多做一次状态确认，总 token 约翻倍。

**垂直线索案例不应算作省调用。** 新组先试探 150，再移到 100；基线直接到 100。新组目标已达成，但预算预检截断了后续模型调用，没有正常最终回复。

## 下一步应做什么

1. 先把相同位置、相同条件下的检查记录合并成简短结论，减少重复证据和原文摘录。已经有充分证据的路线继续使用较短的 R3 表示。
2. 针对“看到两次空结果仍重复查询”检查模型输入与决策理由，验证一条简短、明确且有来源的提示是否比当前结构化记录更有效。若加入执行前重复检查或自动补救，需要与 memory 内容分开对照，不能把控制策略收益全部算作记忆创新。
3. 在扩展题量前，先找到可重复的、有相关历史证据且基线确实用不好的样本。当前两个路线样本的基线已经全部成功，不适合用来宣称成功率提升。

现阶段保留为可选实验功能，不能据这轮结果宣称论文中的有效改进。

## 验证与证据

- 231 项相关测试通过：新记忆语义、真实同步/异步 agent 接线、空回复重启、真实取消、原 R2/R3 和 harness 回归、试验预算与场景恢复。新增范围内共有 64 项测试。
- 试验后重新校验冻结哈希和世界快照通过。冻结源文件的 33 份原始内容另存于实验目录 `frozen-source/`。
- 试验过程有一次 runner 磁盘临时修改，仅涉及准备阶段检查和源文件清单；已加载进程的 `run/run_trial` 未改变。随后精确恢复原冻结哈希，未修改 manifest、未覆盖或补跑任何结果。细节保留在 `source-integrity-note.json`。
- 正式试验：`experiments/execution-memory-mvp-v1/`，含 manifest、公开前缀、世界快照、逐次模型输入、真实工具回执、预算台账及结果。
