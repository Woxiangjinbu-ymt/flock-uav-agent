**进度反馈恢复的案例有较清楚的机制链。** `b1ad4f3e` 启动时公开进度为 17/20，即 85%；模型实际查询三次，得到 85%→90%→100%，在未满足阈值时继续搜索，最终快照确认为 20/20。耗时约 130 秒、1.075M token；旧 M1-R 约 396 秒、4.420M token，曾把已知目标集合误作全局分母。这里能确认新观测被使用且任务最终成功；由于初态和运行时点不同，仍不能把差值当作随机因果效果。

**五机扫点恢复不能作为新路径提示的在线证据。** `20742d37` 开始前世界已达到 20/20；其任务视图和随后工具观测能获得所需目标位置。本任务保存的所有注入均没有 R2 的 `next_step` 或 `receipt_derived_relative_segment`。最后由指定 actor 完成目标访问及移动，20/20 检查通过，约 45 秒。其恢复与前序任务留下的信息有关，不能直接归功于为旧轨迹新增的相对运动提示。

**顺序访问仍受未知目标限制。** `c6e28e3b` 本次开始时世界为 52/100，结束为 54/100；59、55 在任务证据中仍未知，只完成 31 的访问、悬停、拍照。约 441 秒结束，未达到 500 秒超时线。历史 M0 的同题评分包含前序世界承接，且该题检查仅判断目标是否曾被到达，不核验本次指定 actor、顺序及照片。因此“历史 M0 成功”不等于其当前指令执行完整，也不能据此用更宽松标签修复 R2 分数。

**旧正向收益丢失属于探索失败。** `529c0622` 搜索后仍没有 Circle Target 6 的 ID/位置，Polygon Target 7 有接触报告但未按任务访问拍照。约 376 秒自主结束、10.070M token，四项检查均失败。它既不是阈值判断问题，也不能用已有位置提示直接覆盖；未发现目标只能支持“本轮未定位”，不能证明目标不存在或不可达。

## 4. 机制、来源与实际请求审计

100 个保存 trace 的 `task_progress_mode=evidence_r2`、active=true、revision=m1-r2。observer_errors=0，模型请求审计错误=0。379 次带重复的来源引用检查通过：任务原文 span、同场景/先前或当前命令范围、原工具 message 路径、tool_call_id、来源 actor、当前执行证据 actor 均匹配。mission_completion 全部保持 `not_evaluated`，内部标签不作为任务收益。

公开 `get_mission_progress` 在 **11 题中调用 43 次**，得到 43 个有效观测；其余 89 题没有该调用。响应仅含公开场景进度及允许的计数等字段，无隐藏目标位置。最终有 8 题保持新鲜且阈值满足，3 题因后续动作/重叠而标为 stale、阈值 unknown；实际任务成绩相应为 8 成功、3 失败。审计逐条核对了注入中的来源与阈值运算，并根据全部事件重算每题最终刷新状态；未声称从缺失的完整消息正文恢复每次中间注入的精确时间边界。

本轮保存的最终与注入任务视图中，**相对运动派生提示出现 0 次**。一般的“优先沿历史接触路径感知”建议在 2 题的视图里出现 3 次，均使用已有类型的路径证据；不能据此证明新增相对运动分支提高了成功率。旧轨迹离线能生成提示，不等于新运行会遇到并利用相同证据。

保存了 **1,533 次实际序列化 HTTP 请求正文哈希**，与中间件请求数量一致。各任务内工具 schema 哈希保持稳定；可比较的 1,433 对相邻请求均完整保留前一次消息前缀（1433/1433）。这是对已记录的正文哈希格式、字节数、逐消息哈希及前缀元数据的核对；未保存完整请求正文，不能宣称独立重算了所有正文 SHA-256。详见 `evidence-audit.json`、`aggregate-progress-audit.json`。

## 6. 下一步判断与论文范围

这轮支持的结论是：**明确全局分母的公开进度反馈能够纠正特定完成度误判；当前整套证据摘要尚未稳定覆盖全部任务义务，也没有表现出整体成功率净增。** 对 6 页论文，更适合收敛为一个统一、可消融的研究问题，而不是继续增加互不相干的导航、重试、验证器与新指标。

建议分两步，但本次仅交付诊断，不修改冻结方法或启动实验：

1. 先在保存轨迹上检查“原指令剩余义务”的覆盖边界。优先验证明确给出的 actor—坐标航点是否能逐项关联真实回执；对协同覆盖任务先澄清任务和评分语义。验收应包括能检出 `cf8ee51f` 的遗漏、不会把未支持条件标为完成、不会改动已完成动作或替其他 actor 完成义务。此举仍是离线机制验证，不能承诺恢复在线分数。
2. 保留 R2 的公开进度反馈及原证据来源约束，若再提候选，只增加一个边界清楚的可选模块，保持累计关系和关闭开关。新相对运动提示目前可保留为候选能力，不宜单独列为已证实贡献。待离线覆盖和反例检查成立后，再由用户决定付费方案及必要的观测/提示消融。

四个旧 W 尚有一个丢失；总 token 上升；关键路径提示没有在线暴露。需要的是更清楚的机制与收益证据，而不是扩大样本后再解释一个仍不完整的故事。

## 7. 解释边界与交付

fast100 是反复用于研发的开发集，仅有 5 个场景，题目在场内并不独立，世界和黑板承接显著影响后题。M0 是历史参照，无同期重跑；远程模型别名、抽样与运行时点可能影响结果。R2 新工具改变了可获得的观测，没有固定提醒或观测对照。本报告只作同题描述性比较，不宣称随机因果、统计显著、全量提升或测试集泛化；单次 79/100 也不足以证明 R2 必然弱于 M0。早停规则未触发，但规则的存在本身不构成统计验收。

- `paired-tasks.csv` / `paired-tasks.json`：固定 100 题全账本，包含各方法成绩、有效性标记、W/L、子检查、超时、耗时、token、原 trace 路径。
- `summary.json`：机器可读汇总、逐场数据、guard 条件、历史对照限制。
- `case-changes.json`：4 个旧 W、3 个旧 L 与新增 L 的原证据摘录。
- `evidence-audit.json` / `aggregate-progress-audit.json`：来源、actor、公开进度、刷新状态、请求哈希与前缀审计。
- `frozen-verify.json` / `verification.json`：冻结入口复核与封存结果。
- `input-sha256.json`：读取的原始输入及冻结复核输出哈希；`artifact-sha256.json`：本报告制品哈希。
- `analyze.py`：离线汇总与审计脚本，只读取原证据并写本目录。

本轮没有补跑、恢复、增加付费调用或推进 M2/M3。B1、旧 M1/M1-R 及工作区其他修改均保留。验收完成后，自动化 `b1-m1` 已通过应用工具更新为 `PAUSED`，原提示与调度字段保留。
