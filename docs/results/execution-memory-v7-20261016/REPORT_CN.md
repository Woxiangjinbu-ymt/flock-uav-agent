# Memory 优化进展：保留完成证据，只精简适合的任务

日期：2026-10-16。

**本轮最终保留的是 v7：路线任务使用精简清单，其他任务沿用 v5。** 在相同六个场景的两轮对照中，两版都完成了全部任务；路线任务用量降低约 5.6%，没有增加工具调用，也没有为补充落地坐标再查询。

## 做了什么，以及为什么收缩

先做了 v6，把各类任务的重复记录统一合并，并明确区分历史航点和落地位置。三轮 36 次结果发现，v6 只有 14/18 成功，基线 v5 为 18/18：四次线索任务把“沿整段遇到过目标”误解为“目标在端点附近”，耗尽调用额度。事实仍在，但模型没用好。完整失败记录保留在[第六版报告](../execution-memory-v6-20261016/REPORT_CN.md)。

因此 v7 缩小改动范围：

- **完整路线任务**：合并重复记录，保留已完成航点和剩余步骤；落地回执没有坐标，就报告落地成功、精确位置未知。
- **线索、访问、混合及未完整解析的任务**：对相同历史，每个读取点的记忆内容与 v5 逐字一致，完成之后也不切换。
- 仅按原始任务语法选择方案，不按案例编号或实验成绩切换。没有硬性拦截工具，也没有自动结束任务。

## 收缩后的验证结果

另跑固定两轮，共 24 次，新跑的 v5 与 v7 各 12 次；没有与前批成绩混合。

| 指标 | v5 基线 | v7 |
|---|---:|---:|
| 任务达成且正常结束 | 12/12 | 12/12 |
| 已知完成后额外调用 | 0 | 0 |
| 六次路线任务的模型／工具调用 | 18／12 | 18／12 |
| 六次路线任务总 token | 46,751 | 44,113（−5.64%） |
| 六条路线回复中明确错误的落地坐标 | 1 | 0 |

路线用量两轮分别降低 **5.73%、5.55%**，六个路线配对均下降。发送给模型的累计路线记忆文本减少 20.36%；字符长度与实际 token 用量分开统计。

逐条核对 v7 的 12 次执行和最终回复：剩余航点、必要落地和失败感知重试均保留；访问任务没有把到访位置冒充目标中心；六条路线回复明确没有落地坐标，未为完善报告增加查询。

## 哪些结论还不能说

**没有进一步减少完成后无用动作的证据**，因为这批基线也全部为零；成功率也没有提升。

全批总用量为 96,982→84,451 token，看起来下降 12.92%，但约 79% 的净差来自提示逻辑完全相同的非路线任务发生了不同执行路径，不能归为 v7 改进。因此本轮只把路线任务约 5.6% 的下降作为局部收益。未缓存输入还略有增加，本报告不推算账单金额。

落地坐标错误是六条回复中的 1→0，样本很小。两批都只用了原六个开发场景，也没有做独立任务验证，不能宣称泛化效果。

## 当前保留与后续问题

保留 v7 的保守适用范围。路线记忆的目标仍是正确续做、保留完成证据，提示变短是附带收益。线索任务继续使用 v5；下一步若改这部分，应单独解决“线段线索被误读为端点”和“声明换位置却仍原地查询”，再验证实际行为。

新增模式为 `evidence_memory_v7` 和 `evidence_memory_v7_harness`，默认配置未改。
