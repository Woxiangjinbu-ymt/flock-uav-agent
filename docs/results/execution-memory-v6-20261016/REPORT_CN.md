# Memory 第六版：压缩范围过大，暂不作为替换方案

日期：2026-10-16。

**这轮改动没有取得整体提升。** 路线任务的提示变短、落地描述更明确，但线索搜索明显退步，因此保留全部失败记录，并将后续改动收缩到路线任务。

## 改了什么

把 v5 中重复的目标、路线与续做记录合成一份清单；保留原始工具回执和完成证据。成功落地但回执没给坐标时，明确写“精确位置未知”，避免把飞行航点的高度写成落地高度。工具仍自由调用，没有硬性拦截。

## 三轮结果

相同六个场景，v5 与 v6 各运行三轮，共 36 次；没有挑选重跑。

| 三轮合计 | v5 基线 | v6 |
|---|---:|---:|
| 任务达成且正常结束 | 18/18 | 14/18 |
| 已知完成后额外调用 | 1 | 1 |
| 同位置重复感知 | 3 | 3 |
| 模型调用 | 54 | 65 |
| 工具调用 | 37 | 52 |
| 总 token | 160,676 | 220,044（增加 36.95%） |

v6 的四次失败为横向线索三轮、纵向线索第三轮，均耗尽六次模型调用额度。模型围绕历史线段的端点小幅移动、重复感知，没有完成本人到访。**线段和来源仍完整保留，但呈现方式变化后，模型多次把“沿整段曾遇到目标”理解为“目标在终点”。** 不能据此声称事实被删除，也不能把失败时的零额外调用算成收益。

v6 的一次完成后多余动作发生在失败感知场景：重试、定位、到访都已完成，模型又自行落地。v5 的一次额外调用则是已完成路线后再查询无人机列表。

## 哪些局部效果值得保留

- 六次中断路线都正确完成剩余两个航点并落地，没有跳过必要步骤；这两类场景合计用量从 63,710 降到 59,931 token，下降 5.93%。三个已完成路线都直接收尾。
- 九条路线最终回复都没有编造落地坐标。但**本轮重新运行的 v5 九条路线回复也没有明确的错误坐标**，不能拿上一轮 v5 的五条错误充当本轮对照。
- 初始路线摘要从 1,364 降到 1,084 字符，已完成路线从 1,145 降到 935 字符。缩短提示本身没有保证整体表现更好。

## 下一步如何收缩

第七版只在完整支持的路线任务中使用新摘要。所有线索、访问、混合或未完整解析的任务，在每个读取点逐字沿用 v5。选择仅取决于原始任务语法，不根据案例编号、完成情况或实验成绩切换。

这是看过本轮失败后设计的下一次探索，另做预先固定的两轮对照，成绩不与本轮混合。本轮实际用量 380,720 token；后续验证只能使用本次总额度 600,000 中剩余的 219,280 token。
