# FlockCue 研究路线

更新于 2026-11-08。本页维护阶段顺序、门槛和交付。已验证的结果见[研究状态](RESEARCH_STATUS_CN.md)，训练细节见[后训练方案](POSTTRAINING_PLAN_CN.md)。

## 研究主线

**第一篇论文：多无人机小模型 Agent 什么时候需要思考。** 从 DeepSeek 教师轨迹蒸馏一个约 2B 的指挥模型，研究由执行状态事件决定每轮是否思考。

> **待检验假设。** 小型指挥模型需要深思的轮次，集中在执行状态发生变化的时刻，包括新的受阻回执、效果未知、部分完成和跨机义务改变。用这些事件监督"思考或不思考"，在相同成功率下，比教师自选、RACE 的 LoGiC 和固定间隔消耗更少的推理 token；机队越大，优势越明显。

结论为负也有信息量。若 LoGiC 或教师自选与执行事件相当，说明似然信号或教师本身已经隐含执行状态。

**第二篇论文：** 把轨迹验证器训练成按机、按作用范围给分的过程奖励，用于小型指挥模型的 GRPO，对照只用整题结果的奖励。那时主 Agent 是会频繁出错的小模型，验证器有用武之地。2026-11-07 的验证器规格草案与预算移入[历史目录](history/verifier-plan-20261107/)。

**基线定位。** PenguinHarness 式的 Harness 自动迭代（权重不动）作为"为什么要训练"的对照臂，不作主线。三项相关工作的分工与差异见[项目指南](PROJECT_GUIDE_CN.md#与已有工作的关系)。

## 阶段与门槛

## 评价口径

- 主指标：独立评分的整题成功率；推理 token、全部 token、P50/P95 时延。
- 比较时控制思考比例或总推理 token，四种标签报告各自的思考比例。
- 评价标签时固定基座、Harness、工具、每场初态、题序、预算和评分器，只换标签来源。评价系统时分别固定教师比较 Harness、固定 Harness 比较学生。
- 报告完整分母，失败、超时、未运行分开计数；不拼接不同批次的最好值。
- 测试侧只在冻结协议下使用；dev 用于选参数。

## 每一步的开发约定

进入某一步时，在 `docs/specs/<编号>-<主题>/` 下依次写 `spec.md`（要解决什么、怎样算完成）、`plan.md`（复用哪些组件、数据怎样流转）、`task.md`（拆分与依赖）、`checklist.md`（事先写好验收项，执行后回填证据）。四份逐份评审确认后再实施。付费调用和 GPU 资源在对应的 plan.md 中写明上限，用户批准后执行。
