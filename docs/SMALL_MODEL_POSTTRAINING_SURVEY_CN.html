01结论先行

  1. 1
    方向成立，这个平台很适合做蒸馏加多轮 RL。它同时具备三个条件：检查树是确定性的，可以直接当奖励（1,500 题、9,396 个叶子检查）；有 58 个任务模板和随机场景生成器，能造出与评测集不重叠的训练任务；仿真动作即时返回并支持快照恢复，RL 吞吐只受学生模型推理速度限制。同类公开结果里，1.5–4B 模型在窄领域多轮任务上经 SFT 和 RL 后超过 GPT-4o 级模型并不少见：GiGPO 的 1.5B 在 ALFWorld 上达到 86%，GPT-4o 为 48%；RACE 的 2B 在 ScienceWorld 上从 1.1 提到 58.8。
  2. 2
    Harness 的价值没有被挤掉，在小模型上更大。HAD（2026-10）去掉 harness 后，学生成功率从 63.4% 跌到 40.3%；DroneServer 实测本地 4–8B 模型能调用接口，但完不成任何多步飞行任务。论文主线可以从"harness 让大模型更强"转为"harness 与后训练协同设计，让小模型可用"。你们担心的"harness 增益随模型变强而缩小"，本身就可以做成一项可测量的分析。
  3. 3
    可以直接套用的是一条已被反复验证的流水线，而且能压到单卡上。教师轨迹经拒绝采样做少量 SFT，接一段在线纠错热身，再做多轮 GRPO 系强化学习。信用分配到步级，进度奖励用势函数形式，检查树可以直接给出这个势函数。4B 用 LoRA 训练，训练好的 4B 再当同族白盒教师，把能力蒸馏给 0.8B 和 2B。RACE 是这条流水线上的推理效率模块：成功率和普通 SFT+GRPO 持平，推理 token 少 32–80%，适合放在最后一阶段。
  4. 4
    教师用 DeepSeek，条款明确允许蒸馏。DeepSeek 开放平台服务条款（2026-04-29 生效）§4.2 写明，输出可用于"训练其他模型（如模型蒸馏）"；V4 系列权重为 MIT 许可。要注意一件事：9 月 10 日起，官方 API 上的 deepseek-flash 和 deepseek-v4-pro 都路由到 V4.1-Flash，所以通过 API 已经比不出 Pro 和 Flash 的差别。从现在起，每条轨迹都要记下响应里返回的模型名。
  5. 5
    学生：Qwen3.5-4B 用 LoRA 训练作主力，Qwen3.5-0.8B 作低延迟档，Qwen3.5-2B 作中间档并用于方法开发。约 1B 不适合当主模型。同样训练后，0.6–1B 在长时程、API 密集的任务上比 4B 低 15–30 个点。但从更强的策略在线蒸馏后，分布内任务能追回大半：ActFirst-OPD 在 ALFWorld 上 0.6B 达到 68.6，4B 为 82.6。0.8B 与 4B 同分词器、同模板、同架构，每 token 的 KV 缓存只有 12 KiB。
  6. 6
    一张 A800 80 GB 够用，40 GB 可以做开发档。—推断。真正的不确定性在证据上：在几十轮、环境状态持续变化的 agent 任务上，还没有人直接对比过 LoRA RL 和全参 RL。最接近的是 CoPES（Qwen3.5-4B，用检索和 Python 工具解数学题），其中 LoRA 明显落后。所以第一周先在 2B 上做 LoRA 对全参的短对照。
  7. 7
    最大的工程缺口在学生侧上下文，它同时决定单卡吞吐。现有轨迹每题峰值上下文的中位数是 43–48K token，只有约三分之一在 32K 以内；工具参数是字符串里再套 JSON；日志缺 system prompt、tool_call ID 和推理内容，不能直接做 SFT。单卡上每步 RL 的耗时几乎和每回合 token 数成正比，所以压缩上下文是最便宜的提速办法。你们已有的任务进度、证据账本和执行记忆正好可以用来压缩。

02现有平台对后训练的适配度

来自对代码和运行记录的逐项盘点。左侧可以直接复用，右侧是开训前必须补的缺口。

已经具备

  • 奖励函数：检查树由服务端确定性计算，可逐题调用。FullWorld.evaluate()（scripts/harness_full100_world.py:169）返回 passed、checks_passed、checks_expected，二值成功和叶子级部分分都有。
  • 训练任务来源：controller/default_templates.py 有 58 个模板，评测集只用了 50 个；RandomSessionGenerator 可指定无人机、目标、障碍数量和任务族。剩下 8 个模板可以留作新任务类型的泛化测试。
  • 仿真速度：动作即时返回，仿真时间不影响结果。进程内 World（scripts/harness_v2_world.py）带虚拟时钟、种子 RNG 和 pickle 快照恢复，GRPO 同组的多条 rollout 可以从同一初态出发。
  • 资源占用：每个场景约 0.43 GB 内存、1 个 CPU 核。一台多核服务器并行几十个环境没有压力，但租来的单卡实例通常只配 10–16 个 CPU 核，见第 7 节 WP0。
  • 轨迹长度：DeepSeek 每题平均 12.8 次模型调用、22 个工具步，和 RACE、GiGPO 的 30 轮上限同一量级。
  • 评测规范：已有配对 W/L、场景级 bootstrap、冻结子集和 500 秒协议，可以直接沿用。

需要补齐

  • 上下文太长：首轮约 8.6–9K token；每题峰值上下文中位数 43K（DeepSeek）和 48K（Qwen），只有 32–37% 在 32K 以内。system prompt 约 2 万字符，工具 schema 又约 2 万字符。
  • 工具接口不利于小模型：30 个工具的参数都是一个 input_json 字符串，等于 JSON 里再套 JSON；观测是 indent=2 的 JSON，平均 6.3K 字符。改成带类型的参数（无人机 ID 枚举、数值范围）后才能做约束解码。
  • 已有轨迹不能直接做 SFT：约 4,960 条 toolchain、约 3,686 条通过，全部来自 DeepSeek 和 Qwen。记录缺 system prompt、tool_call ID、并行调用分组和 reasoning_content，也没有记下响应实际返回的模型名，只记了请求名 deepseek-flash。失败题的最终文本被换成了错误串，超时题没有工具链。
  • 生成器只能从 GUI 驱动：要写无头脚本，把全局 random 改成显式种子；占位符碰撞检查在离线时会静默返回 False。
  • 场景内状态继承：原协议同场景 20 题顺序执行，位置和历史会延续；100 道典型题中有 12 道在初态就满足至少一个叶子检查。RL 要逐题快照重置，部分分按相对初态的增量计算。
  • 没有训练代码：仓库里没有 vLLM、TRL、verl 或 LoRA 相关代码；基准 runner 只接受 DeepSeek 和 Qwen 端点，接本地模型要加一个后端。

3.1 RACE 精读

When Should Agents Think? Adaptive Reasoning via Cross-Turn Estimation（arXiv 2610.12061，2026-10-08，ICLR 2027 在审；中国人民大学高瓴人工智能学院与阿里巴巴）。RACE 是 Reasoning Adaptation through Cross-Turn Estimation 的缩写。已核实

  • 解决的问题：ReAct 式 agent 每轮都先推理再行动，但前面的推理常常还能支撑后面几步。RACE 让模型逐轮决定要不要推理。
  • 信号 LoGiC：在成功轨迹上删掉某一轮推理，看后续动作的平均 token 对数似然下降多少；不超过 0.001 就判定这一轮可以跳过。只打分，不生成。
  • 训练：SFT 用 DeepSeek-V4-Pro 的成功轨迹，可跳过的轮写成空 think，损失只算推理和动作 token；LR 1e-5，有效 batch 32，最长 65,536。RL 为 cover-aware GRPO：每步 16 个任务 × 8 条 rollout，LR 1e-6，clip 0.2，温度 1.0，最多 30 轮；成功轨迹里可跳过轮的推理 token 从损失中掩掉，另加一个让模型立即输出 </think> 的 closure loss（权重 0.02）。奖励只有任务成功，信用分配是轨迹级。
  • 结果：学生 Qwen3.5-9B，另有 2B、4B 规模实验。和不加 RACE 的 SFT+GRPO 比，四个基准成功率变化为 −1.27、+1.40、−0.17、−0.75，都在统计误差内；推理 token 减少 32–80%。9B 在 ScienceWorld 达到 73.28，教师 DeepSeek-V4-Pro 为 32.11，Claude Opus 4.6 为 59.37。
  • 小模型：2B 在 ScienceWorld 上 1.10 → 20.78（SFT）→ 58.77（RL），WebShop 6.20 → 42.20 → 49.20。AppWorld 只有 147 个训练任务、工具多、参数组合复杂，2B 和 4B 在 RL 后反而退化。
  • 可复用程度：仓库在投稿当天创建，至今 0 commit、没有 README，只能按论文的算法 1、公式、超参和附录提示词复现。

对我们：流水线和超参可以直接作为起点；自适应思考放在最后的效率阶段，因为在笔记本上，少解码就是低延迟。需要改三处。第一，DeepSeek 会返回 reasoning_content，但推理很长：本仓库每次调用平均输出 1.3–1.7K token，要先裁成短理由再给小模型学。第二，多机 JSON 参数长，平均对数似然会稀释无人机 ID、坐标、航点顺序这些关键 token，打分应只看参数值。第三，我们的奖励含部分分，要先定成功阈值，长时程还要补轮级信用分配。另外，AppWorld 上的退化说明，工具多、参数组合复杂的任务族要单独跟踪 RL 效果。

对 1–4B 学生最有用的经验

  • 数据量：1–3K 条成功轨迹已能让 4B 接近教师（Guava、Kang 等）；少于约 500 条时连调用格式都学不稳（FireAct）。每个任务最多留 2–3 条，控制简单题重复（SWE-smith）。
  • 保留短理由，不要只学动作：AgentBank 去掉 CoT 后未见集从 29.5 掉到 22.8。但 ≤3B 学生对长推理吃力，1.5B 学短 CoT 得 34.2、学长 CoT 只有 27.0（2502.12143）；2026 年也有研究认为这取决于实验设置，需要在我们的任务上实测。
  • 加恢复分支和"不调用"负例：Guava 加恢复分支后从 79.3% 提到 87.1%；Agent-FLAN 用负例压低幻觉调用。
  • 损失只算 assistant 轮，观测部分掩掉；混入 10–20% 通用数据防止遗忘。
  • 纯 SFT 会离线漂移：学生只见过教师走过的状态，自己走偏后不会恢复。所以 SFT 之后要接 RL 或在线纠错蒸馏。
  • 小模型的典型失败是循环：SWE-smith-32B 超过 25% 的轨迹出现重复动作，Claude 不到 4%。需要在 harness 里检测重复，在训练里惩罚停滞。

3.3 多轮 Agent 强化学习

在 ALFWorld、WebShop 这类任务上，多轮 RL 能在起点策略上再加几十个点，步级信用分配方法又比普通 GRPO 多 5–15 个点。前提是起点策略已经有一定成功率，并且回合可以重置。起点太弱时只做 RL 会失败：AirVLN-R1 不做 SFT 只有 2.4%，ERA 是 0%。

对我们最关键的横向结论

  • SFT 要有，但别太多：OpenWebRL（2606.02031，4B）发现接上 RL 后，0.4K 条教师轨迹反而好过 1.9K 条。SFT 的目标是让 RL 能起跑。
  • SFT 和 RL 之间加一段在线蒸馏热身：OPW（2609.39436，Qwen3-4B）在 60 步 RL 后 ALFWorld 已见集 96.1，SFT 热身为 83.9。教师权重要退火到 0；权重固定的 GRPO+OPD 反而不如普通 GRPO（39.1 对 53.0）。
  • 有奖励塑形时不要做组内标准差归一化：LOOP 因此掉 9 个点；Dark Room（2607.21273）中"稠密塑形 + 标准差归一化"11 次运行全部塌缩，因为全失败组里的 z-score 会把塑形项抵消。
  • 部分分在 4B 左右证据不一：有的持平，有的二值更好（FinQA-4B 66.3 对 54.0），有的"先稠密后稀疏"最好。λ 必须做消融。
  • 思考会在 RL 中自然变短：RAGEN 每步推理从 307 降到 90 token，不思考的版本表现相当。从 Qwen3-4B-Thinking 起跑 RL，工具调用几乎降到 0（2510.11701），所以起点选非思考或短思考。
  • 多机要用宏动作：小模型团队在空间协作游戏里用原始底层动作拿不到任何奖励，换成宏动作才行（2608.01425）。这支持保留 harness 的复合工具和技能。只训练指挥者、冻结执行者可以避免信用归属不清（AgentFlow 规划器 38.5 → 55.7）。
  • Qwen 的虚假奖励问题：Qwen2.5-Math-7B 用随机奖励也能在 MATH-500 上涨 21.4 分。要跑随机奖励对照，确认提升来自任务。
  • 普通 GRPO 是很强的基线：一项 132 次运行的比较（2610.19789）中，10 种自蒸馏附加方法只有 2 种稳定超过调好的 GRPO。

3.5 最接近的工作，以及可以占的位置

最近两周出现了几篇方向相近的预印本，需要正面区分。HAD 做"harness 感知的蒸馏"，场景是 ALFWorld 等通用基准，依赖白盒教师做 OPD，不用任务奖励。Guava 证明 harness 设计决定小模型能否学会具身任务，场景是单臂操作。Skill-SLM 把小模型用在 UAV 上，做的是单机的一次性任务分解和技能编排。PMR 做单机的选择性云端恢复。目前没有找到把 ≤4B 开源模型训练成多轮、多机协同指挥模型并配程序化检查的工作。

    多机闭环指挥的小模型：3–30 架、10–40 轮工具调用、部分可观测，配 1,500 题完整评测和配对统计。

  3. G3
    把 harness 蒸馏进权重：画出上下文预算与通过率的曲线，说明哪些 harness 能力被模型内化、哪些仍需要外部状态。HAD 的分析提示学生会把可学的反馈留在权重里、把状态交给 harness，我们可以在多机场景验证或推翻。
  4. G4
    笔记本闭环指标：首 token 时间、每秒 token、缓存命中率、每题能耗、检查通过率，以及量化对各类工具调用错误的影响，直接回应 DroneServer 观察到的本地模型失败。

    多机场景的逐步云端升级：小模型在本地执行，不确定时把决策权交给云端模型，并对成功率和云端调用率给出校准保证。Hera、TSDS 做的是家务和网页任务，PMR 是单机。

约 1B 的模型能做到什么程度

下面是同一篇论文里同时报告了小号和大号模型、训练方法相同的结果。数字为各论文自报。

  • 在线蒸馏能追回大半，但仅限分布内：ActFirst-OPD 在 ALFWorld 上，0.6B 从 0.7 提到 68.6，4B 从 63.5 提到 82.6，教师 88.3；换到 ScienceWorld，普通 OPD 后三个规模只有 10.0、22.9、29.3。
  • 同样数据 SFT 后差距仍大：xLAM-2 在 τ-bench 上 1B 21.8、3B 38.2、8B 46.7；ProD 域内平均 0.6B 52.7、1.7B 67.9、4B 78.0。
  • 工具多、组合复杂时，小模型训练后可能变差：RACE 的 AppWorld（数字由柱状图读出）上，2B 从 12.1 经 SFT 降到 7.7、RL 后为 9.7；4B 是 40.9 → 52.5 → 40.5。WebShop 和 ScienceWorld 上 2B 与 4B 训练后接近。
  • RL 未必救得回来：AT-GRPO 中 1.7B 的 Sokoban 一直停在 10–11.5，8B 到了 96–98；GiGPO 的 1.5B 对 7B 是 ALFWorld 86.7 对 90.8，RLVMR 在未见类别上差距拉大到 56.3 对 83.6。
  • 典型失败是循环：HAD 中未训练学生只有 20.4% 的回合没有循环，教师是 64.6%；RAGEN 的 0.5B 出现"Echo Trap"，反复执行同一套计划。

推荐：主力 Qwen3.5-4B，用 LoRA 训练。低延迟档 Qwen3.5-0.8B，由训练好的 4B 同族在线蒸馏得到。Qwen3.5-2B 做中间档和方法开发：它的 KV 缓存和 0.8B 一样大，τ² 却是 48.8 对 11.6。异族对照可选 MiniCPM5-1B（稠密结构，运行时最省心）。0.8B 适合承担短时程重规划、参数填写和技能调用；长时程多机协同能不能交给它，要先在留出模板上实测再下结论。Qwen3.5 是混合注意力结构，训练框架和 llama.cpp 前缀复用的支持都还要在第 1 周跑通，跑不通就换稠密模型（第 6 节）。

笔记本上能跑多快

  • 不量化运行：语言部分的 BF16 权重，0.8B 约 1.5 GB，2B 约 3.8 GB，4B 约 8.4 GB。16 GB 以上内存的 Mac 可以直接跑 4B 的 BF16；8 GB 显存的 RTX 笔记本跑 4B 需要 Q8 或 Q4，跑 0.8B 和 2B 可以不量化。
  • 解码速度 推断：BF16 解码受内存带宽限制。按 M4 Pro 的 273 GB/s 估算，0.8B、2B、4B 分别约 110、45、20 token/s，带宽约 120 GB/s 的基础款芯片减半。实测参照：llama.cpp 在 Apple M3 的 CPU 后端上，0.8B BF16 解码 35 token/s、预填 1,866 token/s，Q4_K_M 解码 107 token/s；RTX 5090 上 0.8B Q8_0 解码 715 token/s。不量化的 4B 在笔记本上偏慢，这也是要有 0.8B 档的原因。
  • 前缀缓存必须开：不缓存时，4B 在 M4 Pro 上每步要重算约 6 万 token，大约 1.5 分钟。所以学生侧上下文要压缩，而且历史只追加、不改写，缓存才一直有效（第 7 节 WP0）。
  • 量化的代价：4bit 让工具调用整体只掉 1–3%，但工具名幻觉最多放大 2.5 倍；"要不要调用"比"调用哪个"更容易被量化打乱。2B 建议用 Q5 或 Q8，每个量化版本都在 MultiUAV 检查上重测并按错误类型统计。

推荐部署栈

  • 运行时：llama.cpp 的 llama-server（Metal 或 CUDA），加载 GGUF，开 --jinja 使用原生工具模板，开 prompt cache、--cache-reuse 和 slot 保存恢复，让 system prompt 和工具 schema 常驻缓存；混合结构加 --ctx-checkpoints。
  • 保证工具调用合法：llama.cpp 的 lazy grammar 在工具调用开始时才启用文法，JSON Schema 自动转 GBNF。只约束调用和参数，不约束思考部分，因为格式约束会损害推理。前提是把 input_json 字符串改成带类型的参数。mlx-lm 的 server 目前不支持文法约束。
  • 投机解码：llama.cpp 2026-05 合入了 Qwen3.5 的 MTP，报告解码加速约 1.5–2 倍（单 slot）。
  • LoRA 不影响部署：训练结束后把 LoRA 合并回基座，再转成 GGUF，推理时没有额外开销。
  • 训练 rollout：用 vLLM 或 SGLang，配 xgrammar 和前缀缓存；需要多架无人机并行调用时，在 RTX 或 Linux 机器上也用它们。
  • 安全层：沿用 DroneServer 的做法，把模型当成不可信指挥者，服务端校验命令、独立地理围栏、审计日志。蒸馏会把教师的不安全倾向带给小模型，而且从大到小传递最强。

KV 缓存按 config.json 计算：Qwen3.5-4B 只有 8 层全注意力，每 token 32 KiB，Gated DeltaNet 层每条序列另有约 50 MB 的固定状态；0.8B 和 2B 每 token 12 KiB，每条序列约 19 MB。按每回合 18K token、128 个并发回合、平均长度取一半估算。logits 必须分块计算：248K 词表在 18K token 上一次算完要约 9 GB（BF16）。Ampere 不支持 FP8，所以 Unsloth 的 FP8 RL、QeRL 的 NVFP4 这些省显存办法在 A100/A800 上用不了。

整个项目—推断。一张卡串行跑大约要三周纯 GPU 时间；同时租两三张单卡并行跑消融，可以压到一周多。

LoRA 做 RL 的证据

  • 支持：Thinking Machines 的 LoRA Without Regret（2025-09-29）发现，策略梯度 RL 里 LoRA 秩低到 1 也能和全参持平。最优学习率约为全参的 10 倍，100 步以内的短训练约 15 倍。LoRA 要加在全部层上，尤其是 MLP，只加注意力层明显更差。实验是数学推理，不是多轮 agent。
  • agent 上的先例：RAGEN 附录中，Sokoban 上 LoRA 秩 64、10 倍学习率，验证成功率与全参相当，显存占用约 23% 对 48%。LOOP 用 32B LoRA（秩 16）把 AppWorld 从 39.2 提到 71.3。2608.01425 在单张 H100 上，对 Qwen3-4B 和 Qwen3.5-2B 做每智能体 LoRA 的多智能体 GRPO。verl-agent 在 2×H100 上跑 7B 的 GiGPO LoRA。
  • 反面：CoPES（2608.02391）最接近我们的设置，是 Qwen3.5-4B 工具 agent，用 verl 0.8.0。全参 GRPO 16 步时 AIME24 达 44.28（78.6 GPU 时）。LoRA（秩 32，学习率只放大 5 倍）走到 64 步才 41.86（314 GPU 时），同为 16 步时只有 28.14。2512.23165 在 1.5B 数学 RLVR 上测得 LoRA 42.5、全参 44.9、DoRA 46.6，秩 1 稳定落后于 16–32。2601.06677 在单张 A40 上测 ≤1.5B，秩 8 一直失败，要到 256 才行。
  • SFT 一侧：2609.17848 在 4B 工具调用 SFT 上，LoRA 三个数据集都好过全参（xLAM 88.0 对 80.4）。
  • 怎么用：秩从 64 起步，加在全部线性层，学习率约为全参的 10 倍（全参 1e-6 对应 LoRA 约 1e-5），并预期比全参多走几倍步数。第 1–2 周先在 2B 上跑 LoRA 对全参的短对照。已有的对照只在数学和工具增强推理上，长时程、环境状态持续变化的 agent 任务上还没有，这组结果本身就能写进论文。

单卡上必须打开的开关

  • rollout 与训练分时共用一张卡：verl 的 agent loop 每步让推理引擎进入 sleep（释放 KV、卸载权重），训练完再唤醒；TRL 用 colocate 模式加 vllm_enable_sleep_mode；Unsloth 的 Standby 让 vLLM 和训练共享同一份权重。
  • logits 分块：用 verl 的分块融合 log-prob 输出头或 Liger。CoPES 报告 verl 0.8 上 Qwen3.5-4B 用不了融合算子，LoRA 也开不了激活卸载，第 1 周要确认 0.9.x 是否已支持，不支持就自己分块。
  • 其余省显存手段：梯度检查点、序列打包（use_remove_padding）、动态 batch。
  • 训推不一致校正：开截断重要性采样（TIS），TRL 默认已开，verl 有 Rollout Correction 预设。有报告 1.5B LoRA 加 TIS 在 BF16 下约 600 步后塌缩、FP16 下稳定（2510.26788），长跑时把 FP16 作为备选。
  • 全参保留 FP32 主权重：verl FSDP 默认如此。纯 BF16 权重配 1e-6 的学习率，小更新会被舍入吃掉。
  • QLoRA 只作最后手段：NF4 量化能省显存，但 QeRL 报告它在 3B/7B 上比 QeRL 低 6–8 个点，rollout 也更慢。只在 40 GB 卡放不下 4B 时考虑。

单卡训练框架

  • 试点：TRL GRPOTrainer v1.16.0（2026-10-15）。colocate、sleep、environment_factory（有状态环境，带 reset 和 get_reward）都在一个进程里，TIS 默认开启，最简单。Unsloth 有 Qwen3.5-4B 的 GRPO notebook，但多轮环境支持未核实。
  • 主线：verl v0.9.1（2026-09-20）加 verl-agent。有 GiGPO、Rollout Correction、LoRA 和 sleep，单卡 quickstart 设 n_gpus_per_node=1。要锁定 0.9.x，2026 年 LoRA 相关修复还在合入，v0.9.1 刚修好一处端到端问题。
  • 其他：ROLL、AReaL、SkyRL 都支持 LoRA，但单卡多轮先例少。rLLM 的 tinker 后端会把数据传到托管服务，不用。

07推荐训练方案

整条路线按依赖顺序排列，周数是从定方向起算的估计。每一站都有可独立汇报的产出，后一站失败时可以退回前一站的检查点。

  1. WP0

    环境与学生接口

    第 1–2 周
    • 训练任务：无头任务生成器，固定种子，按 3 个任务族 × 5 个难度档生成新场景；与 1,500 题按文本和布局去重；留出 8 个未用模板和部分场景。
    • 逐题重置：进程内 World 加快照恢复和虚拟时钟。基准里没有移动目标，但天气按墙钟 1 Hz 更新，异步 rollout 时要用虚拟时钟，同组 rollout 才可比。
    • 模拟器池：64–128 个无头环境；超时和服务错误从损失中掩掉，不当作策略失败。租来的单卡实例通常只有 10–16 个 CPU 核（例如优云智算的 A800 实例是 16 核、240 GB 内存），优先用进程内 World 降低每个环境的开销；不够时另租一台便宜的纯 CPU 机器跑模拟器，经 HTTP 接入。
    • 学生上下文：固定的短 system prompt 和工具 schema，后面接只追加的紧凑历史，任务状态块（每架无人机状态、剩余义务）附在每轮观测末尾。历史只追加、不改写，笔记本上的前缀缓存一直有效，训练时一个回合就是一条序列。超过约 24K token 时，把较早的轮折叠进状态块，只在折叠那一步让缓存失效一次。目标是每回合 ≤18K token、每轮观测 ≤1K token。滑动窗口（verl-agent 默认保留 2 轮，Agent-R1 认为效果最好）作为对照。SFT 和 RL 用同一格式。
    • 动作空间：参数改为带类型的 schema；保留 navigate_to、覆盖规划、公开搜索这些复合工具和技能，作为学生的宏动作。
    • 轨迹记录器：逐字保存 messages、tools、tool_call ID、并行分组、推理内容和每步 token。
  2. WP1

    教师数据

    第 2–3 周
    • DeepSeek（当前 API 实际为 V4.1-Flash）在 harness 内跑新任务，只留通过的轨迹，每题 1–3 条，共 2–3K 条。每次调用记录返回的模型名和 fingerprint，一到两周内集中生成完。
    • 恢复分支：中途注入路径受阻、起飞失败、电量不足等扰动，记录教师怎样恢复。
    • 每轮保留简短的可见理由；用 harness 状态生成任务阶段标签，作为辅助训练目标（TPD 的做法）。
    • 失败轨迹同样保存，后面用于偏好学习，以及给 RL 里"全失败组"补一条成功样本。
    • —推断。
  3. WP2

    SFT 起步

    第 3–4 周
    • 先用 0.5–2K 条，目标是学生在训练分布上通过率达到 30–60%，够 RL 起跑即可。
    • 只算 assistant 轮的损失；batch 32（参照 RACE）；混入 10–20% 通用工具数据。
    • 4B 用 LoRA：秩 64–128，全部线性层，学习率约 1e-4，即全参 1e-5 的 10 倍。2B 和 0.8B 全参，学习率 1e-5；2B 另训一版 LoRA，给后面的对照用。
    • 起点用非思考或短思考模式。
    • 同时完成上下文预算消融：原始历史、执行记忆各版视图、任务状态块。
    • 算力 推断：4B LoRA 在 2K 条、每条约 18K token 的数据上，单张 A800 每个 epoch 约 1–3 小时。
  4. WP3

    在线蒸馏热身

    第 4–5 周
    • 40–100 步，教师权重退火到 0。
    • 只做黑盒版：DeepSeek 对学生实际走到的状态重标动作，DAgger 式（2605.12913—
    • 原方案的白盒版要自部署 Qwen3.8-27B，单卡放不下，取消。白盒 logit 蒸馏挪到 WP5，由训练好的 4B 当教师。
    • 这一站是可选的：SFT 后学生的通过率如果已经够 RL 起跑，可以跳过，直接进 WP4。
  5. WP4

    多轮 RL

    第 5–9 周
    • 优势：A = A回合 + A步。回合项用留一基线，不做组内标准差归一化；步级项用 GiGPO 的锚点分组，状态键取"任务 + 每架无人机已完成的子目标 + 飞行阶段 + 粗粒度位置格"，γ 0.95。连续仿真里精确状态很少重复，所以必须离散化，这正是 harness 任务状态派上用场的地方。
    • 奖励：成功记 1、失败记 0，再加每轮塑形 λ·[γΦ(s′) − Φ(s)]，λ 从 0.5 退火到 0.1。Φ 是检查树的软评估：AND 取均值，OR 取最大，NOT 取 1 − x，叶子按无人机拆开，重置时已为真的叶子排除，航点序列用有序谓词（DARS 的做法）。势函数形式的塑形不改变最优策略，刷不出分。
    • 惩罚：每次无效调用 −0.1，连续 3 次无效调用结束本回合；SFT 之后不再加格式奖励；成功项和进度项分开归一化（GDPO）。
    • 超参：每组 8 条，40 GB 卡上最少 4 条；每步 16 个任务，单卡吃紧时降到 8 个。LoRA 学习率约 1e-5、秩 ≥64，全参 1e-6；clip ε 0.2/0.28；KL 0–1e-3；温度 1.0；每轮最多 512 token；开 TIS。丢弃零方差组，全失败组补一条存储的成功轨迹。
    • 小组更依赖稠密信号：组越小，二值奖励越容易整组同分、没有梯度。单卡 L40S 上的一个记忆 agent 在每组 4 条时，二值奖励学不动，换成连续奖励才行（2605.23067）。所以势函数塑形和叶子增量在单卡上更重要，λ 的消融不能省。
    • 课程：只训 SFT 模型通过率在 10–90% 之间的任务，达到 90% 就退役，约 1K 个任务；模型调用上限 10 → 20 → 30；从 1–2 架逐步到整队。
    • 结构：单一中心化指挥策略，与现有 harness 一致，用按无人机拆分的 Φ 做逐机信用。多机分权（按智能体×轮次分组）留作扩展。
    • 开发顺序：奖励、信用分配和课程先在 2B 上调通，再用 4B LoRA 跑主结果。2B 一步约 10 分钟，4B 约 20 分钟。
    • 回退方案：超过约 30 轮后 GRPO 停滞，就换带轮级 critic 的 PPO（ERA：轮级 GAE 对 token 级，48 → 60）。单卡上 critic 要再占一份模型，4B 时 critic 也用 LoRA，或者只在 2B 上做。
    • 必须跑的对照：只用二值奖励、均匀分摊的进度奖励、随机奖励。
  6. WP5

    规模下放、效率与部署

    第 9–12 周
    • 4B → 0.8B / 2B 在线蒸馏：训练好的 4B 当白盒教师，对学生自己生成的 token 给逐 token 反向 KL。两者同分词器，4B 推理约占 9 GB，可以和学生放在同一张卡上。之后可在 0.8B 上再接一小段 RL。
    • RACE 式自适应思考，或更简单的 AdaptThink，压缩推理 token。
    • 量化评测、约束解码、MTP 投机解码；在笔记本上闭环跑 fast100 和 full1500。
    • 可选：云端升级门控，把决策权分成"技能 → 0.8B → 4B → 云端"几级。

训练框架的选择和单卡上必须打开的开关见第 6 节。
