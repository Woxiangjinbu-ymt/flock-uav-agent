# 当前技能与普通 guarded macro 的离线语义对照

日期：2026-11-03。固定案例为 `method-cases.json`；运行脚本为 `scripts/validate_harness_method.py`。本批没有模型调用、外网、Teacher 采集或训练，所有子程序选择和恢复均由夹具决定。

## 问题与三臂

在同一 `observed_target_v7` 技能、初态、公开接口、守卫、局部处理和预算下，比较：

1. `guarded_macro`：测试专用的独立循环，调用生产 `make_skill_factory`，遇公开调用执行，遇检查点继续，完成或触发共同守卫时退出。没有调用 `HarnessRuntime._drive`，没有调度名称或暂停/恢复策略。
2. `applicability`：生产 `HarnessRuntime`，实际 `applicability` 调度。
3. `failure`：生产 `HarnessRuntime`，实际 `failure` 调度；每次 paused 后立即由脚本请求相同 plan 的 resume，脚本不选择新的原工具动作。

普通宏保留本批所测的 scene/epoch、API 上限和未知回执处理，与另两臂共用技能内 actor、效果、局部修复等守卫。它不作为新增生产 scheduler，也不构成相对自身的算法创新证明。取消、墙钟截止、并发以及任意技能不在本批等价检查范围。

## 预声明分母与预期

12 固定案例 × 3 臂 = 36 个脚本执行。每个 case/arm 启动独立新进程，父进程串行等待退出；所有结果与异常均留在预定分母内。场景和断言先写入固定 case 文件，正式运行不得因为失败换场景。

| 类型 | 案例 | 预期 |
| --- | --- | --- |
| 正常 | 短链、公开搜索 | 三臂 completed，后验独立夹具评分成功，无失败检查点 |
| 可局部处理 | 固定隐藏端点障碍；某 actor 的 max_altitude 小于搜索起飞高度 | 每例一个已处理失败检查点；macro/A 持续，F 首次暂停并可由脚本 resume，最终完成 |
| 必须退出 | 动作回执丢失：已生效、未生效 | 一次未知动作后一次公开状态读取，再退出；不得重放 |
| 必须退出 | 公开 actor 依赖改变；scene epoch 改变 | 后续动作前退出 |
| 必须退出 | 修复预算 1（第二次拒绝触发）；API 预算 3 | 在相应边界退出，不伪造后续动作 |
| 入口拒绝 | 完整任务增加拍照义务；未声明静态障碍合同 | 不丢弃额外义务，不启动不满足合同的搜索；零动作 |

真实 simulator 的 `agent` 角色公开 API 执行动作；独立 checker 只在执行结束后读取物理状态与历史。checker、私有物理状态、完整场景从不传入 generator 或 macro。工具 ledger 仅记录公开请求和回执。任务由夹具直接提交，不能称作模型自然选择或自然恢复。

固定端点障碍在场景初始化时已存在，位置 `(155,365,0)`、半径 1、高度 100，距所有初始 UAV 超过其 80 米感知半径；不临时增删地图。max_altitude 拒绝由真实服务端产生。actor/epoch 修改是明确声明的失效测试；丢失回执测试记录真实动作是否已经派发/生效，外部模型不可见此私有审计标记。

## 比较对象与判定

逐例逐臂保存全部公开调用/参数/原回执、动作子序列、检查点、第一次控制返回及全部脚本控制、frame/ledger、后验物理状态和独立夹具评分。要求宏与 A 的完整调用序列、frame、检查点、终态及物理状态相同；立即脚本恢复后的 F 也应相同。F 的暂停数量应恰好等于真实 `Checkpoint.failed` 机会数，其他两臂应为零。暂停之前的状态另存，不能把最终一致隐藏成“首次交接也一致”。

逐个暂停的公开调用序号与动作序号须按顺序对应同一个 failed checkpoint，首返回须与第一条控制记录相同；不能仅凭总次数相同判为正确。另比较真实公开 ASGI 请求的 method/endpoint/params/JSON/form body 和 response hash，检查前后私有障碍几何不变；这些私有审计条件不参与技能执行。

未知已/未生效、依赖变化另核事件确已发生且没有第二个动作。未完成或故意触发退出的 case 的任务失败是预期边界，不从分母删除，也不把“边界测试通过”写成任务完成率。`report.passed` 表示预声明断言符合预期。

模型调用、HTTP token 和学习收益均为零/未测。暂停减少仅是减少可选择的交回机会；真实模型可能选择原工具或错误恢复，等待期间环境也可能变化，本批无法估计其成功、token 或成本收益。技能和守卫共享导致的条件语义等价是诚实基线结论，不是两种独立算法的胜负。

## 封存与后续

父进程运行前保存源文件与计划，结束后复核源 hash，封存所有 36 个结果、日志、检查、worker PID/串行 join、版本及精确文件 inventory。输出目录不得覆盖。开发运行与正式封存目录分开。

执行使用工作区源码，开/末 hash 必须与封存副本一致；不声称子进程直接从副本导入。子进程清除 UAV/模型配置环境前缀并禁止 socket 网络。全物理对象原件保留；终态语义比较仅忽略 session.request_history 中随机 request_id 与真实墙钟 timestamp，保留其余请求、动作、坐标、状态、历史和进度字段。夹具开始清空旧 command inventory，与正式新进程初态一致。

只读复核：`agent4drone/.venv/bin/python scripts/validate_harness_method.py --verify --output <run目录>`。此模式核 manifest 本身、精确文件清单、各文件 hash、36 槽分母与进程记录，并从封存 cases/trials 重新计算逐例比较。失败返回非零，不调用仿真器、不写原目录、不重跑模型。

后续真实模型验证须另行授权：同一最终版本、同技能/权限/预算和整题评分，平衡顺序，保留正常与故障机会全分母；不得复用只按 skill 动作序号触发而让 raw 路径绕过的扰动。结构化恢复提示和范围化共享须各自独立消融，不能将本批脚本结果替代自然行为证据。
