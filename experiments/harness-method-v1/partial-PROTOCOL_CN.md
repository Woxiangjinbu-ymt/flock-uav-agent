# 部分完成后的公开剩余工作恢复：本地验证

一个新增 development 场景、同一任务的两个预定槽：正例执行恢复，负例省略恢复。两者独立恢复同一初态，真实 Agent/SDK、本地 ASGI 服务、原工具与 v2 执行状态接线保持一致；模型输出使用显式脚本，provider 调用为 0。不访问正式 test 集，不采 Teacher，不证明自然模型恢复收益。

无人机从 (100,100,0) 起飞20米，向原任务中的 A=(200,100,20)、B=(400,100,20) 执行 allow_partial_move=true 的路径。静态圆障碍在第二段，真实服务只能执行第一段并返回 partial_success，成功与未成功点列表必须忠实对应实际动作。

两个槽均在部分完成后调用公开 get_drone_status。正例的脚本辅助解析器仅在原调用、回执、主体、点列表及后续公开状态相互一致时，提取唯一未完成点 B。随后由模型脚本选择原工具 navigate_to(B)，该工具使用公开感知与既有路径规划绕障。解析器只服务本地脚本 fixture，未作为生产 Agent 的自动恢复算法安装。负例在查询后直接结束。

验收分别核对：真实物理事件确认只到 A；实际 wire 已出现 partial_completion 恢复建议与忠实回执；查询确认当前位于 A；正例恢复请求仅为 B、后续实际运动不再到达 A；负例无恢复；独立 scorer 正例4/4通过、负例2/4失败，二者初态一致。公开 mission_completion 始终 not_evaluated，运行返回、公开状态、独立评分三层分开。完整样本分母为同一开发任务的两个受控回合，不写成两个自然任务成功率。

所有准备输入、源码、运行日志和结果封存；旧结果不修改，失败尝试如发生则保留。未使用虚构 partial 回执、controller 私态辅助脚本或隐藏 checker 反馈。

两条脚本使用相同的 `[TASK DONE]` 结束格式，使 Agent 按既有协议正常返回；负例因此含故意提前完成声明，独立 checker 仍必须失败。这个标记不是任务真值。首轮开发尝试遗漏该标记，虽然正例动作和checker已4/4，父运行器仍按协议停批、负例未运行；该包保持不变。后续双槽只修复脚本结束格式并在新目录预先冻结，不重写首轮分母。
