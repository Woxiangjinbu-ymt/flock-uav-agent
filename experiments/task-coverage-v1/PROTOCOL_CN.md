# 任务覆盖与独立数据划分 v1

日期：2026-11-03。对应第三项 / W2；本文先规定数据身份、生成和质量验收，再冻结具体产物。研究入口见[状态](RESEARCH_STATUS_CN.md)与[路线](RESEARCH_ROADMAP_CN.md)。本轮只做本地数据准备，不启动付费模型、Teacher 生产或训练。

## Confirmed Decisions — 两套不同用途的数据

**开发覆盖集使用已知旧题。** 原 `benchmark/benchmark.zip` 的 75 场景、1500 题均按已暴露开发池管理；两模型全量基线、失败分析和历史选样已使用这个池。`main300 / dev240 / validation60 / fast100` 的历史名称和结果保留，但其中的 validation 不升级为未见测试。原文件没有可核实的生成 seed/version，不能从文件名或场景编号猜测。

从原题池按任务结构选取 F1–F6 每类 3 题，保持原指令、原 checker 和整个场景初态，记录选择规则、来源、哈希及暴露历史，不按历史模型成功率或 token 选择。原场景最小机队为 3 架；本集合没有 1–2 架初态，不通过删机伪造覆盖。任务族是评价组织方式，区别于原场景的 task_type。

**新划分用于后续采集和评价。** 使用有界、确定性的静态场景生成器，显式 `Random(seed)`、稳定实体 ID 和角色绑定。首版包含机队规模 1–5，各规模 4 个 train、1 个 dev、1 个 test 场景，共 30 场景；每场包含 F1–F6 各一题，单机场景不生成 F5 多机题，共 174 题，预定 train/dev/test 为 116/29/29。每道题独立恢复本场景的干净初态，不继承前一道题的执行状态。

同一场景及其全部任务、别名、后续派生版本必须在同一个 split。分配在任何正式策略运行前固定，不按后续成功率重新抽样。生成器开发和质量脚本调试使用独立 pilot seed；正式包冻结后出现的问题必须保留原始分母和失败记录，不原地改题或换掉失败题。

## 独立性的含义与泄漏边界

本版评估**已知任务模板下的新场景实例**。训练、开发和测试可共享任务族、动作接口及模板；数字/实体名归一化的命令骨架重叠要报告，不能宣称新任务族、新模板、组合分布外或语言泛化。固定生成器和数据质量审计本身是已知研究设计，不等于测试完全无人看过。

跨 split 禁止共享场景谱系、seed、任务/场景 ID，禁止去实体 ID/名称后的相同初态以及整体平移等价的场景。对相同实体结构，按稳定排序比较平移归一后的坐标和尺寸，每个分量差都不超过 1 米时列为近重复并拒绝跨集；这是一项可解释的筛查，不是完整几何图匹配或语义等价证明。还要与旧 1500 题场景及开发 pilot 比对。旋转、缩放等变换可能受绝对方向、边界和感知半径影响，不能仅靠哈希宣称全无语义近重复。

所有文件由 manifest 和 SHA256 绑定，源生成器、审计器、仿真/评分代码、协议版本与来源一起记录。可重复生成结果以实际字节一致性验证，不只记录 seed。冻结文件不可覆盖；后续修订须新版本并保留父谱系。

## 可解性、检查器与暴露管理

新题仅要求实际 checker 能核验的效果，不把未检查的悬停、照片对象、时序或责任分配写成已经核验的完整要求。F4 明确机队合计区域覆盖，不能用聚合 checker 证明指定 UAV 独立完成。F6 明确公开会话目标访问进度达到 100%，不把取整的 `>=95%` 当作严格 `>95%`；这个表述不匹配当前 `public_search` 的限定语法，仍走原工具。旧题保持原评分语义，并另外记录弱点，不修改历史分母。

质量验收包括：实体/角色引用有效、角色不混同、初态不已完成、原 checker 可执行、恢复后的状态和公开观测一致；再由预先固定的脚本通过公开查询与动作接口完成新题，最后隔离调用原 checker。另做缺少必要动作的负对照，检查 checker 不会把缺项计为完整成功。脚本不得从私有 scene/checker 读取目标坐标作为动作参数；目标位置只能来自公开观测。脚本质量轨迹不是自然模型轨迹，也不得自动转为 Teacher 示范。

正式 test 仅允许预先规定的自动数据质量审计，不用于调整 Agent、prompt、奖励、样本筛选或训练参数。审计与后续用途写入暴露记录；train 用于采集/训练，dev 用于开发和模型选择，test 留待协议冻结后的评价。本地使用边界不等于操作系统级秘密隔离；仓库文件可被读取，后续人工或模型查看、运行必须如实登记。对已用来调参的 test 要降为开发身份并另开版本，不能抹除暴露记录。

## 完成与后续门槛

本轮交付范围是：已知开发覆盖清单和可复用初态，新场景 train/dev/test 包，生成/划分/去重/质量审计脚本与可复查报告。通过这些检查表示数据准备的最小本地闭环，不表示模型能完成 174 题、自然恢复有效、独立泛化成立或已有训练数据。

W1 通用在线采集入口及真实 provider 验收、W3 样本转换/标签 mask/学生输入预算、后续采数额度仍是独立门槛。新集合以可见目标、无执行路径障碍的受控静态实例开始；它不覆盖复杂遮挡搜索、动态障碍、恢复压力或全范围难度。开发覆盖集中的旧复杂任务保留用于暴露这些缺口，不因新集合更容易而替换历史证据。
