## 启动入口

后续决定开始测试时，在仓库根目录执行以下持久任务命令。**该命令会开始付费测试；本次准备没有执行它。**

```bash
controller/.venv/bin/python -B scripts/m1_revision_job.py start \
  --method-commit 77563fb5827629da4dcecc2bb69c828db3907df9 \
  --study-dir experiments/m1-revision-v1
```

入口固定只有一个 `m1r` 阶段；会核对冻结包和预检哈希，拒绝重复 attempt，并使用冻结源码运行。完成或失败后不自动补跑、恢复、追加 M0 或推进 M2/dev240。不要使用旧的双组 `m1_progress_job.py`。

启动后查看 `experiments/m1-revision-v1/jobs/<job>/status.json` 和 `experiments/m1-revision-v1/runs.json`；当前这两类记录尚未创建。服务连通性、API 余额及在线耗时没有通过离线预检验证。

## 本轮如何判断结果

主要报告 M1-R 成功数 / 100、相对历史 M0 80/100 的净增、同题 W/L 和逐场差异；时间、token、缓存与超时作为成本诊断。若运行不完整，仍保留全部 100 题账本，标明未计分和退出原因，不把未运行题补零为算法失败。

该比较复用历史 M0，缺少同期基准重跑与固定提醒对照。远端模型和随机采样可能变化，场景内状态也随各自轨迹发展。因此结果用于下一阶段决策，不宣称随机因果、统计显著或全量提升。
